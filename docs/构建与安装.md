# 构建与安装

本文档说明如何从源码构建便携版、如何安装到本机、以及如何自行打包分发。

---

## 1. 环境要求

| 项目 | 要求 |
| --- | --- |
| 操作系统 | Windows 10 / 11 x64 |
| PowerShell | 5.1 或更高（Windows 自带） |
| 磁盘空间 | 约 300 MB（Electron 运行时约 222 MB + 源码 1 MB + 解压临时空间） |
| 网络 | 仅首次构建需要（用于下载 Electron 运行时）；已有本地运行时则完全离线 |
| 管理员权限 | **不需要**（安装到用户目录） |

> 不需要安装 Node.js。运行时的获取由 PowerShell 脚本完成。

---

## 2. 目录约定

```
音乐播放器/
├── app/          ← 应用源码，唯一需要修改的地方
├── scripts/      ← 构建与安装脚本
├── dist/         ← 构建输出（已被 .gitignore 排除，不入库）
└── docs/         ← 文档
```

**重要**：不要直接修改 `dist/` 里的文件。`dist/音乐播放器-win32-x64/resources/app/`
是构建产物，每次构建都会被 `app/` 的内容完整覆盖。

---

## 3. 构建便携版

### 3.1 一键构建

双击根目录的 **`构建.bat`**，或在 PowerShell 中运行：

```powershell
cd '路径\音乐播放器'
.\scripts\build-portable.ps1
```

### 3.2 构建流程

```
1. 校验 app/ 必需文件（index.html / main.js / preload.js / mini.html / package.json）
2. 检查可选模块（bili.js / cover.js / ncmdump.exe），缺失只警告不报错
3. 准备 Electron 运行时：
     ① -RuntimeDir 指定的目录
     ② 已有的 dist\音乐播放器-win32-x64\
     ③ 从镜像下载 Electron 31.7.7 win32-x64 并解压
4. electron.exe 重命名为 音乐播放器.exe，删除 default_app.asar
5. 清空并重建 resources\app，把 app\ 完整复制进去
6. 对必需文件做 MD5 校验，确认同步无误
7. 打印产物路径与体积
```

### 3.3 参数

| 参数 | 默认值 | 说明 |
| --- | --- | --- |
| `-ElectronVersion` | `31.7.7` | Electron 版本号 |
| `-RuntimeDir` | 空 | 已有运行时目录（含 `electron.exe` 或 `音乐播放器.exe`） |
| `-OutDir` | `dist\音乐播放器-win32-x64` | 输出目录 |
| `-Mirror` | `https://npmmirror.com/mirrors/electron` | 下载镜像前缀 |
| `-Force` | 关 | 强制重新下载运行时 |

### 3.4 示例

```powershell
# 使用本地已有的 Electron 运行时（完全离线）
.\scripts\build-portable.ps1 -RuntimeDir 'D:\downloads\electron-v31.7.7-win32-x64'

# 换 Electron 版本
.\scripts\build-portable.ps1 -ElectronVersion 33.0.0

# 强制重建（重新下载运行时）
.\scripts\build-portable.ps1 -Force

# 只同步源码到已有运行时（最快，日常改代码用这个）
.\scripts\build-portable.ps1
# ↑ 运行时已存在时会自动复用，只做第 5 步的源码同步
```

### 3.5 手动构建

不想用脚本的话，手动三部即可：

```powershell
# 1. 下载 Electron 31.7.7 win32-x64 并解压到 dist\音乐播放器-win32-x64
#    https://npmmirror.com/mirrors/electron/31.7.7/electron-v31.7.7-win32-x64.zip

# 2. 重命名 exe
Rename-Item 'dist\音乐播放器-win32-x64\electron.exe' '音乐播放器.exe'

# 3. 把 app\ 复制成 resources\app
Remove-Item 'dist\音乐播放器-win32-x64\resources\app' -Recurse -Force -ErrorAction SilentlyContinue
Copy-Item 'app' 'dist\音乐播放器-win32-x64\resources\app' -Recurse
```

## 4. 每日开发流程

改代码 → 同步到运行时 → 运行：

```powershell
# 同步（运行时已存在，秒级完成）
.\scripts\build-portable.ps1

# 运行
.\dist\音乐播放器-win32-x64\音乐播放器.exe
```

`app/` 里的文件与运行时里的对应关系：

| 源码 | 运行时 |
| --- | --- |
| `app/index.html` | `resources/app/index.html` |
| `app/main.js` | `resources/app/main.js` |
| `app/preload.js` | `resources/app/preload.js` |
| `app/mini.html` | `resources/app/mini.html` |
| `app/bili.js` | `resources/app/bili.js` |
| `app/cover.js` | `resources/app/cover.js` |
| `app/ncmdump.exe` | `resources/app/ncmdump.exe` |
| `app/package.json` | `resources/app/package.json` |

> 程序运行时 `resources/app` 下的文件被锁定，构建脚本会先尝试覆盖；
> 若失败请先关闭程序再构建。

## 5. 安装到本机

### 5.1 一键安装

双击根目录的 **`安装.bat`**，或：

```powershell
.\scripts\install.ps1
```

### 5.2 安装流程

```
1. 调用 build-portable.ps1 确保产物存在
2. 若程序正在运行则先结束进程
3. 清空并重建安装目录
4. 复制 dist\音乐播放器-win32-x64\* 到安装目录
5. 在安装目录写入 卸载.bat
6. 创建桌面快捷方式
7. 创建开始菜单快捷方式
```

### 5.3 安装位置

```
%LOCALAPPDATA%\Programs\音乐播放器
```

展开后通常是 `C:\Users\<用户名>\AppData\Local\Programs\音乐播放器`。

### 5.4 参数

| 参数 | 说明 |
| --- | --- |
| `-InstallDir` | 自定义安装目录 |
| `-Launch` | 安装完成后立即启动 |
| `-NoBuild` | 跳过构建，直接复制已有 `dist` 产物 |
| `-NoShortcuts` | 不创建快捷方式 |

```powershell
# 安装并启动
.\scripts\install.ps1 -Launch

# 安装到 D 盘
.\scripts\install.ps1 -InstallDir 'D:\Apps\音乐播放器'

# 只复制文件，不创建快捷方式
.\scripts\install.ps1 -NoShortcuts

# 已经构建过，跳过构建步骤
.\scripts\install.ps1 -NoBuild -Launch
```

### 5.5 卸载

三种方式任选：

1. 运行安装目录下的 **`卸载.bat`**（会结束进程、删除安装目录与快捷方式）
2. 删除文件夹 `%LOCALAPPDATA%\Programs\音乐播放器`
3. 删除桌面与开始菜单里的快捷方式

程序不在注册表写入任何内容，删除文件夹就是完全卸载。

用户数据（播放列表、播放进度、收藏）保存在 Electron 的 `userData` 目录：

```
%APPDATA%\music-player
```

如需彻底清除，把该目录一并删除。

## 6. 推送到 GitHub

仓库根目录的 `scripts\push-to-github.ps1` 把「设置 origin → 检查身份 → 推送」合并成一步：

```powershell
.\scripts\push-to-github.ps1 -RepoUrl 'https://github.com/你的用户名/music-player.git'
```

脚本会：

1. 检查 git 可用、当前目录是仓库
2. 检查提交身份（`user.name` / `user.email`），缺失时交互式询问并写入仓库本地配置
3. 有未提交改动时询问是否先提交
4. 设置或更新 `origin`，并把分支重命名为 `main`
5. `git push -u origin main`，并**显式检查退出码**（PowerShell 5.1 不会因原生命令失败而抛异常，
   不检查的话推送失败也会打印"成功"）
6. `git push origin --tags` 推送版本标签（失败不阻断，代码已经推上去了）
7. 失败时打印针对性的排查建议

### 版本标签

仓库带两个附注标签，记录了版本演进：

| 标签 | 对应提交 | 说明 |
| --- | --- | --- |
| `v1.0.0` | 首个公开发布版本 | 本地曲库 + 频谱可视化 + 迷你悬浮窗 + 媒体键 |
| `v1.1.0` | 派生数据管控 + 历史版本回滚 | 三层数据管控、`versions\` 存档、审计日志 |

```powershell
git tag -n1                      # 列出标签与说明
git show v1.1.0 --stat           # 看某个版本改了什么
git checkout v1.0.0 -- app/      # 把某个版本的文件取出来（不切换分支）
git push origin --tags           # 单独补推标签
```

推上去之后，在 GitHub 仓库的 **Releases → Tags** 可以看到，也可以基于标签创建 Release。

### 远端已有内容（网页上建仓库时勾了 README）

```powershell
.\scripts\push-to-github.ps1 -RepoUrl 'https://github.com/你的用户名/music-player.git' -Pull
```

`-Pull` 会先 `fetch` 再 `pull --allow-unrelated-histories`（网页建仓产生的历史与本仓库无关，
不加这个参数会报 `refusing to merge unrelated histories`）。

### 认证

脚本**不保存任何凭证**，认证交给 git 的凭据管理器（Windows 上通常是 Git Credential Manager），
首次推送会弹出浏览器登录窗口。

GitHub 已取消密码认证，如果弹出的是用户名/密码框：

- **用户名**：GitHub 用户名
- **密码**：粘贴 **Personal Access Token**（[生成地址](https://github.com/settings/tokens)，
  选 `Generate new token (classic)`，勾选 `repo` 权限）

也可以改用 SSH：

```powershell
git remote set-url origin git@github.com:你的用户名/music-player.git
git push -u origin main
```

或安装 [GitHub CLI](https://cli.github.com/) 后：

```powershell
gh auth login
gh repo create music-player --public --source=. --push
```

### 为什么不把运行时提交上去

| 限制 | 数值 |
| --- | --- |
| GitHub 单文件硬上限 | 100 MB |
| 本项目 `音乐播放器.exe` | **约 172 MB**（超限，无法推送） |
| 完整运行时 | 约 222 MB |
| 仓库推荐体积 | 1 GB 以内 |

所以 `.gitignore` 排除了 `dist/`。仓库只有源码、脚本与文档，克隆后运行
`scripts\build-portable.ps1` 即可在本地准备运行时。

> Git LFS 也不是好选择：222 MB 会占掉免费 LFS 配额（1 GB）的五分之一，
> 且每位克隆者都要下载同样体积。

## 7. 分发建议

### 6.1 便携版（推荐）

把整个 `dist\音乐播放器-win32-x64\` 文件夹压缩后分发。接收方解压即用，
**不需要安装、不需要管理员权限**，可以放在 U 盘里。

压缩后大约 90 ~ 110 MB（Electron 运行时压缩率较高）。

### 6.2 自己做安装包

仓库的 `scripts\install.ps1` 是「绿色安装」，不生成单个 exe 安装包。
如果需要传统的单文件安装程序，可用以下工具之一包装 `dist\音乐播放器-win32-x64\`：

| 工具 | 说明 |
| --- | --- |
| [Inno Setup](https://jrsoftware.org/isinfo.php) | 免费，脚本化，推荐 |
| [NSIS](https://nsis.sourceforge.io/) | 免费，体积小 |
| [electron-builder](https://www.electron.build/) | 需要 Node.js，可直接产出 NSIS / portable target |

使用 electron-builder 时，把 `app/` 当作 `files`，`directories.output` 指向 `dist/`，
即可复用本文档的目录约定。

### 6.3 不要提交运行时到 Git

Electron 运行时约 222 MB，远超 GitHub 的合理体积限制：

- GitHub 单文件硬上限 100 MB（`音乐播放器.exe` 约 172 MB，**无法推送**）
- 仓库推荐体积 1 GB 以内
- 大文件会用尽 LFS 配额

因此 `.gitignore` 已排除 `dist/`。仓库只保存源码、脚本与文档，
运行时由使用者在本地通过 `scripts\build-portable.ps1` 准备。

## 8. 版本回滚

`versions/` 保存了 `musicplayer.html` 历史上 12 个关键节点的逐字节快照，
用于可视化效果调坏时快速退回已知可用状态。

### 8.1 快照来源与可靠性

从 DSH 会话日志里把 `musicplayer.html` 的**全部 write/edit 操作按时间反向重放**还原。
日志里的 `edit` 是精确字符串替换，因此反向回放能逐字节还原历史状态
（P 系列回放 204 处成功、0 失败）。

### 8.2 使用脚本

```powershell
# 列出全部版本（并指出当前 app\index.html 对应哪一个）
.\scripts\use-version.ps1 -List

# 回滚到 Q1
.\scripts\use-version.ps1 -Version Q1

# 只换源码，不重新构建
.\scripts\use-version.ps1 -Version R1 -NoBuild
```

`-Version` 匹配顺序：完整文件名 → 前缀 → 关键字，唯一匹配即可。
匹配到多个会报错并列出候选，不会瞎猜。

### 8.3 脚本做了什么

1. 计算当前 `app/index.html` 的 MD5，备份到 `dist\版本备份\index-<时间戳>-<版本名>.html`
2. 把目标快照复制成 `app/index.html`，并校验 MD5
3. 把当前版本名写入 `dist\版本备份\当前版本.txt`
4. 默认调用 `build-portable.ps1` 让改动生效

`dist/` 已被 `.gitignore` 排除，所以备份不会污染仓库。

### 8.4 切回最新版

```powershell
# 方式一：git
git checkout -- app/index.html

# 方式二：用备份
.\scripts\use-version.ps1 -Version index-20260922-214648-当前开发版
```

`-List` 会在「本机备份」一节列出所有备份文件名，直接复制即可。

### 8.5 兼容性

12 个快照都是**自包含单文件 HTML**，且只调用当前 `app/preload.js` 里仍然存在的 IPC
（`findLyrics` / `convertNcm` / `setRenderMode` / `getGpuStatus` / `getDisplayInfo`），
所以可以直接当 `app/index.html` 使用，**不需要一并回滚 `main.js` / `preload.js`**。

代价是快照来自「单文件播放器」时期，**不认识**后来加入的：

- `bili.js` — B 站缓存提取
- `cover.js` — 新版封面解析
- `ncmdump.exe` — NCM 官方解密
- `mini.html` — 迷你悬浮窗
- 多歌手识别、媒体键自检、主题系统等

### 8.6 手工回滚

不想用脚本的话，两步即可：

```powershell
Copy-Item 'versions\Q1_preWave.html' 'app\index.html' -Force
.\scripts\build-portable.ps1
```

版本对照表、每版说明，以及一段**已被后续需求推翻的历史约束记录**
（2026-09-13 曾明令禁止横移 / `wavePhase` 行波）见 [../versions/README.md](../versions/README.md)。

## 9. 故障排查

| 现象 | 原因 | 解决 |
| --- | --- | --- |
| `找不到 app 目录` | 在错误的工作目录运行 | 用 `cd` 切到仓库根目录，或直接双击 `构建.bat` |
| `app 目录缺少必需文件` | 源码不完整 | 检查 `app/` 下是否有 `index.html` / `main.js` / `preload.js` / `mini.html` / `package.json` |
| 下载 Electron 失败 | 网络 / 镜像不可达 | 用 `-RuntimeDir` 指定本地已有的运行时，或挂代理后重试 |
| `无法清理旧安装目录` | 程序仍在运行 | 先关闭程序；安装脚本已尝试自动结束进程 |
| `同步校验失败` | 复制过程中被占用 | 关闭程序后重新构建 |
| 启动后白屏 | `resources/app` 不完整 | 重新运行构建脚本 |
| NCM 无法解密 | `ncmdump.exe` 缺失或被拦截 | 确认 `app/ncmdump.exe` 存在，并加入杀软白名单 |
| 提示脚本被禁止运行 | 执行策略限制 | 使用 `安装.bat` / `构建.bat`（已带 `-ExecutionPolicy Bypass`），或在管理员 PowerShell 中 `Set-ExecutionPolicy -Scope CurrentUser RemoteSigned` |
