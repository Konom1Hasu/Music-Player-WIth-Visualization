# 构建与安装

本文档说明如何从源码构建便携版、如何安装到本机、以及如何自行打包分发。

---

## 1. 环境要求

| 项目 | 要求 |
| --- | --- |
| 操作系统 | Windows 10 / 11 x64 |
| PowerShell | 5.1 或更高（Windows 自带） |
| 磁盘空间 | 约 300 MB（Electron 运行时约 222 MB + 应用源码约 5 MB + 解压临时空间） |
| 网络 | 仅首次构建需要（用于下载 Electron 运行时）；已有本地运行时则完全离线 |
| 管理员权限 | **不需要**（安装到用户目录） |

> **只是想装上用：不需要 Node.js。** 到 Releases 下载 Setup.exe 双击即可（见 §5.1）。
> 从源码装也可以双击 `安装.bat`（见 §5.2）。
> Node.js 只在"改了界面源码、要重新构建界面产物"，或者本地打安装包时才用得到
> （界面用 Vite 构建；安装包用 Inno Setup 编译，见 §3.6）。
> 没装 Node 依赖时构建会跳过界面重建、沿用 `app\ui` 里已有的产物，不会失败。

---

## 2. 目录约定

```
音乐播放器/
├── app/          ← 应用源码，唯一需要修改的地方
├── scripts/      ← 构建与安装脚本
├── dist/         ← 构建输出（已被 .gitignore 排除，不入库）
└── docs/         ← 文档
```

**重要**：不要直接修改 `dist/` 里的文件。`dist/音乐播放器-win32-x64/resources/app/`
是构建产物，每次构建都会被 `app/` 的内容完整覆盖。

## 3. 构建便携版

### 3.1 一键构建

双击根目录的 **`构建.bat`**，或在 PowerShell 中运行：

```powershell
cd '路径\音乐播放器'
.\scripts\build-portable.ps1
```

### 3.2 构建流程

```
1. 校验 app/ 必需文件（index.html / main.js / preload.js / mini.html / package.json）
2. 检查可选模块（bili.js / cover.js / ncmdump.exe），缺失只警告不报错
3. 准备 Electron 运行时：
     ① -RuntimeDir 指定的目录
     ② 已有的 dist\音乐播放器-win32-x64\
     ③ 从镜像下载 Electron 31.7.7 win32-x64 并解压
4. electron.exe 重命名为 音乐播放器.exe，删除 default_app.asar
5. 准备界面产物：app-rhine 能构建就 `npm run build` 并同步到 app\ui；
   没有 node_modules（没装 Node 依赖）时跳过重建、沿用 app\ui 里已有的产物并提示一行
6. 清空并重建 resources\app，把 app\ 完整复制进去
7. 对必需文件做 MD5 校验，确认同步无误
8. 打印产物路径与体积
```

> 第 5 步是 2.0.1 补的教训：原来的脚本既不会重建 `app-rhine/dist`、也不会同步到 `app/ui/`，
> 于是便携版里界面还是上一个版本的 JS。**发布**时必须真构建一次
> （`release.ps1` 流程里会保证 `node_modules` 存在）。

### 3.3 参数

| 参数 | 默认值 | 说明 |
| --- | --- | --- |
| `-ElectronVersion` | `31.7.7` | Electron 版本号 |
| `-RuntimeDir` | 空 | 已有运行时目录（含 `electron.exe` 或 `音乐播放器.exe`） |
| `-OutDir` | `dist\音乐播放器-win32-x64` | 输出目录 |
| `-Mirror` | `https://npmmirror.com/mirrors/electron` | 下载镜像前缀 |
| `-Force` | 关 | 强制重新下载运行时 |

### 3.4 示例

```powershell
# 使用本地已有的 Electron 运行时（完全离线）
.\scripts\build-portable.ps1 -RuntimeDir 'D:\downloads\electron-v31.7.7-win32-x64'

# 换 Electron 版本
.\scripts\build-portable.ps1 -ElectronVersion 33.0.0

# 强制重建（重新下载运行时）
.\scripts\build-portable.ps1 -Force

# 只同步源码到已有运行时（最快，日常改代码用这个）
.\scripts\build-portable.ps1
# ↑ 运行时已存在时会自动复用，只做第 5 步的源码同步
```

### 3.5 手动构建

不想用脚本的话，手动三部即可：

```powershell
# 1. 下载 Electron 31.7.7 win32-x64 并解压到 dist\音乐播放器-win32-x64
#    https://npmmirror.com/mirrors/electron/31.7.7/electron-v31.7.7-win32-x64.zip

# 2. 重命名 exe
Rename-Item 'dist\音乐播放器-win32-x64\electron.exe' '音乐播放器.exe'

# 3. 把 app\ 复制成 resources\app
Remove-Item 'dist\音乐播放器-win32-x64\resources\app' -Recurse -Force -ErrorAction SilentlyContinue
Copy-Item 'app' 'dist\音乐播放器-win32-x64\resources\app' -Recurse
```

## 4. 每日开发流程

改代码 → 同步到运行时 → 运行：

```powershell
# 同步（运行时已存在，秒级完成）
.\scripts\build-portable.ps1

# 运行
.\dist\音乐播放器-win32-x64\音乐播放器.exe
```

`app/` 里的文件与运行时里的对应关系：

| 源码 | 运行时 |
| --- | --- |
| `app/index.html` | `resources/app/index.html` |
| `app/main.js` | `resources/app/main.js` |
| `app/preload.js` | `resources/app/preload.js` |
| `app/mini.html` | `resources/app/mini.html` |
| `app/bili.js` | `resources/app/bili.js` |
| `app/cover.js` | `resources/app/cover.js` |
| `app/ncmdump.exe` | `resources/app/ncmdump.exe` |
| `app/package.json` | `resources/app/package.json` |

> 程序运行时 `resources/app` 下的文件被锁定，构建脚本会先尝试覆盖；
> 若失败请先关闭程序再构建。

### 3.6 打一键安装包（Inno Setup）

把上面那个便携目录包成**单文件 Setup.exe**：

```powershell
# 需要 Inno Setup 6（命令行编译器 ISCC.exe）
winget install -e --id JRSoftware.InnoSetup

.\scripts\build-installer.ps1      # 也可以双击 打包安装包.bat
# 产物：dist\安装包\音乐播放器-Setup-<版本>.exe
```

脚本会：先跑一次 `build-portable.ps1`（可 `-NoBuild` 跳过）→ 校验
`resources\app\ui\index.html` 确实引用到了界面产物（防止把旧界面打进安装包）→
用 `installer\music-player.iss` 编译 → 打印体积与 SHA256。

| 参数 | 说明 |
| --- | --- |
| `-Version` | 覆盖版本号（默认读 `app\package.json` 的 `version`） |
| `-OutDir` | 输出目录，默认 `dist\安装包` |
| `-NoBuild` | 跳过便携版构建，直接用已有的 `dist\音乐播放器-win32-x64` |
| `-Quiet` | 编译时不输出进度 |

**用户拿到的向导**（刻意做短，每一步都为了少点一次鼠标）：

```
欢迎  →  选择目录（默认 %LOCALAPPDATA%\Programs\音乐播放器）
      →  附加任务（☑ 创建桌面快捷方式 —— 默认勾选，可以取消）
      →  安装  →  完成（可勾"立即运行"）
```

没有许可页（MIT 声明随程序装进 `resources\app\LICENSE.txt`）、没有开始菜单组页面、
没有"准备安装"确认页。安装包的行为定义在 `installer\music-player.iss` 里，几个关键选择：

- **按用户安装**（`PrivilegesRequired=lowest` + `{localappdata}\Programs`）：双击即可，不弹 UAC
- **AppId 固定**：新版本认成升级、覆盖到原目录，不会并存两份
- **卸载不删用户数据**：`%APPDATA%\music-player`（曲库 / 收藏 / 设置）原样保留
- **桌面快捷方式是可选任务**：`[Tasks] desktopicon`（Inno 里默认勾上）＋
  `[Icons]` 里那一条带 `Tasks: desktopicon`，取消勾选就不建
- **不写 `ArchitecturesAllowed`**：该指令取值在 Inno 6.3 前后不同，写死会让另一版本的 ISCC 报错；
  本程序是纯文件树，装到 `{localappdata}`，用不到 64 位安装模式
- 向导文案用「英文 `Default.isl` + 覆盖用户会读到的那些消息」的方式做成中文
  （Inno 官方发行版不带简体中文语言文件，中文是社区翻译）
- 想给安装包换图标：把 `app.ico` 放进 `installer\`，构建脚本会自动带上

> ⚠ `installer\music-player.iss` **必须存成 UTF-8 带 BOM**，否则 Inno 会把中文按本地代码页读成乱码。
> 同理 `scripts\*.ps1`（PowerShell 5.1 没有 BOM 时也按本地代码页读）。
> 而根目录与 `scripts\` 下的 **`.bat` 必须相反 —— 一个非 ASCII 字节都不能有**：
> cmd.exe 按字节偏移重读批处理，注释里写个中文路径就会让后面的行被当成命令去执行
> （实际踩过：终端刷出 `'Needs' 不是内部或外部命令`、`'wershell' 不是…` 这种碎片）。
> 这两条现在都由 `scripts\文档一致性验证.js` 常态化检查（第 [9]、[10] 项）。

**已在本机验证过**：用 Inno Setup 6.7.3 编译出 `音乐播放器-Setup-2.1.1.exe`（94.4 MB），
并静默装 / 卸两轮 —— 一轮带 `desktopicon`、一轮不带，确认桌面快捷方式确实可选、
卸载后安装目录与快捷方式都清干净。见 `docs\更新日志.md` 的「未发版」段。

### 3.7 自动构建与发布（GitHub Actions）

`.github\workflows\release.yml`：**推一个 `v*` 标签就自动出安装包并挂到 Release 上**，
用户只需要下载 Setup.exe 双击安装。

```
打标签（v2.1.2）  →  Actions 跑起来
                      ├─ 校验标签与 app\package.json 的版本号一致
                      ├─ 文档一致性 + 三套离线回归验证（数据管控 / 设置持久化 / ID3）
                      ├─ choco install innosetup
                      ├─ build-installer.ps1 → 便携版 + Setup.exe
                      ├─ 上传 Actions 产物（artifact）
                      └─ gh release create / upload → Release 里挂上 Setup.exe
                  →  用户下载 音乐播放器-Setup-2.1.2.exe，双击安装
```

- **触发**：推 `v*` 标签（`scripts\release.ps1` 会打）；也可以在 Actions 页面手动 `workflow_dispatch`
  —— 手动触发只出 artifact，不碰 Release
- **标签必须等于 `v` + `app\package.json` 的版本号**：不一致直接失败，
  免得发出"标签写 2.1.2、实际装 2.1.1"的包
- **发布说明**里带上文件名与 SHA256
- CI 与本地**共用同一套打包逻辑**（`build-portable.ps1` + `build-installer.ps1`），
  CI 不另起一套，所以本地能出什么、CI 就能出什么

## 5. 安装到本机

### 5.1 普通用户：下载 Setup.exe 双击安装（推荐）

到 **[Releases](https://github.com/Konom1Hasu/Music-Player-WIth-Visualization/releases)**
下载 `音乐播放器-Setup-x.y.z.exe`，双击 → 下一步 → 完成。**不需要管理员权限**。

| 项 | 说明 |
| --- | --- |
| 安装形态 | 单文件安装程序（Inno Setup 打包，见 §3.6） |
| 安装位置 | `%LOCALAPPDATA%\Programs\音乐播放器`（按用户；不弹 UAC） |
| 快捷方式 | 桌面（可取消勾选）＋ 开始菜单「音乐播放器」 |
| 卸载 | 「应用和功能」里的「音乐播放器」，或开始菜单里的「卸载 音乐播放器」 |
| 用户数据 | 曲库 / 收藏 / 设置都在 `%APPDATA%\music-player`，**卸载不会删除** |
| 升级 | 装新版本会覆盖到同一目录（AppId 固定），不会并存两份 |

> 和便携版的区别只有一个：安装包会做"装到系统里"这件事（快捷方式 + 卸载入口，
> 卸载信息写在 `HKCU` 供「应用和功能」读取）。程序本身依旧不写注册表。
> 不想要安装形态，就用便携版（见 §7.1）。

### 5.2 从源码一键安装（`安装.bat`）

**双击根目录的 `安装.bat`** —— 就这一步。它会自动完成：构建（需要时）→ 安装 →
创建桌面 / 开始菜单快捷方式 → **直接打开播放器**。成功后窗口自己关掉，不需要再按键，
也不需要另外去点快捷方式。

等价于：

```powershell
.\scripts\install.ps1 -Launch
```

只装不启动：

```powershell
.\scripts\install.ps1              # 直接跑脚本
.\安装.bat -NoLaunch               # 或者双击时想装完不启动
```

> **不需要先"构建"再"安装"。** `安装.bat` 会自动调用构建；
> 也不会因为没装 Node 依赖而失败 —— `app-rhine\node_modules` 不存在时会跳过界面重建、
> 沿用 `app\ui` 里已有的构建产物（会提示一行警告）。
> 换句话说：**从源码仓库直接双击 `安装.bat` 就能装好**，
> 只有"改了界面源码、想让改动进包"时才需要 `cd app-rhine; npm install`。
>
> 注意这条走的是 PowerShell 绿色安装（不生成 Setup.exe、不在注册表留卸载项）。
> 想要和 Releases 上一样的安装体验，用 §3.6 打一个安装包。

### 5.3 安装流程

```
1. 调用 build-portable.ps1 准备产物（含界面产物：能构建就重建，不能就沿用 app\ui）
2. 若程序正在运行则先结束进程
3. 清空并重建安装目录
4. 复制 dist\音乐播放器-win32-x64\* 到安装目录
5. 在安装目录写入 卸载.bat
6. 创建桌面快捷方式
7. 创建开始菜单快捷方式
8. 启动程序（安装.bat 默认带上；install.ps1 要 -Launch）
```

### 5.4 安装位置

```
%LOCALAPPDATA%\Programs\音乐播放器
```

展开后通常是 `C:\Users\<用户名>\AppData\Local\Programs\音乐播放器`。

### 5.5 参数

| 参数 | 说明 |
| --- | --- |
| `-InstallDir` | 自定义安装目录 |
| `-Launch` | 安装完成后立即启动（`安装.bat` 默认带） |
| `-NoLaunch` | 装完不启动（仅当同时给了 `-Launch` 时才有意义） |
| `-NoBuild` | 跳过构建，直接复制已有 `dist` 产物 |
| `-NoShortcuts` | 不创建快捷方式 |

```powershell
# 安装并启动（= 双击 安装.bat）
.\scripts\install.ps1 -Launch

# 安装到 D 盘
.\scripts\install.ps1 -Launch -InstallDir 'D:\Apps\音乐播放器'

# 只复制文件，不创建快捷方式
.\scripts\install.ps1 -NoShortcuts

# 已经构建过，跳过构建步骤
.\scripts\install.ps1 -NoBuild -Launch
```

### 5.6 卸载

**装的是 Setup.exe（§5.1）**：

1. 「设置 → 应用 → 已安装的应用」里找「音乐播放器」→ 卸载
2. 或开始菜单「音乐播放器」组里的「卸载 音乐播放器」
3. 这个卸载入口记在 `HKCU`（Windows 的"应用和功能"就是这么工作的）；程序本身不写注册表

**装的是 `安装.bat` / `install.ps1`（§5.2）**：三种方式任选：

1. 运行安装目录下的 **`卸载.bat`**（会结束进程、删除安装目录与快捷方式）
2. 删除文件夹 `%LOCALAPPDATA%\Programs\音乐播放器`
3. 删除桌面与开始菜单里的快捷方式

这一种不写注册表，删除文件夹就是完全卸载。

两种方式都**不会删除用户数据**。曲库（IndexedDB）、收藏与设置都在 Electron 的
`userData` 目录：

```
%APPDATA%\music-player
```

需要彻底清除时手动删除该目录。反过来说：重装、升级、换安装方式都不会丢曲库。

## 6. 推送到 GitHub

日常更新只需要一条命令（**沿用已有的 `origin`，不需要再写仓库地址**）：

```powershell
.\scripts\push-to-github.ps1
```

也可以双击根目录的 **`推送.bat`**。

首次推送需要指定仓库地址：

```powershell
.\scripts\push-to-github.ps1 -RepoUrl 'https://github.com/你的用户名/music-player.git'
```

### 参数

| 参数 | 说明 |
| --- | --- |
| `-RepoUrl` | 仓库地址。**可省略** —— 省略时沿用已有 `origin` |
| `-Branch` | 分支名，默认 `main` |
| `-Pull` | 推送前先 `fetch` 并合并（远端有本仓库没有的提交时用） |
| `-Check` | 只探测推送通道，不做任何推送 |
| `-NoAutoFix` | 关闭自动适配，只用最朴素的 `git push` |

### 脚本会做什么

1. 检查 git 可用、当前目录是仓库
2. 检查提交身份（`user.name` / `user.email`），缺失时交互式询问并写入仓库本地配置
3. 有未提交改动时询问是否先提交
4. 确定 `origin`（沿用已有地址，或按 `-RepoUrl` 设置 / 更新），并把分支重命名为 `main`
5. **探测推送通道**，失败则按错误类型自动适配（见下）
6. `git push -u origin main` —— 显式检查退出码，失败时按错误类型给出针对性提示
7. `git push origin --tags` 推送版本标签（失败不阻断，代码已经推上去了）

### 自动适配的两类障碍

脚本先跑一次 `git ls-remote` 探测通道，失败时**按错误类型**决定兜底方式：

| 判定 | 触发特征 | 兜底动作 |
| --- | --- | --- |
| `tls` | `unable to get local issuer certificate`、`schannel`、`SEC_E_NO_CREDENTIALS` | 改用 **openssl 后端** + 合并本机自签 CA 的 bundle |
| `credential` | `could not read Username`、`couldn't create signal pipe` | 直接调用 `git-credential-manager.exe` 取缓存凭证，拼成 `Authorization` 头 |
| `network` | `Could not resolve host`、`Failed to connect` | 不做兜底，直接报错 |
| `nonfastforward` | `rejected`、`fetch first` | 提示加 `-Pull` |

在正常环境里这两条兜底都不会触发，脚本就是普通的 `git push`。

> 兜底只通过 **`GIT_CONFIG_*` 环境变量**生效，**不写进 `.git/config`** ——
> 只在本次命令有效，不影响你在自己终端里的 git 行为。
>
> 取缓存凭证时**只报告"拿到了"，不打印 token 内容**。

### 版本标签

仓库带三个附注标签，记录了版本演进：

| 标签 | 说明 |
| --- | --- |
| `v1.0.0` | 首个公开发布版本：本地曲库 + 频谱可视化 + 迷你悬浮窗 + 媒体键 |
| `v1.1.0` | 派生数据三层管控 + 历史版本回滚 + 审计日志 |
| `v1.1.1` | 修复调音设置重启后丢失 |

```powershell
git tag -n1                      # 列出标签与说明
git show v1.1.0 --stat           # 看某个版本改了什么
git checkout v1.0.0 -- app/      # 把某个版本的文件取出来（不切换分支）
git push origin --tags           # 单独补推标签
```

推上去之后，在 GitHub 仓库的 **Releases → Tags** 可以看到，也可以基于标签创建 Release。

### 推送不通时的排查：schannel 与加速器

> 这一节讲**原理与手动排查**。日常不需要看 —— `push-to-github.ps1` 已经内置了自动适配，
> 探测失败时会自己改走 openssl 后端并合并本机 CA（见上文「自动适配的两类障碍」）。
> 需要手动介入时，再用下面的命令定位。

两种典型症状，成因完全不同。

**症状 A：`schannel: AcquireCredentialsHandle failed: SEC_E_NO_CREDENTIALS (0x8009030e)`**

Windows 的 schannel（git 默认 TLS 后端）完全用不了 —— 这个错误对**所有** HTTPS 站点都出现，
连 `https://www.baidu.com` 也失败。区分方法（Node 自带 OpenSSL，不走 schannel）：

```powershell
node -e "require('https').get('https://www.baidu.com',r=>{console.log('HTTP',r.statusCode);process.exit(0)}).on('error',e=>{console.log('ERR',e.code);process.exit(1)})"
```

如果 Node 能通 → 网络没问题，只是 schannel 不可用，走下面的"解决办法"。

**症状 B：`SSL certificate problem: unable to get local issuer certificate`**

网络通，但对端证书验不过。装了 **Steam++ / Watt Toolkit** 这类加速器时会这样：
它把 `github.com` 的 DNS 劫持到 `127.0.0.1`，并用**自己的根证书**做 TLS 中间人。

```powershell
# 看对端证书是谁签的（不校验证书也要能把 issuer 读出来）
node -e "const h=require('https');h.get({host:'github.com',rejectUnauthorized:false},r=>{const c=r.socket.getPeerCertificate();console.log('issuer:',c.issuer.CN,'|',c.issuer.O)}).on('error',e=>console.log(e.code))"
# 输出示例：issuer: SteamTools Certificate | BeyondDimension
```

这个根证书装在 **Windows 证书库**里，所以走 schannel 的 git 天然信任它；
但 git 的 **openssl** 后端只认自己的 CA bundle，不认识它 → 报 B。

**解决办法：改用 openssl 后端 + 把本机自签 CA 合并进 bundle**

```powershell
.\scripts\setup-push-tls.ps1 -Test      # 生成 bundle 并立刻验证通道
.\scripts\setup-push-tls.ps1 -PrintEnv  # 只打印要设置的环境变量
```

脚本做的事：

1. 以 git 自带的 `ca-bundle.crt`（公共根证书）为基准
2. 追加 `Cert:\LocalMachine\Root` 里所有**自签且未过期**的根证书（加速器的中间人 CA 就在其中）
3. 写入 `dist\git-ca\ca-bundle.pem`
4. 用**环境变量**（`GIT_CONFIG_COUNT` / `GIT_CONFIG_KEY_n` / `GIT_CONFIG_VALUE_n`）
   把 `http.sslBackend=openssl` 与 `http.sslCAInfo` 传给 git

用环境变量而不是写进 `.git/config`：**不改动仓库配置**，只在本次命令生效，
不会影响你在自己终端里的正常 git 行为。

> bundle 内含本机私有 CA，属于本机材料 —— `dist/` 已被 `.gitignore` 排除，不会被提交。
>
> 想让加速器不影响 git，也可以在 Steam++ 里把 GitHub 的加速项关掉，
> 那样 schannel 直接连真实 GitHub 即可，不需要这个 bundle。

### 推送不通时的排查：凭证助手起不来

**症状 C：**
```
sh.exe: *** fatal error - couldn't create signal pipe, Win32 error 5
fatal: could not read Username for 'https://github.com': terminal prompts disabled
```

TLS 已经通了（否则会是症状 A/B），卡在**取凭证**这一步。
原因是 Git for Windows 把 `credential.helper = manager` 里的 `manager` 解析成
`mingw64/bin/git-credential-manager`（一个**shell 包装脚本**），
于是 git 会先起 MSYS 的 `sh.exe` —— 而某些受限环境禁止创建命名管道，
`sh.exe` 根本起不来，凭证助手自然没被调用，git 只好回落到终端提示（又被禁用了）。

**先确认凭证是否真的已缓存**（有缓存才谈得上绕开助手）：

```powershell
cmdkey /list | Select-String 'git:https://github.com'
# 期望看到：Target: LegacyGeneric:target=git:https://github.com  User: <你的用户名>
```

**绕开办法：不走 git 的凭证机制，直接取缓存凭证当 HTTP 头用**

```powershell
# 直接调用 exe（用 PowerShell 的管道，不涉及 MSYS）
$c = "protocol=https`nhost=github.com`n`n" |
     & 'C:\Program Files\Git\mingw64\bin\git-credential-manager.exe' get
# 输出里含 username= 与 password=（password 就是 token）
```

把 `username:password` 做 Base64 后作为 `Authorization: Basic ...` 交给 git。
**走 `GIT_CONFIG_*` 环境变量而不是命令行参数**，减少暴露面：

```powershell
$b64 = [Convert]::ToBase64String(
         [Text.Encoding]::UTF8.GetBytes("$user`:$token"))
$env:GIT_CONFIG_COUNT   = '3'
$env:GIT_CONFIG_KEY_0   = 'http.sslBackend';  $env:GIT_CONFIG_VALUE_0 = 'openssl'
$env:GIT_CONFIG_KEY_1   = 'http.sslCAInfo';   $env:GIT_CONFIG_VALUE_1 = '<bundle 路径>'
$env:GIT_CONFIG_KEY_2   = 'http.extraheader'; $env:GIT_CONFIG_VALUE_2 = "Authorization: Basic $b64"
git push -u origin main
```

两个容易踩的坑：

- **git 的推送进度是写到 stderr 的**（`To https://...`、`Writing objects`）。
  在 `$ErrorActionPreference = 'Stop'` 的脚本里调用 git，PowerShell 会把原生命令的
  stderr 当成终止性错误并中断 —— 必须在调用 git 前后临时放宽。
- 含中文的 `.ps1` **必须存成 UTF-8 with BOM**。PowerShell 5.1 读无 BOM 的 UTF-8 文件会按
  ANSI/GBK 解码，中文里可能出现被误认成引号或反引号的字节，导致「字符串缺少终止符」这类
  莫名其妙的语法错误。

### 为什么不把运行时提交上去

| 限制 | 数值 |
| --- | --- |
| GitHub 单文件硬上限 | 100 MB |
| 本项目 `音乐播放器.exe` | **约 172 MB**（超限，无法推送） |
| 完整运行时 | 约 222 MB |
| 仓库推荐体积 | 1 GB 以内 |

所以 `.gitignore` 排除了 `dist/`。仓库只有源码、脚本与文档，克隆后运行
`scripts\build-portable.ps1` 即可在本地准备运行时。

> Git LFS 也不是好选择：222 MB 会占掉免费 LFS 配额（1 GB）的五分之一，
> 且每位克隆者都要下载同样体积。

## 7. 分发建议

### 7.1 一键安装包（推荐）

`.github\workflows\release.yml` 自动产出的单个 `音乐播放器-Setup-x.y.z.exe`，
发到 GitHub Release 上，用户下载后双击安装（见 §5.1）。这是给最终用户的主路径：
**不需要装 Node、不需要构建、不需要管理员权限。**

安装包内就是 §7.2 那个便携目录，两者内容完全一致。

### 7.2 便携版（免安装）

把整个 `dist\音乐播放器-win32-x64\` 文件夹压缩后分发。接收方解压即用，
**不需要安装、不需要管理员权限**，可以放在 U 盘里。压缩后大约 90 ~ 110 MB
（Electron 运行时压缩率较高；打成 Inno Setup 安装包后体积接近）。

### 7.3 不要提交运行时到 Git

Electron 运行时约 222 MB，远超 GitHub 的合理体积限制：

- GitHub 单文件硬上限 100 MB（`音乐播放器.exe` 约 172 MB，**无法推送**）
- 仓库推荐体积 1 GB 以内
- 大文件会用尽 LFS 配额

因此 `.gitignore` 已排除 `dist/`。仓库只保存源码、脚本与文档，
运行时由使用者在本地通过 `scripts\build-portable.ps1` 准备。

## 8. 版本回滚

`versions/` 保存了 `musicplayer.html` 历史上 12 个关键节点的逐字节快照，
用于可视化效果调坏时快速退回已知可用状态。

### 8.1 快照来源与可靠性

从 DSH 会话日志里把 `musicplayer.html` 的**全部 write/edit 操作按时间反向重放**还原。
日志里的 `edit` 是精确字符串替换，因此反向回放能逐字节还原历史状态
（P 系列回放 204 处成功、0 失败）。

### 8.2 使用脚本

```powershell
# 列出全部版本（并指出当前 app\index.html 对应哪一个）
.\scripts\use-version.ps1 -List

# 回滚到 Q1
.\scripts\use-version.ps1 -Version Q1

# 只换源码，不重新构建
.\scripts\use-version.ps1 -Version R1 -NoBuild
```

`-Version` 匹配顺序：完整文件名 → 前缀 → 关键字，唯一匹配即可。
匹配到多个会报错并列出候选，不会瞎猜。

### 8.3 脚本做了什么

1. 计算当前 `app/index.html` 的 MD5，备份到 `dist\版本备份\index-<时间戳>-<版本名>.html`
2. 把目标快照复制成 `app/index.html`，并校验 MD5
3. 把当前版本名写入 `dist\版本备份\当前版本.txt`
4. 默认调用 `build-portable.ps1` 让改动生效

`dist/` 已被 `.gitignore` 排除，所以备份不会污染仓库。

### 8.4 切回最新版

```powershell
# 方式一：git
git checkout -- app/index.html

# 方式二：用备份
.\scripts\use-version.ps1 -Version index-20260922-214648-当前开发版
```

`-List` 会在「本机备份」一节列出所有备份文件名，直接复制即可。

### 8.5 兼容性

12 个快照都是**自包含单文件 HTML**，且只调用当前 `app/preload.js` 里仍然存在的 IPC
（`findLyrics` / `convertNcm` / `setRenderMode` / `getGpuStatus` / `getDisplayInfo`），
所以可以直接当 `app/index.html` 使用，**不需要一并回滚 `main.js` / `preload.js`**。

代价是快照来自「单文件播放器」时期，**不认识**后来加入的：

- `bili.js` — B 站缓存提取
- `cover.js` — 新版封面解析
- `ncmdump.exe` — NCM 官方解密
- `mini.html` — 迷你悬浮窗
- 多歌手识别、媒体键自检、主题系统等

### 8.6 手工回滚

不想用脚本的话，两步即可：

```powershell
Copy-Item 'versions\Q1_preWave.html' 'app\index.html' -Force
.\scripts\build-portable.ps1
```

版本对照表、每版说明，以及一段**已被后续需求推翻的历史约束记录**
（2026-09-13 曾明令禁止横移 / `wavePhase` 行波）见 [../versions/README.md](../versions/README.md)。

## 9. 故障排查

| 现象 | 原因 | 解决 |
| --- | --- | --- |
| `找不到 app 目录` | 在错误的工作目录运行 | 用 `cd` 切到仓库根目录，或直接双击 `构建.bat` |
| `app 目录缺少必需文件` | 源码不完整 | 检查 `app/` 下是否有 `index.html` / `main.js` / `preload.js` / `mini.html` / `package.json` |
| 下载 Electron 失败 | 网络 / 镜像不可达 | 用 `-RuntimeDir` 指定本地已有的运行时，或挂代理后重试 |
| `无法清理旧安装目录` | 程序仍在运行 | 先关闭程序；安装脚本已尝试自动结束进程 |
| `同步校验失败` | 复制过程中被占用 | 关闭程序后重新构建 |
| 启动后白屏 | `resources/app` 不完整 | 重新运行构建脚本 |
| NCM 无法解密 | `ncmdump.exe` 缺失或被拦截 | 确认 `app/ncmdump.exe` 存在，并加入杀软白名单 |
| 提示脚本被禁止运行 | 执行策略限制 | 使用 `安装.bat` / `构建.bat`（已带 `-ExecutionPolicy Bypass`），或在管理员 PowerShell 中 `Set-ExecutionPolicy -Scope CurrentUser RemoteSigned` |
