# 快捷键

全部快捷键分三层：**媒体键**（系统级）、**全局备用组合键**（系统级）、**应用内快捷键**（窗口聚焦时）。

---

## 1. 媒体键（系统级）

即使窗口在后台、被最小化，甚至你正在玩全屏游戏（无边框模式），这些键都有效。

| 键名 | 典型触发方式 | 功能 |
| --- | --- | --- |
| `MediaPlayPause` | 键盘播放键、多数耳机单击 / 双击 | 播放 / 暂停 |
| `MediaNextTrack` | 耳机双击 / 三击、键盘下一曲 | 下一首 |
| `MediaPreviousTrack` | 耳机长按 / 三击 | 上一首 |
| `MediaStop` | 键盘停止键 | 暂停 |
| `MediaPlay` | 部分耳机 / 声卡驱动的独立播放键 | 播放 |
| `MediaPause` | 部分耳机 / 声卡驱动的独立暂停键 | 暂停 |

### 实现说明

媒体键同时通过两条通道接管：

1. **Chromium Media Session（SMTC）** — 系统媒体控制面板、部分蓝牙耳机走这条
2. **Electron `globalShortcut`（Win32 `RegisterHotKey`）** — 键盘与多数有线耳机线控走这条

> 渲染侧的接收端是 `app-rhine/src/player.ts` 里的 `handleMediaKey()`：
> 通道 2 由主进程 `mediaAction()` 通过 `'media-key'` 发过来（`desktop.on('media-key', …)`），
> 通道 1 用 `navigator.mediaSession.setActionHandler` 注册 play / pause / nexttrack / previoustrack。
> **两条都在渲染侧** —— 整合进莱茵终端时这一段曾经整个丢失（主进程照旧发、界面没人听，
> 表现为"耳机键毫无反应"），2.2.0 已补回。若媒体键没反应，先看设置面板的自检行，
> 再看这里是否还在。

因为部分耳机把「播放 / 暂停」发成独立的 `MediaPlay` 和 `MediaPause` 两个不同键
（而不是 `MediaPlayPause`），所以六个键全部注册。

### 事件防抖

耳机在单击时可能连发多次按键事件，导致「播放 → 暂停」互相抵消（表现为按了没反应）。
因此所有媒体键动作都经过 **300 ms 防抖**。

### 媒体键是独占资源

Windows 的媒体键同一时刻只能被**一个**程序注册。如果游戏或其它音乐软件先注册了，
本程序就拿不到。

打开设置面板 →「`HEADPHONE / MEDIA KEYS`」那一行看状态：

| 显示 | 含义 |
| --- | --- |
| `媒体键 ✓ 已接管` | 六个键全部注册成功 |
| `✕ 被占用` + `未拿到：…` | 有一部分被抢走，后面会把**具体键名**列出来 |
| `✓ 备用组合键可用` | 上面那套组合键可用（见 §2） |
| `最近一次：播放 / 暂停 · 来源 MediaPlayPause · 12:52:04` | **刚按下的那个键被系统认成了哪一个** |

程序每 **6 秒**会重试一次失败的键（成功的不重复注册），所以关掉冲突程序后会自动恢复。

## 1.5 有线耳机按键（这一节专门讲耳机）

有线耳机的按键**本身不是键盘按键** —— 它走的是系统的"消费者控制"通道，被 Windows 翻译成
媒体键再发给前台程序。所以支持耳机按键 = 把那些媒体键注册上 + 让用户能看出按的是哪一个。

### 三键线控的典型映射

| 耳机上的操作 | 系统发出 | 本程序的动作 |
| --- | --- | --- |
| 单击（中键） | `MediaPlayPause` | 播放 / 暂停 |
| 双击 | `MediaNextTrack` | 下一首 |
| 三击 | `MediaPreviousTrack` | 上一首 |
| 长按 | 多数固件直接走系统语音助手，本程序拿不到 | — |
| 音量键 | `VolumeUp` / `VolumeDown`（由系统接管，**本程序不抢**） | 系统音量 |

六个媒体键全部注册，覆盖各家固件差异：`MediaPlayPause`、`MediaNextTrack`、
`MediaPreviousTrack`、`MediaStop`（当暂停用）、`MediaPlay`、`MediaPause`。

### 怎么确认"我的耳机键被认成了什么"

1. 打开设置面板 → 看 `HEADPHONE / MEDIA KEYS` 那一行；
2. 按一下耳机上的键 → 那一行右侧会写：**动作 · 来源键名 · 时间**，例如

   ```
   下一首 · 来源 MediaNextTrack · 12:52:05
   ```

3. 如果按键**毫无反应**、那一行也不动，说明这个键：
   - 被别的程序（游戏、其它播放器）抢走了 → 看自检行里"未拿到"的键名，关掉冲突程序等 6 秒自动重试；
   - 或者它压根没走媒体键通道（少数耳机固件把长按/多功能键发成厂商私有指令）→ 用下面 §2 的备用组合键。

### 接听 / 挂断那颗键

有线耳机线控上那颗**接听键**（很多线控只有这一个多功能键）在 Windows 上通常就是被系统翻译成媒体键：

| 耳机上的操作 | 系统通常发出 | 本程序的动作 |
| --- | --- | --- |
| 接听键 单击 | `MediaPlayPause`（多数固件） | 播放 / 暂停（= 接听 / 挂断） |
| 接听键 长按 | `MediaStop`（部分固件） | 暂停 |
| 结束通话键 | `MediaStop` | 暂停 |

也就是说**多半本来就能用**（六个媒体键都注册了）。按下去如果没反应，最常见的原因不是我们没接，
而是那颗键被系统里别的程序截走了 —— 尤其是 **Windows 的「手机连接 / Phone Link」**、
通讯软件（微信 / QQ / Discord）或耳机自带软件：它们会把接听键当成"接电话"用。
按一下键如果弹出了那些程序的窗口、而 `HEADPHONE / MEDIA KEYS` 那行**不动**，就是这种情况。

**两个办法**：

1. 关掉/退出抢键的程序（手机连接最常抢），等 6 秒本程序自动重试拿到；
2. 或者用耳机配套软件把接听键**改绑成组合键** —— 为此专门留了两个语义明确的：

   | 耳机按键想做的事 | 建议绑成 |
   | --- | --- |
   | 接听（播放 / 继续） | `Ctrl` + `Alt` + `A` |
   | 挂断（暂停） | `Ctrl` + `Alt` + `H` |

> 这两个键与 §2 的其它组合键一样是**全局快捷键**：窗口在后台、游戏在跑也生效，
> 而且按下时设置面板那行会显示 `播放 / 暂停 · 来源 Ctrl+Alt+A（接听）`，一眼能确认绑对了。
> 本程序**不做键盘钩子（`WH_KEYBOARD_LL`）**去硬抢任何键 —— 带反作弊的游戏会把全局钩子判定为外挂，
> 风险远大于收益。所以厂商私有指令的按键无法接管，只能用上面的办法改绑。

### 耳机带"USB 声卡 / 配套软件"的情况

这类耳机（USB 声卡、可编程线控）的软件通常能把按键**映射成任意键盘组合**。
把耳机按键绑成下面这套即可，语义与耳机三键一一对应：

| 耳机按键想做的事 | 建议绑成 |
| --- | --- |
| 播放 / 暂停 | `Ctrl` + `Alt` + `Space` |
| 下一首 | `Ctrl` + `Alt` + `→` |
| 上一首 | `Ctrl` + `Alt` + `←` |
| 音量 + | `Ctrl` + `Alt` + `↑` |
| 音量 − | `Ctrl` + `Alt` + `↓` |

> 这套就是 §2 的备用组合键 —— 同一批键，既能在"媒体键被游戏占用"时当兜底，
> 也能直接给耳机软件当映射目标。**它们都是全局快捷键**，窗口在后台、游戏在跑也生效。

## 2. 全局备用组合键（系统级）

媒体键被占用时的替代方案，也是耳机软件最方便绑的一套（见 §1.5）。

| 快捷键 | 功能 |
| --- | --- |
| `Ctrl` + `Alt` + `Space` | 播放 / 暂停 |
| `Ctrl` + `Alt` + `→` | 下一首 |
| `Ctrl` + `Alt` + `←` | 上一首 |
| `Ctrl` + `Alt` + `↑` | 音量 +5% |
| `Ctrl` + `Alt` + `↓` | 音量 −5% |
| `Ctrl` + `Alt` + `A` | **接听**（播放 / 继续）—— 给耳机接听键改绑用 |
| `Ctrl` + `Alt` + `H` | **挂断**（暂停）—— 给耳机挂断键改绑用 |
| `Ctrl` + `Alt` + `P` | 播放 / 暂停（上一版方案的别名） |
| `Ctrl` + `Alt` + `N` | 下一首（别名） |
| `Ctrl` + `Alt` + `B` | 上一首（别名） |

### 迷你悬浮窗控制

在独占全屏或原始输入的游戏里，悬浮窗**收不到鼠标事件**（系统层面限制），
此时用这些键来操作。**注意方向键加了 `Shift`** —— 把 `Ctrl+Alt+←/→` 让给了耳机的
上一首 / 下一首（那是耳机软件最常绑的两个键）。

| 快捷键 | 功能 |
| --- | --- |
| `Ctrl` + `Alt` + `Shift` + `←` | 迷你窗左移 14 px |
| `Ctrl` + `Alt` + `Shift` + `→` | 迷你窗右移 14 px |
| `Ctrl` + `Alt` + `Shift` + `↑` | 迷你窗上移 14 px |
| `Ctrl` + `Alt` + `Shift` + `↓` | 迷你窗下移 14 px |
| `Ctrl` + `Alt` + `0` | 迷你窗放大（宽高各 +20 px） |
| `Ctrl` + `Alt` + `9` | 迷你窗缩小（宽高各 -20 px） |
| `Ctrl` + `Alt` + `L` | 锁定 / 解锁迷你窗（锁定后忽略指针事件，防误触） |

## 3. 应用内快捷键（窗口聚焦时）

分成两套，两套的按键**不一样** —— 主界面是音乐档案终端，旧版独立播放器界面只在
`app/ui` 构建产物缺失时作为兜底加载。

### 3.1 主界面：音乐档案终端

| 快捷键 | 功能 |
| --- | --- |
| `←` `→` | 切换档案分组（列） |
| `↑` `↓` | 前后翻档案（同一列内，可循环） |
| `Enter` | 档案阵列里：**打开档案并播放**（进详情 + 起播当前这一首）；已经在详情里：**播放 / 暂停这一首**。开屏阶段按 `Enter` 直接进系统 |
| `/` | 打开曲目检索（`TRACK INDEX`） |
| `Esc` | 按优先级：关弹窗 → 收起歌曲编辑面板 → 从详情回到档案阵列 |

设置面板里给出的就是这一行：`←` `→` 切列　`↑` `↓` 选档　`ENTER` 读取　`/` 检索　`ESC` 返回。

**什么算"正在打字"**：只有真的会吃字符的控件 —— 文本框、文本域、下拉框、可编辑区。
**进度条与音量条（`input[type=range]`）不算输入框**：拖过它们之后光标停在上面，
回车、方向键、`/` 依旧可用。

> 早先的判据是 `e.target instanceof HTMLInputElement`，把这两条滑杆也当成了输入框 ——
> 于是"拖过一次进度条之后，回车 / 方向键 / `/` 全部失灵"，就是用户反馈的"回车键有时候会失灵"。
> 同一批修复还让**详情层里的回车**有了明确含义（播放 / 暂停），此前在那里按回车是没有任何反应的。

### 3.1.1 鼠标：播放条与播放列表上的点击

| 点哪里 | 结果 |
| --- | --- |
| 播放条的**曲名 / 艺术家**那一块 | **打开这一首的档案**（只切画面与选中态，不改变播放状态） |
| 播放条的**其它位置**（频谱那一块等） | 回到档案阵列（在详情里想回去时最顺手的一下） |
| 播放条上的按钮（播放暂停 / 上一首 / 下一首 / 收藏 / 导入 / 列表…） | 各按钮自己的功能，**不会**被当成"打开档案"或"返回" |
| 进度条、音量条 | 拖拽调整，同上 |
| 弹窗开着时点播放条 | 先收掉弹窗（与"点一下先退出当前层"的直觉一致） |
| 播放列表里**点曲名那一行文字** | 播放这首 **并打开它的档案**（无视 `OPEN ARCHIVE ON PLAY` 偏好 —— 点名字就是要看档案） |
| 播放列表里点行内其它空白处 | 只播放（是否打开档案看 `OPEN ARCHIVE ON PLAY`） |
| 播放列表行的 `↳` / `♡` / `✕` | 下一首播放 / 收藏 / 移除 |

### 3.2 旧版独立播放器界面（兜底）

| 快捷键 | 功能 |
| --- | --- |
| `空格` | 播放 / 暂停 |
| `→` | 快进 5 秒 |
| `←` | 后退 5 秒 |
| `↑` | 音量 +5% |
| `↓` | 音量 -5% |
| `M` | 打开 / 关闭迷你悬浮窗 |
| `L` | 展开 / 收起播放列表面板 |
| `F` | 收藏 / 取消收藏当前歌曲 |
| `Esc` | 关闭歌曲编辑弹层 |
| `Enter` | 在歌曲编辑弹层中保存（光标在文本输入框时） |

这一套的判据是 `e.target.matches('input,textarea,select')`（见 `app/index.html` 的「快捷键」一节），
与终端的判据不同。

## 4. 快捷键失效排查

按顺序检查：

1. **设置面板 → 「媒体键」自检行**
   - `✓ 已注册` → 快捷键本身没问题，检查耳机 / 键盘固件或电量
   - `⚠` / `✕` → 有程序抢占了媒体键，关闭游戏 / 其它音乐软件，等 6 秒自动恢复
2. **游戏是否为独占全屏**
   - 独占全屏下窗口无法置顶、收不到鼠标事件，请改为「无边框窗口」
3. **是否被安全软件拦截**
   - 某些安全软件会阻止 `RegisterHotKey`，把本程序加入白名单
4. **`ncmdump.exe` 是否被杀软隔离**
   - 只影响 NCM 解密，不影响快捷键
