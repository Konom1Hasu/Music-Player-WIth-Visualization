# 发布与推送

> 这份文档只回答一件事：**把当前仓库推上去，让 GitHub Actions 自动出 Setup.exe 并挂到 Release。**
> 构建与安装的细节见 [构建与安装](构建与安装.md)，每个版本改了什么见 [更新日志](更新日志.md)。

---

## 0. 一页速览

```
① 把版本标签挪到当前提交        git tag -f v2.2.0 -m "2.2.0"
② 过一遍本机检查                node scripts\文档一致性验证.js
③ 双击推送                      .\推送.bat
④ 等着 CI 出包                  Actions → Release 工作流（约 3–8 分钟）
⑤ 从 Releases 下载 Setup.exe    双击装 → 按 §6 的清单走一遍
```

## 1. 当前状态快照

> 下面是写下这份文档时的实测值（`git` / 打包脚本的输出）。推送前重新跑一遍 §2 的命令即可刷新。

> 这份表里凡是"每提交一次就变"的项都写成**读数方式**，不写死数字（写死会立刻过期）——
> 推送前把那几条命令跑一遍就是最新的。

| 项 | 值 / 读数方式 |
| --- | --- |
| 版本（`app\package.json`） | `2.2.0`（CI 会校验 `标签 == v{version}`，不一致直接失败） |
| 分支 | `main` |
| 本地领先远端 | `git status -sb` 首行：`main...origin/main [ahead N]`；**推送成功后应变成 `[up to date]`** |
| 版本标签 | `v2.2.0`；`git rev-list --count 'v2.2.0^{commit}..HEAD'` 必须是 **0**（改完代码要 `git tag -f` 再推） |
| HEAD | `git log --oneline -1` 的第一行 |
| 本地安装包 | `dist\安装包\音乐播放器-Setup-2.2.0.exe`，94.4 MB，SHA256 `E09B886AA22089EB2B88F65C7301069954E37DC636D7B4466E8C511690A7083F`（写文档时实测） |
| 触发方式 | 推 `v*` 标签 → `.github\workflows\release.yml` 构建并上传 Release |
| 远端 | `https://github.com/Konom1Hasu/Music-Player-WIth-Visualization.git` |

**为什么要 `git tag -f`**：`v2.2.0` 是本地标签，这一轮改动反复迭代过，标签一度还停在旧提交上。
CI 在打好的标签上构建，**标签指哪儿，Release 里就是哪儿** —— 所以每次推送前先确认"标签到 HEAD 的距离 = 0"。

> ⚠ 核对标签时别踩这个坑：本项目用的是**带注释的标签**（`git cat-file -t v2.2.0` → `tag`），
> 所以 `git for-each-ref --format='%(objectname)'` 打印的是**标签对象自己的 SHA**，不是它指向的提交。
> 想看它指向哪个提交，用 `git rev-parse --short 'v2.2.0^{commit}'`。

## 3. 推送

### 3.1 先把标签挪到当前提交（推荐每次都做）

```powershell
git tag -f v2.2.0 -m "2.2.0"
git rev-parse --short 'v2.2.0^{commit}'                       # 期望：与下面的一致
git rev-parse --short HEAD
git rev-list --count 'v2.2.0^{commit}..HEAD'                  # 期望：0
```

### 3.2 推送（二选一）

```powershell
.\推送.bat                                  # 双击也行；内部就是下面那条
.\scripts\push-to-github.ps1                # 自动适配 TLS / 凭证受限的网络环境
```

脚本做四件事：探测通道（必要时启用 openssl + 本机 CA、或从凭据管理器取缓存凭证）→
`git push -u origin main` → `git push origin --tags` → 打印仓库地址与推了哪些标签。
它**不会**打印 token；所有 git 配置都用环境变量临时传入，不写进 `.git/config`。

> **常见提示**
>
> - 首次推送会弹 GitHub 登录窗口（Git Credential Manager）。GitHub 已取消密码认证，
>   若要手填凭证请用 Personal Access Token（勾 `repo`）或改用 SSH。
> - 直连失败多半是加速器：装了 Steam++ / Watt Toolkit 就让它开着（它接管 github.com 的解析），
>   或反过来关掉它对 GitHub 的加速。先单独探一次通道：`.\scripts\push-to-github.ps1 -Check`。
> - 远端有本地没有的提交 → 加 `-Pull`：`.\scripts\push-to-github.ps1 -Pull`。

### 3.3 标签被拒时（只有这一种情况需要强推）

如果远端已经存在一个**指向别处**的 `v2.2.0`（早先推过一次版），`--tags` 会对这一个标签报
`rejected (already exists)` —— 代码仍然推成功了，只需补一刀：

```powershell
git push origin --force v2.2.0     # 只强制这一个标签
```

## 4. 推上去之后 CI 会做什么

`.github\workflows\release.yml`（`windows-latest`，timeout 60 分钟，实际约 3–8 分钟）：

```
取源码 → 装 Node 20（缓存 app-rhine/package-lock.json）→ npm ci
      → 校验 标签 == v{package.json.version}（不一致直接失败）
      → node scripts\文档一致性验证.js
      → 数据管控验证 / 设置持久化验证 / ID3编码验证
      → choco install innosetup
      → .\scripts\build-installer.ps1          （便携版 + Setup.exe，与本地同一条路）
      → 上报产物名与 SHA256
      → upload-artifact：音乐播放器-Setup-2.2.0
      → gh release create/upload：挂到 v2.2.0 Release
```

- **在哪看**：仓库 → Actions → `Release`；失败的那一步日志里会直接写原因（版本不一致 / 检查红 / 编译错）。
- **Release 说明是自动生成的**：只写"下载双击安装 + 按用户安装 + 卸载不删曲库 + 便携版替代 + 版本与 SHA256"，
  不重复更新日志。想让人看到这一版改了什么，就在 Release 出来后手动补一段（可用 §7 的草稿）。
- **不想发版只想测构建**：Actions → Release → `Run workflow`（`workflow_dispatch`），产物只进 Actions artifact，不动 Release。

## 5. 推送后核对（5 分钟）

1. Actions 里 `Release` 工作流是绿的，且 `gh release upload` 那一步成功；
2. Releases 页面上 `v2.2.0` 有附件 `音乐播放器-Setup-2.2.0.exe`，SHA256 与 §1 表里的对比
   （CI 与本地各打一次，**哈希不会相同** —— 只核对页面显示的那行与本地文件一致）；
3. 下载 → 双击 → 安装向导走一遍（勾/不勾桌面快捷方式都试一次）→ 开始菜单能启动；
4. 卸载：目录、开始菜单项、桌面快捷方式都清掉，**曲库与设置保留**（装回来还在）。

这些在无头 Edge 里判不了或判不准，装完请逐条看一眼：

| 项 | 怎么看 |
| --- | --- |
| 双击档案卡片 = 打开并播放 | 在阵列上双击一张卡片：应当进详情且立刻出声（射线命中在无头里读不准） |

| `POWERED BY RHINE LAB` 不被遮挡 | 进详情 / 打开播放列表 / 全屏，看右下角那行是否始终可见（已抬到 `z-index: 12`） |

| 开屏配色（深色主题） | 深色主题下开屏仍是浅底深字（不跟随主题），界面本体是深色 |
| 播放条图标 | 9 个按钮都应是裸图形（无方框无底色），悬停只变色 |
| 媒体键 | 耳机/键盘的播放暂停、上一首、下一首应生效（主进程注册 + 渲染侧监听都已补回） |
| 一键重读封面 | 设置 → `RE-READ ALL COVERS`：跑完提示"更新 N 首"，列表里的封面应刷新 |
| B 站缓存导入 | 选一个缓存文件夹 → 列表出现曲目 → 点播放应出声（会话副本 + blob 两条路） |
| 重复歌曲 | 同一个文件夹再导一次：应当提示"跳过重复 N 首"，列表条数不变 |

## 7. 出问题怎么办

| 情况 | 处理 |
| --- | --- |
| 标签被远端拒（`already exists`） | `git push origin --force v2.2.0`（见 §3.3） |
| CI 在"标签与版本一致"那步失败 | 标签与 `app\package.json` 对不上：要么 `git tag -f` 挪标签，要么按 [维护指南](维护指南.md) 升版本 |
| CI 在文档检查那步失败 | 本地 `node scripts\文档一致性验证.js` 复现，按提示修（多数是 README 结构图没加新文件） |
| CI 构建失败但本地能打 | 看那一步日志；本地兜底：`.\打包安装包.bat` 出的 Setup.exe 可以直接手动拖进 Release |
| 发完发现要改 | 改完 `git tag -f v2.2.0` → 推标签 → CI 会 `--clobber` 覆盖 Release 上的同名附件 |
| 想整版撤回 | Releases 页面删掉该 Release（标签可留可删：`git push origin :refs/tags/v2.2.0`） |

## 8. 本次（2.2.0）改动摘要 —— 可直接粘到 Release 说明

> 面向用户的说法，技术细节见 [更新日志 §2.2.0](更新日志.md)。

**装法**：下载 `音乐播放器-Setup-2.2.0.exe`，双击 → 下一步 → 勾/不勾"创建桌面快捷方式" → 完成。

**播放器**

- 导入的 B 站缓存现在能正常播放（补回"可播放副本 + 读字节转 blob"两条路）
