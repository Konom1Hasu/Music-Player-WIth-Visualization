### 安装：改成「CI 出安装包 + 下载双击安装」

**★ 自动构建与发布（`.github\workflows\release.yml`）**

推一个 `v*` 标签就自动出安装包并挂到 Release 上：

```
打标签 → 校验标签与 app\package.json 的版本号一致
       → 文档一致性 + 三套离线回归验证（数据管控 / 设置持久化 / ID3）
       → choco install innosetup
       → build-portable.ps1 + build-installer.ps1 → 便携版 + 单个 Setup.exe
       → gh release create / upload
       → 用户下载 音乐播放器-Setup-x.y.z.exe，双击安装
```

也可以手动 `workflow_dispatch` 触发：只出 Actions artifact，不动 Release。
CI 与本地共用同一套打包逻辑（还是那两个 .ps1），不另起一套。

**★ 一键安装包（`installer\music-player.iss` + `scripts\build-installer.ps1`）**

用 Inno Setup 6 把便携目录包成单个 Setup.exe。用户拿到的体验就是一句话：
**下载 → 双击 → 下一步 → 勾/不勾"创建桌面快捷方式" → 安装 → 完成**。

向导刻意做短（每一步都为了少点一次鼠标）：

| 页面 | 有没有 | 说明 |
| --- | --- | --- |
| 欢迎 | 有 | 一行说清"按用户安装、不需要管理员" |
| 许可 | **没有** | MIT 声明改为随程序装进 `resources\app\LICENSE.txt`，不必让用户多点一次"我接受" |
| 选择目录 | 有 | 默认 `%LOCALAPPDATA%\Programs\音乐播放器`，想换可以换 |
| 开始菜单组 | **没有** | `DisableProgramGroupPage=yes` |
| 附加任务 | 有 | **桌面快捷方式默认勾选、可以取消**（`[Tasks] desktopicon`，`[Icons]` 里只有勾了才创建） |
| 准备安装 | **没有** | `DisableReadyPage=yes`：设置页上直接就是"安装"按钮 |
| 完成 | 有 | 可以勾"立即运行" |

其余行为：

- **按用户安装**（`PrivilegesRequired=lowest` + `{localappdata}\Programs`）：双击即可，不弹 UAC
- **AppId 固定**：新版本认成升级、覆盖到原目录，不会并存两份
- **卸载不删用户数据**：`%APPDATA%\music-player` 里是曲库，删了就找不回来
- 刻意不写 `ArchitecturesAllowed` / `ArchitecturesInstallIn64BitMode`：
  这两个指令的取值在 Inno 6.3 前后不一样（`x64` → `x64compatible`），
  写死任何一个都会让"另一版本"的 ISCC 报 Unknown architecture；
  本程序是纯文件树、装到 `{localappdata}`，用不到 64 位安装模式
- 向导文案 = 英文 `Default.isl` + 覆盖用户真正会读到的那些消息
  （Inno 官方发行版不带简体中文语言文件，中文是社区翻译）
- 图标由构建脚本按"文件在不在"传 `/DHasIcon`，`.iss` 里只做 `#ifdef` ——
  不依赖 ISPP 的路径变量，任何 6.x 都能编译
- **MIT 声明随分发件走**：`build-portable.ps1` 现在把仓库 `LICENSE` 复制成
  `resources\app\LICENSE.txt`（MIT 要求分发时随附声明；既然去掉了许可页，声明就必须落在
  用户装完能看到的目录里）
- ⚠ `.iss` 与 `scripts\*.ps1` 都必须存成 **UTF-8 带 BOM**：
  Inno 与 PowerShell 5.1 在没有 BOM 时会按本地代码页读，中文直接变乱码。
  这一轮踩了两次 —— 先是编辑 `build-portable.ps1` / `install.ps1` 时把 BOM 弄丢，
  后是自己写的临时演练脚本忘了加 BOM，两次都是"字符串没有结束符"。
  文档检查的第 [9] 项本来就在盯 `scripts\` 下的这个，但**临时脚本不在它的范围内**。

**★ 安装步骤从"两步"变成"一步"**

- `安装.bat` 默认带 `-Launch`：双击 → 构建（需要时）→ 安装 → 快捷方式 → **直接打开播放器**；
  成功时窗口自动关掉。原来装完会停在"按回车键退出"，而且要自己去点快捷方式。
- `install.ps1` 新增 `-NoLaunch`；想"装完不启动"就加它
- `build-portable.ps1` 不再因为 `app-rhine\node_modules` 不存在而直接抛错：
  没有 Node 依赖时跳过界面重建、沿用 `app\ui` 里已有的产物并提示一行 ——
  **只想装上用的人不必先装 Node + npm install**（连产物都没有才算错误）
- 新增根目录 `打包安装包.bat`：双击即打 Setup.exe

### 修复

**★ 换歌时，左边的档案阵列不跟着动（没有切换档案的动画）**

终端把音乐库映射成档案阵列之后，**只有"用户自己点/按键选档"才会驱动三维阵列**：
`scene.select()` 只在 `select()`、`start()`、`replayBootAfterModal()` 三处被调用。
换歌走的是 `rhine-track` 事件，那条路上只刷了刻度（`#file-ticks`）、滚动文字与详情区，
**从没通知过三维场景** —— 于是"下一首"、"点播放列表里的一行"之后，卡片原地不动，
既没有抬起新卡片，也没有归位旧卡片与那道波浪。

- 新增 `focusArchive(index)`：刻度、文字、**`scene.select(selected)`** 一起走；
  `rhine-track`（换歌）与 `rhine-open-track`（起播开档案）共用它
- 不传方向时 `selectionCell()` 取"最近的那一份"，也就是从当前这张到目标那张的最短一条路

**★ 播放列表删除之后那一行不消失**

`app-rhine/src/player.ts` 的 `notify()` 只通知"档案数据变了"（终端据此重排阵列），
**没有重画播放器自己的界面** —— 播放列表只在 `renderNow()` 里重建，而删除走的是 `notify()`。
于是点完 `✕`：库里那条已经删了，列表里那一行还在，而且行号 `data-i` 与曲库错位
（点这一行会播到别的歌）。往已有曲库里导入新歌也是同一个毛病（列表当场不多出那几行）。

- `notify()` 末尾补 `renderNow()`；`listSignature()` 补上标题 / 艺术家 / 专辑，
  改过曲目信息的行也会跟着更新
- `removeSong()` 顺手把「下一首播放」队列里那一首的 id 清掉（否则队列计数永远多算一个）

**★ 「记住播放进度」关掉之后仍然在记录**

`rememberPos()` 这道闸只加在**读**的一侧（`loadSongAudio()`），六个**写**路径一个都没过闸：
`selectSong()` / `timeupdate` / `pause` / `savePosition()` / `savePlayhead()` / `restorePlayhead()`。
表现就是关了之后曲目里的 `pos`、IndexedDB、localStorage 播放头照旧每 4 秒写一次，
下次启动照样"接着上次听"。而且这个开关当时**并没有出现在设置面板里**（`setPlaybackPref()` 是死代码）。

- 六个写路径全部过闸；`savePlayhead()` 在关闭状态下顺手清掉已存的播放头
- `restorePlayhead()` 要求 `rememberPos && resumeLast` 都为真才恢复
- `applyLibrary()` 读了库之后再看偏好：关着就把读回来的旧进度在内存里清零 ——
  否则那些旧值会跟着后面任何一次 `persist()`（点歌 / 收藏 / 改信息）原样写回库，
  再进一次"怎么还有进度"的错觉（只清内存，不额外写库）
- 系统设置里补上「播放行为」三项（见下）

**★ 起播没有打开这首歌的档案**

`openOnPlay` 只有定义与默认值，**没有任何调用点**。

- 新增 `followWithArchive()`：起播后派发 `rhine-open-track`，终端收到即进该曲目的详情
- 两个入口一致：在播放列表里点一行、在档案上点播放，结果都是"档案被打开"
- 打开档案前先收起播放列表抽屉（它是 880×560 的浮层，正好压住左侧三维阵列）

**★ 回车键有时候失灵**

两处叠加：

1. 「正在打字」的判据是 `e.target instanceof HTMLInputElement`，
   **进度条与音量条（`input[type=range]`）也被当成在打字**：拖过一次进度条之后焦点停在它上面，
   之后回车 / 方向键 / `/` 整轮失效；
2. 回车的触发条件是一份白名单（body / 详情面板 / 上一首下一首 / 档案刻度），
   焦点一在别处就没有任何反应；而且**在详情层里回车什么都不做**。

- 新增 `isTypingTarget()`：只有真的会吃字符的控件（文本框 / 文本域 / 下拉框 / 可编辑区）才算打字
- 回车改为"当前这一层的主操作"：开屏 → 进系统；档案阵列 → 读取档案；**详情 → 播放 / 暂停**
  （档案栏底下那行提示也从「ENTER 播放」改成「ENTER 读取」，与详情层的行为对齐；
  阵列那一层仍然只读不自动播放，维持 1.3.0 的决定）
- 焦点在别的按钮 / 链接上时，回车仍交给浏览器原生 click（播放条 `☰` / `▶`、返回键保持各自原意）

**★ 先点列表播放、再点其他档案切换失灵**

三处叠加：

1. 播放列表抽屉（left 59 / bottom 238 / 880×560）整块压在左侧三维档案阵列上，
   一直开着时点在阵列卡片上的那一下会被它吃掉；
2. `playAt()` 对"就是当前这首"直接 `return`，**不派发 `rhine-track`** ——
   先在列表里点歌、再去点别的档案把选中态挪走之后，再点回列表里这一首就切不回去了；
3. `app-rhine/src/scene.ts` 的 `pointerup` 带一句 `this.detail > 0.2` 就 `return`，
   详情展开时画布上的点击整轮被挡掉（而终端 `select()` 本来就写了"详情里选中 → 退回阵列"）。

- 列表点外面、以及档案要打开时，都收起抽屉
- `playAt()` 的早退分支补派发 `rhine-track`
- `scene.ts` 详情期间只忽略"点正在特写的那一张"，点别的档案改为正常切过去。
  比较的是**曲目序号**，不是阵列槽位（`fileAtCell` / `fileAtSlot` 返回的是序号，
  `selectedSlot` 是 `lane*32+row`）—— 两者混用会让"点特写那张"被误判成"点了别的档案"

**★ 弹窗收尾只挂在动画回调上，可能永远收不了尾**

`app-rhine/src/ui-transitions.ts` 里 `SurfaceTransition` 的收尾只挂在退场动画的 `finished` 上；
动画被 `dispose()` 顶掉、被下一次 `run()` 抢占、或者动画时间轴停住时（后台 / 被遮挡 / 无头环境），
`finished` 不落定 → `closeModal()` 传进去的回调永不执行 → `modalClosing` 永远停在 `true`。
后果不是"弹窗关不掉"这么轻：`keydown` 里那句 `if (modalClosing) return;` 会把**所有按键**
整轮吞掉，弹窗节点也一直留着把整机 `inert` 住 —— 键盘与档案阵列点击全部失效，只能重开程序。

- `SurfaceTransition` 按动画时长补一条兜底计时器（`complete()` 自身按 revision 判重，重复调用安全）
- `closeModal()` 与新增的 `finishModalClose()` 幂等收尾，并把"关完要做什么"存起来统一执行

### 新增：系统设置 → 播放行为

| 开关 | 默认 | 说明 |
| --- | --- | --- |
| REMEMBER PLAYBACK POSITION | 开 | 记住每首歌的播放进度；关掉后**不写任何进度**，启动也从零开始 |
| RESUME LAST TRACK | 开 | 启动时把播放条恢复到上次在听的那一首与位置 |
| OPEN ARCHIVE ON PLAY | 开 | 起播时自动打开这首歌的档案详情 |

三项都存在 `localStorage` 的 `rhine-play-prefs`。关掉「记住进度」时会顺手清掉已经存下来的进度
（每首曲目的 `pos`、IndexedDB、`rhine-playhead`）并作废正在等待的续播点。

### 修复：批处理里有中文，导致双击后被 cmd 拆成垃圾命令

`打包安装包.bat` 的注释里写了两个中文路径（`dist\安装包\…`）。cmd.exe 是**按字节偏移**
重读批处理的，一旦读指针落在多字节字符中间就整行错位，后面的行会被当成新命令执行。
用户实际看到的就是：

```
'Needs' 不是内部或外部命令      ← 注释行 "rem  Needs Inno Setup 6 …" 被截断
'wershell' 不是内部或外部命令   ← "powershell" 少了一半
'm' / 'rshell' / 'rorlevel' / 'ho' / 'em' / 'characters' / 'cal' … 一堆碎片
'"D:\harness work\音乐播放器\"' 不是内部或外部命令   ← %~dp0 那行被拆开
```

更糟的是碎片里正好拼出了 `winget install -e --id JRSoftware.InnoSetup`，**被真的执行了一次**。

修复与防复发：

- `打包安装包.bat` 改成**纯 ASCII**（中文只放在它调用的 `.ps1` 里 ——
  `安装.bat` / `构建.bat` / `推送.bat` 本来就是这么做的，注释里也写着这条规矩，是我没守）
- `scripts\文档一致性验证.js` 新增第 **[10] 项**：仓库根目录与 `scripts\` 下的
  `.bat` / `.cmd` 不得含任何非 ASCII 字节（原来是"靠人记住"，现在会挡住）

### 安装包动作的离线演练（编译前的第一层核对）

`.iss` 编译通过之前，还做过一层"动作演练"：把它声明的那套动作在**同形状的中文路径**上真跑一遍 ——
装到 `%LOCALAPPDATA%\Programs\音乐播放器-演练`，按 `[Icons]` 建三个快捷方式
（开始菜单程序 / 开始菜单卸载 / 桌面），再读回快捷方式核对 `TargetPath`、`WorkingDirectory`、
`IconLocation`，最后清理。结果：58 个文件一致、关键文件齐全（含 `resources\app\LICENSE.txt`
与界面产物）、快捷方式三项属性都对。演练只写演练目录与临时目录，没碰真实桌面与已安装的副本。

## [2.1.0] — 2025

**主题：** 频谱参数**整体退回 1.3.0 原值**（2.0.0 的去毛刺整轮撤回）、回车只读档案不自动播放、
播放条启动即显示上次那首与上次进度；并补上一件能离线量频谱的观测工具。

### 可视化

**★ 参数完全照 1.3.0（用户明确要求）**

用户拿到 2.0.0 后的原话是"可视化的效果，参数设置请完全参照 1.3.0 版本的播放器"。
2.0.0 曾按"毛刺感太严重"做过一轮去毛刺，这一版**整轮撤回**，逐项回到 1.3.0 的原值：

| 参数 | 2.0.0（已撤） | 2.1.0 = 1.3.0 |
| --- | --- | --- |
| 分析窗 `ANALYSIS_WINDOW` | 512 | **1024** |
| 抖动形式 | 逐柱慢速随机（`JITTER_SLIDE`） | **正弦行波**（相位每拍 +`JITTER_STEP`） |
| 抖动幅度 `JITTER_AMP` | 0.16 | **0.45 × K** |
| 空间频率 `JITTER_FREQ` | — | **0.1 + 0.2·(K−0.4)** |
| 相位步进 `JITTER_STEP` | — | **0.03 × K** |
| 单边颤动 `JITTER_WOBBLE` | 0.022 | **0.055 × K** |
| 量化前平滑 | `[1,2,1]` 横向平滑 + 预留一级余量 | **无平滑**，直接量化 |
| 渲染插值 | `render()` 里再做一次一阶逼近 | **不插值**，直接重画 `bars` |
| Goertzel 归一化 | `/(n/4)` | `/(n/4)`（不变） |
| 倾斜 / 泵动 / 幂次 / 跟随 | 55 / 0.40 / 2.1 / 0.7−0.2·(i/n) | 同（不变） |

保留的只有**架构**，它与观感无关：Goertzel 仍在 Web Worker 里按 30Hz 算（与 1.3.0 的分析
节拍一致），主线程按 60fps 把同一份 `bars` 重画。`Spectrum.render()` 不再介入数值，
所以屏幕上的阶梯感与行波抖动与 1.3.0 一致，只是合成次数更多、滚动缩放更顺。

`app-rhine/src/spectrum.ts` 里那句"与 1.3.0 的两处有意差异"的注释也一并改掉了 ——
留着会误导下一个人再去做一次已经撤回的"优化"。

### 修复

**★ 回车只读取档案，不自动播放**

`openFile()`（回车 / 点击档案）原先会顺手 `playAt()`。现在这一路只做 `setMode("detail")`：
起播交给用户 —— 播放键、播放列表里点一行、空格。档案阵列的"读取"与"播放"从此是两件事。

**★ 播放条在启动后显示上次的曲目与进度**

新增 `localStorage["rhine-playhead"] = {id, pos}`：每次 `timeupdate` 覆盖写一份（量很小），
`applyLibrary()` 时由 `restorePlayhead()` 恢复成播放条上的曲目、时间与进度条位置，
并挂一枚 `.p-now .p-resume` 提示（`上次听到这里 · 按播放继续`，一按播放就撤掉）。
这样"关窗即丢进度"的观感没有了 —— 即便被强杀，下次启动播放条也是上次那一刻的样子。

**★ 启动时的一次崩溃**

`restorePlayhead()` 会派发 `rhine-track`，而这一路可能在 `records` 还是空数组时到达，
读取 `records[index].title` 直接抛 `TypeError`。现在该监听器先判 `records[index]` 存在。

### 工具

**★ 新增 `scripts\频谱离线观测.mjs`**

无头浏览器里 `requestAnimationFrame` 在虚拟时间下会停摆、媒体也解不出码，
**页内探针测不到柱高**。这个脚本把"合成信号 → Spectrum 流水线"整段搬进 Node：


**IndexedDB 首次打开要多久取决于库大小与磁盘**（本机实测 1.2–8.5 秒，450 首的库更久）。
只要超过 1.5 秒，这一整轮就当空库启动 —— `songs` 是空的，于是：

- 曲目全部不显示（只剩"导入音乐"占位档案）
- 每首歌的 `pos`（上次停在哪）读不回来 → **点歌当然只能从头放**
- 收藏、播放次数一并丢失

现在读库**不挡启动**，并且兜底从 1.5 秒提到 8 秒、只在"真的一条都没回来"时才生效：

```ts
buildUI();
syncRecords();                       // 先按空库把界面立起来（占位档案）
void loadLibrary().then(applyLibrary); // 读回来再刷档案阵列 / 刻度 / 播放列表 / 详情面板
```

**★ 续播落点加两层保护**

- `timeupdate` 里**每 4 秒**兜底落一次位置（崩溃 / 强杀不再丢进度）
- 新增 `playing` 兜底：个别容器在 `loadedmetadata` 阶段还寻址不了，
  这时 `currentTime` 赋值会被丢掉，于是播起来之后再补一次
- "离曲尾太近就从头放"的判据改成 `max(5 秒, 曲长的 4%)`

**★ 播放列表不再每次重建**

`renderNow()` 在播放 / 暂停 / 收藏 / 切歌 / 载入曲库时都会被调用，而它每次都重写整个列表的
`innerHTML`（450 首就是 450 行 DOM 重建）。现在按签名（曲目数 + 当前曲目 + 队列 + 收藏）
判断，内容真的变了才重建 —— 播放 / 暂停不再触发一次整表重排。

### 可视化

**去毛刺**：用户反馈"毛刺感太严重"。毛刺来自三处叠加，逐条收掉：

| 项 | 之前（1.3.0 原样） | 现在 | 为什么 |
| --- | --- | --- | --- |
| 抖动 | 相位每帧 `+0.03` 的正弦**行波**，幅度 0.45 | 逐柱**慢速随机**（滑动系数 0.5），幅度 0.16 | 行波会在柱面上留下横向爬行的毛边 |
| 量化前 | 无平滑 | **[1,2,1] 横向平滑**（权重 0.26） | 相邻柱之间一格一格的锯齿被抹平，14 级阶梯反而更干净 |
| 单边颤动 | 0.055 | 0.022 | 满高条顶端不需要那么大的抖 |
| 画布超采样 | 1.5×（954×716） | 1.25×（795×596） | 填充量再降 30%，边缘也更锐 |

低频那只"细针"、鼓点泵动、14 级阶梯感都保留。

**帧率**：渲染节拍从"整帧 33ms"改成**播放中 60fps、暂停后 15fps**：

```ts
const budget = VIZ_TEST || !audio.paused ? 15 : 64;   // 之前是无条件 33
```

分析节拍仍是 30Hz（worker 每 33ms 一帧，足够跟上鼓点），**worker 两次回包之间的帧靠
`Spectrum.render(dt)` 把显示值一阶逼近目标值**（`1−e^(−dt/55ms)`）——
所以柱高是连续滑动的，而不是每 33ms 跳一格。Goertzel 的算力一分没涨，
分析窗长还从 1024 降到 512（乘加量减半），时域缓冲改成两侧轮流用靠 transfer 归还，每帧不产生垃圾。

循环也不再"暂停即停"：停掉会让画面僵在最后一帧，现在降到 15fps 继续画收起动画。

1. **点一首以前听过的歌 → 看进度条是否停在它上次的位置**（不再是 0:00）
2. **看频谱柱形**：应该比 1.4.7 明显干净 —— 柱身不再有横向爬行的毛边、

### 已知限制

- 无头浏览器 + 虚拟时间下媒体元素 `readyState` 恒为 0（音频解不出来），
  因此"点击后续播的实际播放位置"无法在本机自动化里断言，只能自动化核对

## [1.4.6] — 2025

**主题：** 频谱计算搬进 Web Worker（修"可视化帧率很低"）、进度只为"下次续上"而存、补回音量 / 倍速 / 拖拽导入。

### 修复

**★ 可视化帧率很低**

1.4.4 把 1.3.0 的自研频谱搬过来时，我省掉了它的 Web Worker（当时判断"120 段 × 1024 点

## [1.4.4] — 2025

**主题：** 频谱换成 1.3.0 版独立播放器那套自研分析器（原样搬过来，不是"看着像"）。

### 变更

之前终端里的频谱是"`AnalyserNode.getByteFrequencyData` → 对数分频 → 画柱"。
用户连着反馈"没实现 1.2.0 / 1.3.0 版本的效果"，于是把那版**真正**搬过来 ——
在终端详情区画布上跑 1.3.0 的同一条流水线（新增 `app-rhine/src/spectrum.ts`）：

| 环节 | 1.3.0 的做法（现已照搬） |
| --- | --- |
| 分析 | `SPECTRUM_N = 1024` 时域窗 + Hann 加窗 + **Goertzel** 逐带计算（120 个对数频段，42Hz–16kHz） |
| 归一 | 每帧按本帧峰值归一后做**对数压缩** `log10(1+100·min(1,m/mx))/log10(101)` |
| 频段增益 | 手工调的 `bandBoost` 曲线：**宽丘 + 细针**的左峰（细针对准低频峰所在柱的中心）、中高频人声尖峰、中频谷，钳在 0.58–2.9 |
| 倾斜 | `pow(5, tilt·(1−i/n))`，tilt 由"频谱平衡 55"换算 |
| 幂次 | `pow(min(1,v), 2.1)` 拉大高低差 |
| 鼓点 | 用**未归一化**的低频原始幅度做 onset（`(rise−0.08)×2.2`，参考电平 0.05 慢跟随），再以**乘法泵动**作用在低频窗上 —— 加法会把十几根一起顶过 1.0，量化后变成平直方块 |
| 抖动 | 三条量（幅度/空间频率/单边颤动）随"抖动 1.00"缩放，向上幅度按**剩余余量**缩放，避免峰心两侧被一起钳住而失去针形 |
| 量化 | **14 级**阶梯（观感里的"台阶") |
| 平滑 | 一阶跟随，上行系数 0.70→0.50、下行 0.58→0.80（随频率放缓） |
| 峰值线 | `peaks[i] = max(peaks[i]·0.97, bars[i])`，画 2px |
| 样式 | 五种：融合 / 音色 / 条形 / 圆环 / 波形（默认融合）；配色仍取终端自己的令牌 |

**有意的差异**（都记在 `spectrum.ts` 的头部注释里）：

- **不用 Web Worker**：面板是 30fps 重绘，120 段 × 1024 点 ≈ 12 万次乘加/帧（约 370 万次/秒）主线程吃得下，
  省掉 worker + 看门狗回退的复杂度
- **滑块固定成 1.3.0 的默认值**（倾斜 55、鼓点 0.40、抖动 1.00、峰宽 σ 0.048、左峰目标增益 1.05）
- 配色取终端令牌（`#c9a878 → #9b7247 → #252820`，夜态另有一套），版式与动效参数与源版本一致

### 新增

- **`?viztest=1`**：不播音乐、用合成信号（55Hz 低音 + 每 4 秒一次"鼓点" + 440Hz / 2.4kHz）跑频谱，
  并把频谱实例挂到 `window.__spectrum`，用于无音频环境下的自动化核对
- **`scripts\生成频谱探针.ps1`**：在构建产物 `index.html` 里注入"预置一首带封面的曲目 + 回传柱高"的脚本，
  生成探针页（必须在 `npm run build` 之后跑，Vite 会清空 dist）

### 验证

探针在真实应用里读回 120 根柱的实测值：

```
bars = 120
min/max/mean = 0.000 / 0.537 / 0.052
顶到 0.98 以上的柱数 = 0
前 12 根 = 0.37 0.54 0.42 0.20 0.20 0.42 0.48 0.31 0.20 0.36 0.47 0.31
```

三条结论都在这几个数里：**没有一根被钳在满格**（对照 1.4.2 之前"整排顶满"）、
左区相邻柱高低穿插（0.54 / 0.20 / 0.42 相隔出现，正是"抖动"那一层在起作用）、
满高与谷底之间有完整的动态范围。

**顺带修掉一个真 bug**：时域缓冲原先只在 `ensureAnalyser()` 里分配，于是
**没有音频上下文时整条频谱恒为 0**（探针第一次跑出来全是 `0.00`，就是这个原因）。
现在缓冲由渲染循环自己保证，与音频上下文解耦。

以及封面方块区域的平均色 —— 用来证明"画布上真的画上了封面"，而不只是"代码跑过了"。

### 修复

**★ 可视化一直顶满**

根因是自动增益的写法：`gain = 1 / normRef`，而 `normRef` 跟着最近峰值走 ——
等于**每帧都把最响的那根柱拉到满格**；再叠加当时 1.85 的鼓点泵浦与到 1.32 的低频倾斜，
大量柱体被 `Math.min(1, …)` 直接夹在顶端，于是整排长时间贴着上沿。

现在的取值链：

| 环节 | 之前 | 现在 |
| --- | --- | --- |
| 分析器 dB 窗口 | 默认 −100…−30dBFS（对音乐太宽） | **−85…−25dB**（60dB 窗口，安静段也铺得开） |
| 曲线 | `(peak/255)^0.8` | `(peak/255)^1.05`（更贴真实动态） |
| 自动增益 | `1/normRef`，无上限 | `min(1.5, max(1, 0.78/normRef))`：正常音量**恒为 1**，只有整体很轻才抬一点 |
| 鼓点泵浦 | 上限 1.85、命中 +0.32 | 上限 **1.32**、命中 +0.2 |
| 低频倾斜 | 0.70 → 1.32 | **0.88 → 1.18** |
| 低频尖峰 | +45% | **+20%** |
| 显示上限 | `min(1, …)` | `min(0.97, …)`（满格留一点余量） |

以"大多数频段落在 120–200、峰值 200"的常见响度算：旧写法 gain≈1.2，泵浦一响
`0.87 × 1.85 ≈ 1.6` 直接夹满；新写法 gain=1，主频段落在 0.48–0.90，
只有底鼓那一瞬的泵浦会短暂顶到 0.97。

## [1.3.1] — 2025

**主题：** 修掉"开了封面 3D 但什么都看不到"的真 bug，并给项目装上**能自己看界面**的验证工具。

### 修复

**★ 封面 3D 的绘图缓冲被设成 1×1，导致一帧都画不出来**

用户反馈"我并没有看到 3D 效果"。这一次没有靠猜 —— 我搭了一个离线桩环境把
`app/index.html` 在无头浏览器里渲染出来，dump DOM 后读到了确凿证据：

```
<canvas id="cover3d" width="1" height="1" class="on">     ← 绘图缓冲只有 1×1 像素
<canvas id="viz"      width="600" height="312">           ← 对比：可视化画布正常
```

根因是 `c3dEnable()` 里的**调用顺序**：

```
c3dResize();                     ← 此刻 #cover3d 还是 display:none
cv.classList.add('on');          ← 之后才显示
```

`display:none` 时 `clientWidth`/`getBoundingClientRect()` 都是 **0**，
而原代码写的是 `cv.clientWidth || 1`，于是取到 1 →
`setSize(1,1)`、`camera.aspect = 0/1 = 0` → 渲染到 1×1 缓冲，屏幕上什么都不会出现。
只有手动缩放窗口（触发 resize 监听）才会突然冒出来。

修复三步：

1. **先显示、后测量** —— 把 `cv.classList.add('on')` 提到 `c3dResize()` 之前
2. `c3dResize()` 改用 `getBoundingClientRect()`，量到 0 时**用父容器兜底**
3. 仍为 0 就返回 false，调用方**下一帧重试**（最多两次）

验证（同一桩环境、同样参数，只看画布属性）：
```

修复后: width="410" height="301"
```
并用 ASCII 渲染确认封面区从"均匀暗块"变成了有明暗层次的三维物体。

### 新增

**项目自己"看界面"的能力（`scripts\渲染快照.ps1` + `scripts\截图转文本.js`）**

本项目的 UI 验证一直只能靠人看；而沙箱里既起不了带界面的 Electron，

拆解动画**完全照抄 RhineLabUI `model-viewer.ts` 的规范**，不是自行设计：

```
PARTS = [ {id, depth} × 6 ]                        六个部件各带一个 depth
按 userData.assemblyPart 把网格分组                 22 个节点每个都带这个 extras
每帧 group[part].position.z = depth * spread       沿 Z 平移
spread 阻尼跟随目标值，速率 5.5
```

| 部件 | 英文 | depth |
| --- | --- | --- |
| 紧固件 | FASTENERS | 2.75 |
| 透明盖板 | OPTICAL COVER | 1.85 |
| 折射环组 | REFRACTIVE RINGS | 0.75 |
| 光学核心 | OPTICAL CORE | −0.15 |
| 信息基板 | SUBSTRATE | −1.10 |
| 背板与框架 | CARRIER | −2.05 |

- **两个模型共用同一个中心偏移**（都按单体的包围盒居中）：各自居中的话，
  拆解时零件会整体错位 —— 它们出自同一套 Blender 坐标
- 装好时显示单体，`spread > 0.02` 时换成拆解件；两者在 `spread = 0` 时外形一致，
  硬切换看不出来
- **取景只做一次**，按单体包围盒定相机（1.72 倍留白吃掉拆解增量），
  拆解途中不重新取景 —— 否则镜头自己缩放会晕

**转速与播放状态联动**

播放时正常转（0.30 rad/s），暂停时几乎停住（0.05），阻尼过渡避免一按暂停就跳。
这样 3D 与"正在放歌"产生联系，而不是自顾自地转。

那套主题的封面本来就该是这卷档案。其它主题仍默认关闭；
**用户只要手动关过一次，就永远尊重用户的选择、不再自动打开**。

### 说明：`.blend` 与 `.glb` 的关系

用户要求"把 Blender 文件用于播放器 UI"。需要说清一件事：
**`.blend` 是 Blender 的工程文件，运行中的程序读不了它** —— 没有运行时会去解析 `.blend`。
正确通路是在 Blender 里导出 `glTF 二进制`（`.glb`），程序加载 `.glb`。

`art/internal_architecture.py` 和两个 `.blend` 源场景"）：

| `.blend` 源 | 导出件 | 用途 |
| --- | --- | --- |
| `rhine-archive.blend` | `archive-cassette.glb` | 单体（默认视图）—— v1.2.0 已用 |
| `archive-assembly.blend` | `archive-assembly.glb` | 拆解件 —— **本版本新用** |

本机没装 Blender，所以无法从 `.blend` 重新导出或减面；直接用现成 `.glb` 是唯一可行做法。

## [1.1.4] — 2025

**主题：** 修复一个会**毁坏用户原始缓存文件**的严重缺陷（硬链接 + 覆盖擦除）。
这是本项目最严重的一次事故，原因、机制与修复完整记录在下面。

### 修复

**★ 严重：擦除派生副本时会就地毁掉用户的原始缓存文件**

事故现象：B 站缓存音频突然无法播放，报 `MediaError 4`（"格式不支持或文件头异常"）。

根因链条：

1. `bili.js` 的 `ensureM4a` 对**嗅探不到 MP4 头**的源文件（`offset === 0`）走的是
   `fs.linkSync(audioPath, dest)` —— **硬链接**，副本与源文件**共享同一个 inode**。
   （当初选硬链接是为了"同盘瞬时、不占额外空间"。）
2. v1.1.0 起副本目录改为**会话临时目录**，退出时由 `wipeDir` 擦除。
3. `wipeFile` 的擦除方式是"以 `r+` 打开、整天覆写 0、`fsync`、再 `unlink`"。
   覆写是**写 inode**，于是透过硬链接直接落到用户的原始缓存文件上；
   随后的 `unlink` 只摘掉副本那个目录项 —— **源文件还在，内容已经全是 0**。
4. 下次启动时 `ensureM4a` 从"已经是全 0"的源文件生成副本，
   Chromium 自然解不出来 → `MediaError 4`。

已实测确认：用户 `Downloads\Mobile Devices\` 下**两个音频缓存文件被原地写成全 0**
（文件大小不变、非零字节数为 0）。带 9 字节自定义头的电脑端缓存不受影响，
因为它们走的是 `copyWithoutPrefix`（真正的独立副本）。

修复（两层，缺一不可）：

- **`wipeFile` 增加硬链接保护**：`nlink > 1` 时**只摘目录项，绝不覆写**。
  这是中央防线 —— 同时保护了会话临时目录与 `purgeLegacyAudioCache()`
  要清理的 `userData\bili_audio`（v1.0.x 在里面留的也正是硬链接）。
- **`ensureM4a` 彻底不再用 `linkSync`**：一律 `copyFileSync` 出**独立副本**
  （`nlink === 1`、与源 inode 不同）。多占一份磁盘，换绝对安全。

### 新增

- `scripts\数据管控验证.js` 增加 **第 3b 组「硬链接保护」回归测试**（断言数 16 → 27）：
  - 构造硬链接副本 → 用**从 `main.js` 源码摘出的真实 `wipeFile`** 擦除 →
    断言源文件 MD5 **一字不变**、链接数回到 1
  - 反向断言 `ensureM4a` 产出的副本不再与源共享 inode、且 `nlink === 1`
  - 静态断言 `wipeFile` 含 `nlink > 1` 保护、`bili.js` 不再出现 `linkSync(` 调用
    （断言前先剥掉注释，避免"注释里提到 `linkSync`"造成误报；
    正则用 `(?<!un)linkSync\(` 以免被 `unlinkSync` 误命中）

### 变更

- `app\package.json`：版本号 `1.1.3` → **`1.1.4`**
- `docs\数据管控与合规.md`：擦除一节补上硬链接保护；「已知边界」补上本次事故的说明
- `docs\架构说明.md`：数据管控层的擦除小节同步

### 说明

- 这两个被毁掉的文件位于 `Downloads\Mobile Devices\`（手机导出的缓存），
  **不在 B 站客户端缓存目录里**，无法通过重新缓存取回。可尝试
  「属性 → 以前的版本」或文件历史找回；否则需从手机重新导出。
- 电脑端 B 站缓存（`Videos\bilibili\`）**全部完好**，因为它们的副本一直是独立文件。

## [1.1.1] — 2025

**主题：可视化调音等偏好设置的持久化修复。**

### 修复 —— 设置"重启后不保持"

三个滑块/选项的调音数据本该**全局通用、重启后保持**，实际却会静默丢失。
两类成因都属于"不报错、不崩溃，只是设置悄悄没了"：

- **鼓点强度（写 A 读 B）** — 滑块 `setItem('mp_kick')`，恢复代码却 `getItem('mp_kick2')`，
  而 `mp_kick2` 从来没有被写入过。于是每次重启鼓点强度都退回默认 `0.40`，
  滑块位置也停在中点。已改为读写同一个键 `mp_kick`
- **排序方式（只读不写）** — 恢复代码读 `mp_sort`，但 `#sortSel` 的 `change` 处理器
  只改了变量没落盘。已补上 `setItem('mp_sort', ...)`
- **排序方式（不回填控件）** — 即使读到了值，也没有写回 `<select>`，
  界面仍显示"添加顺序"，看起来就像没保存。已补 `$('#sortSel').value = sm`

顺带加固：排序方式恢复时增加 `SORT_MODES` 白名单校验
（直接信任 localStorage 里的字符串会让下拉框落到空白项）。

### 确认 —— 调音数据本来就是全局的

排查中确认了「所有歌曲通用」这一条**本来就没有问题**，并用自动化断言固定下来：

- 5 个调音参数（`tiltStrength` / `jitterK` / `kickPump` / `bassGainTarget` / `bassSigma`）
  都是模块级全局变量，没有任何一首歌单独持有一套
- 切歌/播放流程（`selectSong` / `playAt` / `playRandom` / `nextSong` / `prevSong`）
  不触碰这些变量
- `idbPut` 写单曲记录时不包含任何调音字段
- 频谱 Worker 只算**原始频段幅度 + 鼓点触发**，不含任何调音参数，
  因此 Worker 重建也不会让调音回退

### 新增 —— 回归验证

- 新增 `scripts\设置持久化验证.js`，**31 项断言**，`node` 直接跑，不需要 Electron：
  | 组 | 验证内容 |
  | --- | --- |
  | 1 | localStorage 键名交叉校验：没有"只读不写"（永远读不到）也没有"只写不读"（写了没人用） |
  | 2 | 每个 `type="range"` 滑块都要「保存 / 恢复同一个键 / 回填控件」三件事齐全 |
  | 3 | 下拉框恢复时回填控件；枚举型设置有白名单校验 |
  | 4 | 调音参数是全局的，且不被切歌流程改动；恢复走 `apply*` 而不是只改变量 |

  | 6 | 恢复时的范围闸门要与滑块 `min`/`max` 一致（改范围忘了改闸门会静默丢弃边界值） |

### 修复

开发过程中定位并修复的问题，一并记录以便追溯：

- **鼓点响应失效** — 低频参考值 `kickRef` 只在首次赋值（`if (kickRef <= 0)`）之后不再更新，
  导致 `kick` 迅速饱和到 1.0，乘性泵浦完全失效。改为持续跟踪 `kickRef += (lowMag - kickRef) * 0.05`，
  Worker 与同步回退两条路径都修复
- **滑动感做不出来** — 值位移混合在平滑频谱上不可见；随机抖动波方向随机、平均位移为零。
  改为每 6 条柱体一个周期的相干行波，相位每帧推进 0.26
- **打开小窗后主窗帧率减半** — `resources\app\main.js` 曾设置
  `webContents.setFrameRate(60)` 且小窗持续渲染；移除 `setFrameRate`，
  小窗改为按需渲染，并关闭 `disable-direct-composition`（保留 flip-model）
- **媒体键状态误报「被占用」** — 6 s 重试逻辑把已被本程序注册的键重新注册，
  Electron 返回 `false`（`IsRegistered` 检查），把健康状态改写成失败。改为幂等注册
- **进度条圆形滑块不跟随** — 代码只设置了 `#barFill` 的宽度，`#barThumb` 从未被定位。
  新增 `setBarUI(pct)` 同时设置填充宽度与滑块位置，接入 `timeupdate`、重置与两条拖动路径
- **暂停按钮看起来是方的** — 两个独立原因：图标原来是两个尖角矩形
  （`M6 5h4v14H6zM14 5h4v14h-4z`），改为圆角 `<rect rx="1.8">`；
  且 `#playBtn` 缺少 `icon-btn` class，因而没有 `border-radius: 50%`
- **迷你窗图标未同步改版** — 主界面换新图标集后小窗仍用旧图标，新增独立 `MIC` 图标库
- **迷你窗缩放异常** — 渲染层 `e.screenX` 已是 DIP，又除了一次 `scaleFactor`，
  125% 缩放下窗口增长慢 20%。改用主进程 `screen.getCursorScreenPoint()`
- **迷你窗拖不动** — 点击穿透靠页面 mousemove 事件驱动，快速移动后立刻按下时状态未切换。
  改为主进程 50 ms 光标轮询，即使丢事件也会自愈
- **迷你窗被游戏遮挡** — 无边框全屏游戏会重新抢 Z 序，增加 800 ms 周期重申置顶

### 已知限制

- Windows 独占全屏（Exclusive Fullscreen）下，任何普通窗口都无法覆盖，迷你窗不会显示；
  请将游戏改为「无边框窗口」或「窗口化全屏」
- Windows 媒体键是独占资源，被其它程序注册时本程序无法接管，设置面板会显示占用状态
- 60 Hz 显示器下可见帧率上限为 60，渲染路径的目标是「稳定无卡顿」而非追求更高数字
