## [2.7.0] — 2026-10-08

**主题：** 频谱"延迟更低 + 帧率更高 + 动态对比更极端"。

### 变更

- **分析窗 1024 → 512 点（延迟砍半）**：窗本身引入的群延迟从 ≈10.7ms 降到 ≈5.3ms。
  这是目前**唯一一处刻意偏离 1.3.0** 的参数。代价：等效噪声带宽翻倍（≈70Hz → ≈141Hz），
  低频那根"细针"对邻频带更敏感 —— 用户已知情并选择接受，观感由频段增益与瞬态强调保形。
- **动态对比拉大**：瞬态强调系数 `TRANSIENT_BOOST` 0.62 → 0.90、门曲线斜率
  `TRANSIENT_GAIN` 2.6 → 3.4、鼓点放大 `KICK_RISE_GAIN` 3.2 → 4.2。
  只改"动"与"静"的反差，不动稳态的频谱形状。
- **瞬态通量归一化改用上一帧峰值**（`prevMx`）：原来用**本帧**峰值做分母，
  宽频敲击会把自己的峰值抬高、把通量缩掉，门因此关不严（降窗后尤其明显）。
  改用敲击前的稳定参考后，底鼓 / 军鼓 / 踩镲三种敲击的 onset 都能正常打开。
  在线 worker 模板同步了同一算法（两条分析路径必须同参数）。
- **帧率解锁**：播放中不再卡 15ms 的手动节流 —— 60Hz 屏上恰好放行、看不出问题，
  但高刷屏上等于"每三帧才画一次"。有头实测：**41.6 fps → 85.3 fps**，
  帧间隔中位数由 24ms 降到 12ms。暂停后仍降到 ≈15fps 省电（收起动画也要画，不能停循环）。

### 新增与修正的验证

- 新增 `scripts\帧率探针.cjs`：驱动产物 exe 实测渲染帧率（fps / 帧间隔 p50·p90 / rAF 上界）。
  必须**有头**运行并前置窗口 —— Chromium 对后台窗口降频 rAF（实测后台 ~78Hz、前台 ~86Hz），
  不前置会量到偏低的数。
- `scripts\频谱离线观测.mjs`：
  - 踩镲用例由"纯 9kHz + 12kHz 正弦"改为**宽带**型（5.2–10kHz）。原用例的两个频点恰好
    踩在坑上：12kHz 超出频段覆盖上限（`F_MAX_RATIO` 0.45 × 24kHz = 10.8kHz）、
    9kHz 落在频段缝隙（检测器在 9216Hz，偏 216Hz，短窗 Hann 主瓣外只能靠旁瓣收）——
    这是**用例选频不真实**，不是产品缺陷（真实踩镲是宽带的）。
  - 鼓点检测器的复刻改为**从源码读常量**，不再抄一份（抄一份就会与实现漂移）。
  - `KICK_RISE_GAIN` 等灵敏度参数的自检由"钉死数值"改为"须是显式常量"。

## [2.6.0] — 2026-10-04

**主题：** 队列级频谱预分析 —— 把可视化从"反应"升级为"编排"，根治鼓点的感知延迟。

### 新增

- **播放前离线分析整首（"乐谱先验"）**：解成 8kHz 单声道 → 16 段 Goertzel 滤波组 →
  低频能量包络 + 谱通量 → 自相关测速 → 搜相位 + 吸附拍点，得到节拍网格、每拍强度与响度曲线。
  后台 worker 里跑，一次一首，队列最多 3 首（当前 + 后面两首），4 分钟的歌约 0.5 秒；
  结果存在曲目记录里，第二次播放直接命中。
- **鼓点提前 28ms 点亮**：在线检测是因果的（分析窗 21ms + worker 往返 + 绘制节拍，
  画面比耳朵晚 30~50ms），**调参救不了**。有了拍点就能在拍点**之前**升起来 ——
  合成点击轨实测拍点前 2ms 已达这一拍强度的 90%。
- **每 4 拍换一次柱体形态**：尖峰幅度 / 锯齿疏密 / 行波纹理按小节轮换（幅度都在 ±30% 以内），
  画面跟着小节走，不再只是被动响应。另加小节重音（每小节第一拍给低频一点额外推力）。
- **副歌预热**：前瞻 2.5 秒的响度明显高过前 5 秒时提前扩动态范围，高潮进来时不显得突然。
- 系统设置新增 `BEAT PRE-ANALYSIS` 一行：显示当前这首测出的 BPM 与拍点数、后台队列还剩几首，
  可一键关掉。

### 修复

- **拍点整体偏早 48ms**：第 f 帧检测到的事件时刻是 `f·HOP + (WIN−HOP)`（谱通量比的是
  "新进入窗的那一段"，它从窗内偏移 `WIN−HOP` 处开始），原来按窗起点报时间。
  不补这一项等于把"延迟"换个方向继续存在 —— 合成点击轨实测：不补 −46ms、补了 +2ms。

### 验证

- 新增 `scripts\节拍预分析验证.mjs`，**52 项全绿**：合成 40 秒 / 120 BPM 点击轨 + 20~32 秒副歌，
  钉住 BPM、拍点数、拍点对齐（中位数 2ms、无系统偏移）、提前量落在 20~31ms、
  小节形态每 4 拍一换、副歌预热的时间曲线，以及**"没有乐谱时柱高与改动前逐位相同"**。
- W 组专门钉一条硬约束：`analyzeMono` 必须自包含（worker 靠 `toString()` 注入），
  验法是把 toString 的结果重新求值成函数、跑同一输入、要求**逐位相同**。
- 全量回归 9 套全绿 + `tsc --noEmit` ✓

## [2.5.0] — 2026-10-04

**主题：** 收紧频谱回落（拖尾），给详情区与弹层加玻璃质感。

### 修复

- **频谱回落不够干脆** —— 先量出停信号后的衰减曲线（新增 `scripts\频谱回落观测.mjs`），
  结论是柱体本身很脆（峰值 1.0 一个 tick 掉到 0.40，掉到 10% 只用 40ms），
  拖尾在**峰值指示线**上：原本 `peaks *= 0.97/tick`，半程 455ms、掉到 10% 要 1.5 秒。
  - `PEAK_DECAY` 0.97 → **0.90**，半程 132ms、10% 437ms，仍比柱体慢一档但不再是残影
  - `decay()` 原先写死 0.94，统一到同一个 `PEAK_DECAY`
  - `FALL_INTERP_SPAN = 0.6`：绘制插值改为非对称，下降在 12ms 内到位，上升仍走满跨度
  - `snapshot()` 补 `peaks` 字段，回落观测才能单独量这条线

### 新增

- **玻璃质感**：详情面板 `rgba(243,241,235,0.7)` + `blur(12px) saturate(1.12)`；
  弹层 `rgba(240,238,231,0.74)` + `blur(16px) saturate(1.14)`；均配 14px 圆角与顶部高光。
  深色主题换深玻璃，`prefers-reduced-transparency: reduce` 时收掉。
  播放条与播放列表**不加**，背后是持续动画的三维场景，每帧重模糊不划算。
- `scripts\频谱回落观测.mjs`（含常量自检与判定门槛）、`scripts\面板表面清点.cjs`、`scripts\玻璃质感截图.cjs`

### 验证

`右侧切换验证.cjs` 24 项全绿；全量回归 9 套 + `tsc --noEmit` 通过。

## [2.4.0] — 2026-10-04

**主题：** 右侧面板可在「可视化」与「歌词」之间切换，并修掉这轮暴露的三个歌词同步缺陷。

### 新增

- **右侧「可视化 ⟷ 歌词」分段开关**：位于详情区顶部工具栏，两个选项都画出来、当前项反白；
  状态存 `localStorage` 的 `rhine-detail-view`，重启后保持。
  切换走 `setDetailView()`，只换类名**不重绘**详情区（重绘会重放解密动画、重建频谱实例）。

### 修复

- **歌词跟错曲目**：`stepLyrics()` 用 `currentSong()` 取词，而详情区展示的是 `songs[selected]`，
  两者可以不同。改为以详情区展示的那首为准（`detailSongId` / `detailSong()`）。

## [2.3.0] — 2026-10-03

**主题：** 把频谱对音质的隐性代价还回去，音频链路补上保音调、预取与跟随封面配色。
背景见 [2026-10-03-代码审阅与优化建议.md](2026-10-03-代码审阅与优化建议.md)。

### 修复

- **三维档案被绑在核显上**：`app\main.js` 注释里的 `force-discrete-gpu` 在 Windows 的 Chromium
  里根本不存在，等于什么都没做，程序一直落在核显上 → 帧率看门狗降档 → 刻线先糊。
  改用 Electron 自己的开关：默认 `--force_high_performance_gpu`，退回核显加 `--low-power-gpu`
  或 `settings.json` 写 `"preferDiscreteGpu": false`。
- **音频图固定连回 destination**：`createMediaElementSource()` 会**取代**元素自身的直通输出，
  不接 `ctx.destination` 就是无声 + 频谱不动。
- **AudioContext 无参构造**：按规范 `sampleRate` 传 0 会抛 `NotSupportedError`。
  用 `new Ctor()` 即"使用输出设备首选采样率"。
- **可视化失败改为有限重试**：`VIZ_MAX_ATTEMPTS = 3`，成功即归零，重试用尽才 toast。
- **变速保音调**：显式设 `preservesPitch` / `webkitPreservesPitch = true`；此前依赖浏览器默认值，
  0.75× 发闷、1.5× 变尖。

### 优化

- **低画质档补精度**（`render-quality.ts` 的 `performance` 档）：`antialias` off → `smaa`
  （离屏渲染目标上 renderer 的 `antialias` 不生效，等于全程无抗锯齿）、`transmission` 0.5 → 0.75、
  `anisotropy` 4 → 16。
- **已存画质设置一次性迁移**：`normalizeQuality()` 逐项读已存设置，光改档位定义对老用户不生效，
  加 `supersededPresets` 按档位名映射，保住档位意图又真的拿到修正；自定义档不误升级。
  回归 `node scripts\画质迁移验证.mjs`。
- **界面舒展一档并修三处遮挡**（用 `scripts\版面探针.mjs` 量两两重叠面积）：
  详情区改成底边锚定（`bottom: 112px`，内容再长也只向上生长）；
  播放条与抽屉宽度定在 900（上限 910，右侧面板从 970 起）；
  设置弹窗改 `height: auto` + `max-height: 940px` + `overflow-y: auto`。
- **频谱观感强化**：鼓点 onset 参考电平改不对称跟随（阈值 0.08 → 0.02、放大 2.2× → 3.2×，
  160 BPM 命中率 96.9%）；新增谱通量检测做宽带瞬态强调（军鼓抬中频、踩镲抬高频）；
  顶端张力改低频大摆幅 + `TOP_SHIMMER` 高频抖动（符号翻转率 16.1% → 43.3%）；
  音色灵敏度用频率相关幂次（2.1 → 1.45）+ 谱锐化 0.55，只动形状不动低频峰高度。
- **两条频谱分析路径统一**：Worker 源码由 `player.ts` 从 `SPECTRUM_*` 常量插值生成，
  两条路径参数一致。算法本体仍是两份，加新逻辑两边都要写。
- **B 站音源统一走内存读取**：静态服务下 Chromium 拦 `file://`，报 MediaError 4，
  固定走 `readAudio` 读字节 → Blob → objectURL。
- **切歌预取**：距曲尾约 12 秒时备好下一首音源（只备源不播放）；`queueNext` 与换歌时
  `invalidatePrefetch()`；随机播放不预取。
- **歌词查找改单调游标**（摊还 O(1)）、**列表渲染去掉 O(n²)**（行首序号改用循环下标）、
  **进度条拖拽去掉强制布局**（矩形在 `pointerdown` 量一次 + rAF 合并）。

### 新增

- **封面主色驱动的强调色**：`refreshCoverAccent()` / `sampleAccent()` 按 HSV 加权采样主色，
  写成 `--p-accent` 等变量。成本极低（封面已是 512px dataURL，再缩到 24×24 采样）。
  灰度封面或无封面时回落主题默认色，可在设置面板「COVER ACCENT」关掉。

### 变更

- `app\package.json`：2.2.0 → **2.3.0**

## [2.2.0] — 2025

**主题：** 一个双击就能装的安装包（CI 自动编译 Setup.exe 挂 Release），外加播放器交互的多处修复。

### 变更

- 版本号 2.1.1 → **2.2.0**；安装主路径改成「下载 Setup.exe 双击安装」，源码里的 `安装.bat` 退为开发路径
- 新增 `installer\`、`.github\workflows\release.yml`、`scripts\build-installer.ps1`、`打包安装包.bat`
- **自动构建发布**：推 `v*` 标签 → 校验标签与版本号一致 → 文档一致性 + 三套离线回归 →
  `choco install innosetup` → 便携版 + Setup.exe → `gh release create/upload`
- **一键安装包**：Inno Setup 6 把便携目录包成单个 Setup.exe。向导刻意做短
  （去掉许可页、开始菜单组页、准备安装页）；按用户安装（`PrivilegesRequired=lowest`），不弹 UAC；
  AppId 固定，新版本认成升级；卸载不删用户数据；桌面快捷方式默认勾选可取消。
  刻意不写 `ArchitecturesAllowed`（取值在 Inno 6.3 前后不同，写死会让另一版本报 Unknown architecture）。
  MIT 声明随分发件走（`LICENSE` 复制成 `resources\app\LICENSE.txt`）。
  ⚠ `.iss` 与 `scripts\*.ps1` 必须存成 UTF-8 带 BOM，否则中文乱码。
- **安装从两步变一步**：`安装.bat` 默认带 `-Launch`；没有 Node 依赖时跳过界面重建、沿用已有产物。

### 修复

- **有线耳机接听键**：补 `Ctrl+Alt+A` 接听（播放/继续）、`Ctrl+Alt+H` 挂断（暂停）供改键绑定。
  线控接听键通常已被系统翻译成媒体键，多半本来就能用；不做键盘钩子硬抢（会被反作弊判成外挂）。
- **"之前导入的歌曲全不见了"**：曲库没丢。旧库实测 `getAll` 要 2,995ms（397 首 3.5GB blob），
  超过原来 8 秒兜底超时，而兜底返回空数组后**不重试**就当空库渲染。
  新增 `loadLibraryWithRetry()`：超时先提示"正在读取曲库…"，再用 30 秒重读一次。
- **频谱回到 1.3.0 手感 + 点曲名打开档案**：分析节拍常量 `VIZ_ANALYSIS_MS`（当时设 33，
  后来发现 1.3.0 其实是 50Hz）。播放条曲名区 = 打开档案，其它位置 = 回到阵列，控件区两者都不触发。
- **导入旧版调音设置**：旧版跑 `file://` 域、新版跑 `http://127.0.0.1:41739`，localStorage 按 origin
  隔离读不到。用主进程开一个隐藏 `file://` 空白页让 Chromium 自己读那份存储再交回渲染侧。
  频谱五参数改成运行时对象 `vizParams`，导入一次即记住。
- **频谱算法两处和 1.3.0 不一致**：频段映射写死 42Hz~16000Hz（原版是 `fMin=20`、
  `fMax=0.45×Nyquist`，48kHz 下低频峰落在 86Hz 而原版 43Hz，每根柱子的频率都是错的）；
  鼓点 onset 段位第 2–8 带（原版 2–16 带）。两处都改回原版公式，同步路径与 worker 两边同时改。
  另去掉播放条 52 格的 30ms 节流。新增 `spectrum.bandInfo()`。
- **B 站缓存与源文件解耦**：原设计副本只写在会话临时目录、退出即销毁，源文件夹一没就重建不出来。
  新增 `bili-keep` IPC 把副本再复制到 `<userData>\library\audio\`；取音源优先级改成
  本地副本 → 会话副本 → 源缓存；三样都没有时提示带上真实原因。
  设置面板加 `LOCAL AUDIO COPIES` 行显示占盘。
- **开屏整段恢复原速**（`BOOT_SPEED = 1`）、播放条图标统一成 `stroke-width: 1.7` 线描去掉小方块、
  切歌不再重播解密黑条（`renderDetail(instantRedaction)` 只有第一次进详情才播）、
  `POWERED BY RHINE LAB` 抬到 `z-index: 12`、回车改为打开档案并播放。
- **一键全部重新读取封面**：`rereadAllCovers()` 逐首调 `read-cover`，无本地路径的跳过，
  每 8 首报一次进度，结束给汇总。
- **打开档案与播放对不上**：新增 `player.focusTrack(index)`，打开档案时把播放器切到这一首但不播放；
  双击档案 = 选中 → 打开 → 起播（`scene.ts` 双击判定 < 400ms）。
- **播放列表多种排列顺序**：导入顺序 / 曲名 / 艺术家 / 专辑 / 时长 / 播放次数 / 最近添加，
  用 `localeCompare(..., "zh-Hans-CN")`，排完把当前这首的新下标用 `rhine-track` 告诉终端。
- **全屏后底部被播放条盖住**：播放条从 `bottom: 40px` 回到 `80px`。
  **标题不是上次听的那首**：`dedupeLibrary()` 删掉的正是播放头记的那条，

## 版本规划

### 计划中

- 播放列表导入 / 导出（M3U）
- 自定义封面替换
- 均衡器
- 多语言界面

### 已知边界

- Windows 媒体键是独占资源，被其它程序注册时本程序无法接管，设置面板会显示占用状态

- 在线音乐源（本项目定位为本地播放器）
- 云同步
