## [1.1.2] — 2025

**主题：推送流程工程化。** 应用代码（`app/` 下的 js / html）未改动，
`app/package.json` 只跟着升了版本号。

### 变更

- `app\package.json`：版本号 `1.1.1` → **`1.1.2`**（应用代码本身无变化）
- `scripts\push-to-github.ps1` 重写：
  - **`-RepoUrl` 变为可选** —— 省略时沿用已有 `origin`，日常更新只需
    `.\scripts\push-to-github.ps1` 一条命令
  - 新增**通道探测 + 自动适配**：先跑 `git ls-remote`，失败时按错误类型分类并兜底
    | 判定 | 兜底动作 |
    | --- | --- |
    | `tls` | 改用 openssl 后端 + 合并本机自签 CA 的 bundle |
    | `credential` | 直接调用 `git-credential-manager.exe` 取缓存凭证，拼成 `Authorization` 头 |
    | `network` / `nonfastforward` | 不做兜底，给出对应提示 |
  - 新增 `-Check`（只探测通道）与 `-NoAutoFix`（关闭兜底）
  - 统一用 `Invoke-GitCapture` 调用 git：临时放宽 `$ErrorActionPreference`，
    避免 git 写在 stderr 的进度信息在 `EAP=Stop` 下被当成终止性错误而中断
- `scripts\setup-push-tls.ps1` 新增 `-SetEnv` / `-EmitPath` / `-Quiet`：
  可把配置直接注入当前进程环境、可只输出 bundle 路径供其它脚本调用
- 新增 `推送.bat`（纯 ASCII 转发），双击即可推送

### 修复

- **「凭证兜底不触发」** —— 通道探测用的是 `git ls-remote`，而**公开仓库的 ls-remote
  根本不需要凭证**，所以 TLS 修好后探测就通过了，脚本误判"通道没问题"，
  一直到真正的 `git push` 才因为认证失败而报错，兜底却已经错过。
  现已把凭证兜底挂到**真正需要认证的那一步**：`push` 失败且判定为
  `credential` / `tls` 类问题时，取缓存凭证重试一次
- 「CA 收集输出绕过 `-Quiet`」：`setup-push-tls.ps1` 里两处裸 `Write-Host`
  不受 `-Quiet` 约束，被 `push-to-github.ps1` 调用时会刷出 50 多行证书清单

### 文档

- `docs\构建与安装.md` 第 6 节重写：单一命令用法、参数表、自动适配的错误分类表、
  标签列表补上 `v1.1.1`；原「推送不通时的排查」降级为原理与手动排查参考
- `README.md` 项目结构补上 `推送.bat` 与新脚本说明

## [1.1.1] — 2025

**主题：可视化调音等偏好设置的持久化修复。**

### 修复 —— 设置"重启后不保持"

三个滑块/选项的调音数据本该**全局通用、重启后保持**，实际却会静默丢失。
两类成因都属于"不报错、不崩溃，只是设置悄悄没了"：

- **鼓点强度（写 A 读 B）** — 滑块 `setItem('mp_kick')`，恢复代码却 `getItem('mp_kick2')`，
  而 `mp_kick2` 从来没有被写入过。于是每次重启鼓点强度都退回默认 `0.40`，
  滑块位置也停在中点。已改为读写同一个键 `mp_kick`
- **排序方式（只读不写）** — 恢复代码读 `mp_sort`，但 `#sortSel` 的 `change` 处理器
  只改了变量没落盘。已补上 `setItem('mp_sort', ...)`
- **排序方式（不回填控件）** — 即使读到了值，也没有写回 `<select>`，
  界面仍显示"添加顺序"，看起来就像没保存。已补 `$('#sortSel').value = sm`

顺带加固：排序方式恢复时增加 `SORT_MODES` 白名单校验
（直接信任 localStorage 里的字符串会让下拉框落到空白项）。

### 确认 —— 调音数据本来就是全局的

排查中确认了「所有歌曲通用」这一条**本来就没有问题**，并用自动化断言固定下来：

- 5 个调音参数（`tiltStrength` / `jitterK` / `kickPump` / `bassGainTarget` / `bassSigma`）
  都是模块级全局变量，没有任何一首歌单独持有一套
- 切歌/播放流程（`selectSong` / `playAt` / `playRandom` / `nextSong` / `prevSong`）
  不触碰这些变量
- `idbPut` 写单曲记录时不包含任何调音字段
- 频谱 Worker 只算**原始频段幅度 + 鼓点触发**，不含任何调音参数，
  因此 Worker 重建也不会让调音回退

### 新增 —— 回归验证

- 新增 `scripts\设置持久化验证.js`，**31 项断言**，`node` 直接跑，不需要 Electron：
  | 组 | 验证内容 |
  | --- | --- |
  | 1 | localStorage 键名交叉校验：没有"只读不写"（永远读不到）也没有"只写不读"（写了没人用） |
  | 2 | 每个 `type="range"` 滑块都要「保存 / 恢复同一个键 / 回填控件」三件事齐全 |
  | 3 | 下拉框恢复时回填控件；枚举型设置有白名单校验 |
  | 4 | 调音参数是全局的，且不被切歌流程改动；恢复走 `apply*` 而不是只改变量 |
  | 5 | 调音数据不写进单曲记录（否则就成了"每首歌一套"） |
  | 6 | 恢复时的范围闸门要与滑块 `min`/`max` 一致（改范围忘了改闸门会静默丢弃边界值） |
- 该脚本**验证过有牙齿**：把两个 bug 还原到副本上跑，能精确报出
  「只读未写: mp_kick2 读于第 2299 行 / 只写未读: mp_kick 写于第 1171 行」并退出 1

### 修复 —— 验证脚本自身的缺陷

第 6 组最初用单行正则匹配恢复语句，而 4/5 个滑块的恢复是跨两行的
（`const` 一行、`if` 一行），导致误报"没有范围闸门"。已改为向后看 4 行。

## [1.1.0] — 2025

**主题：派生数据管控 + 历史版本回滚。**

### 新增 —— 数据管控

针对程序能解出的两类派生数据（`.ncm` 解出的音频、B 站缓存剥离头后的副本），
加入「不落盘 / 不可导出 / 可追溯」三层管控。

**最小落盘**
- 解密结果只在内存中经 IPC 传递给渲染进程，**从不写入用户音乐目录**
- 新增**会话专属临时目录** `%TEMP%\mp-session-<12位随机ID>\`，每次启动重新生成
- B 站可播放副本改写到会话目录（原来长期驻留在 `userData\bili_audio`）
- 解密子目录在字节读回内存后**立即覆盖擦写并删除**，不等 GC
- `will-quit` 拦截退出 → 递归擦除会话目录 → 真正退出（4 秒兜底，不会关不掉）
- 启动时 `sweepStaleSessions()` 清掉崩溃/强杀残留的会话目录
- 启动时 `purgeLegacyAudioCache()` 擦除 1.0.x 遗留在 `userData\bili_audio` 的长期副本（升级清理）
- 临时目录尽力打上隐藏属性（`attrib +h`）
- `wipeFile()` 覆盖写零 + `fsync` 后再 `unlink`，单会话上限 256 MB 避免退出卡顿

**不可导出**
- 确认全部 27 个 IPC 通道**没有任何一个接受"输出路径"参数**
- `preload.js` 暴露的 16 个方法中**没有任何写文件方法**
- 这条保证是结构性的：不是"没做导出按钮"，而是"没有可用路径把字节写到磁盘"

**可追溯**
- 新增本地审计日志 `userData\audit.log`：时间 / 版本 / 会话 ID / 事件 / 来源文件 / 产物体积 / 结果
- 记录 `ncm-decrypt`、`bili-extract`、`bili-scan` 三类事件，上限 500 条自动裁剪
- 只在本机，程序从不外发

**输入侧限制**
- `convert-ncm` 先校验 `CTENFDAM` 容器魔数，非 NCM 直接拒绝（不再是一个通用解密器）
- B 站提取只处理本机已有缓存，不发起任何音频下载请求
- 原始 `.ncm` 与缓存文件从不被修改或删除

**程序内可见性**
- ⚙ 面板新增「数据管控」行：`内存解密 · 会话级临时目录 · 无导出 · 审计 N 条`（悬停看完整说明与审计路径）
- 同排「清日志」按钮一键清空审计
- ⚙ 面板新增「版本」行，显示当前版本号
- 首次启动弹出一次**使用边界与数据管控告知**弹层（记录在 `localStorage.mp_notice_v110`）

**新增 IPC / API**
- `get-data-policy` → `{ version, sessionId, auditCount, policy }`
- `clear-audit-log`
- `preload` 对应暴露 `getDataPolicy()` / `clearAuditLog()`

**回归验证**
- 新增 `scripts\数据管控验证.js`，16 项断言：
  副本落盘位置（3 项）、擦除逻辑（3 项）、陈旧清扫（1 项）、静态断言（8 项）、
  preload 暴露面（1 项）。`node scripts\数据管控验证.js app` 即可跑
- 擦除逻辑的测试**从 `main.js` 源码里摘出实现**再执行，测的是真实代码文本而非复制品

**文档**
- 新增 `docs\数据管控与合规.md`：技术实现、验证明细、使用边界、已知边界（含"覆盖擦除不保证
  取证级不可恢复"的诚实说明）
- README 新增「数据管控」一节；`docs\功能说明.md` 的 NCM / B 站章节同步更新

### 新增 —— 历史版本回滚

- `versions\` 归档 12 个历史关键节点的逐字节快照（自包含单文件 HTML，可直接当 `app/index.html` 运行）
- `scripts\use-version.ps1` 一键回滚：自动备份当前版本 → 替换 → 重新构建
- `versions\README.md` 含版本对照表、兼容性说明，以及一段已被后续需求取代的历史约束记录

### 变更

- `app\package.json`：版本号 `1.0.0` → **`1.1.0`**，补充 `author` / `repository`，标记 `private`
- 新增 git 附注标签 **`v1.0.0`**（首个公开发布版本）与 **`v1.1.0`**（本版本），
  推送时由 `push-to-github.ps1` 一并推送
- B 站可播放副本位置：`userData\bili_audio\` → **会话临时目录**（下次启动由 `ensureAllPlayable()` 重新生成）
- `bili.js` 的 `ensureM4a(audioPath, cacheDir, force)`：第二个参数语义由 `userDataDir` 改为
  **直接的缓存目录**；`scan` 新增 `opts.audioDir`（未提供时回退旧行为）
- `main.js` 的 `cleanupDir()`（`fs.rmSync`）→ `wipeDir()`（覆盖擦写 + 删除）

### 修复

- 「推送脚本把失败当成功」：`scripts\push-to-github.ps1` 未检查 `git push` 退出码，
  而 PowerShell 5.1 的 `$ErrorActionPreference='Stop'` 不覆盖原生命令退出码 ——
  推送失败也会打印"推送成功"。现已显式检查并给出针对性排查建议
- 「bat 注释被当成命令执行」：`构建.bat` / `安装.bat` 在 `chcp` 之前含中文注释，
  cmd.exe 切换代码页后按旧字节偏移重读文件，把 `rem` 行解析成命令并报错。
  已改为纯 ASCII；生成的卸载脚本改为 `.bat`（纯 ASCII 转发）+ `.ps1`（真正逻辑）
- 「失效的代码注释」：`app\index.html` 中引用了已删除的调试脚本路径

## [1.0.0] — 2025

首个公开发布版本。

### 新增

**曲库**
- 支持文件导入、文件夹递归导入、拖拽导入
- 支持 `mp3` / `flac` / `m4a` / `aac` / `wav` / `ogg` / `wma` / `ape` / `ncm`
- `.ncm` 网易云加密文件导入时自动解密（内置 `ncmdump.exe` + AES-ECB 回退实现）
- B 站客户端缓存扫描与音频提取
- 播放列表拖动排序、「下一首播放」队列插入

**元数据**
- 标题 / 歌手 / 专辑 / 封面自动识别
- 内嵌标签优先，回退同目录图片与文件名解析
- 多歌手识别：`/`、`、`、`&`、`;`、`feat.`、`ft.`、`with`、`×` 等分隔符全部拆分，并保护 `AC/DC`、`R&B` 等已知组合
- 已导入歌曲一键「重新识别」，且不丢失收藏、播放次数与进度

**播放**
- 四种播放模式：列表循环 / 顺序播放 / 单曲循环 / 随机播放
- 0.5× ~ 2.0× 倍速播放
- 播放进度、音量、播放模式、当前曲目自动记忆并恢复
- 关闭时正在播放的话，下次启动恢复到暂停状态（不突然出声）

**歌词**
- 同名 `.lrc`、内嵌歌词、相似文件名匹配三种来源
- UTF-8 / UTF-8 BOM / GBK 编码自动识别
- 逐行滚动高亮，支持翻译行

**频谱可视化**
- 自研频谱分析器：Hann 窗 + Goertzel 精确取点，1024 点时域样本
- 对数频率分带，120 条柱体
- 峰值归一化 + 对数压缩，安静段与爆音段都有动态
- 鼓点泵浦：低频能量动态参考值 + 上升沿检测 + 乘性调制
- 高耸条自动定位到柱体序列左边缘，配合倾斜因子形成窄而尖的形态
- 相干行波叠加（约 12 条/秒，方向右 → 左）营造滑动感
- 分析运行在 Web Worker 中，Worker 不可用时自动降级为同步计算
- 定时器驱动渲染，窗口被遮挡 / 最小化时不被 Chromium 节流
- 可视化参数（灵敏度、倾斜、鼓点强度、峰值保持、低频宽度、滑动强度、柱体粗细）可在设置面板实时调整

**迷你悬浮窗**
- 复用主窗已算好的柱体数据，不重复计算
- 使用最高置顶层 `screen-saver`，可显示在无边框全屏游戏之上
- 点击不抢焦点（`setFocusable(false)`），游戏中操作不切出
- 默认点击穿透，光标悬停到控件上时才可点
- 支持拖动（主进程光标轮询，尺寸锁定）、缩放、透明度、锁定、边缘吸附

**系统集成**
- 媒体键 / 耳机线控：`MediaPlayPause` / `MediaNextTrack` / `MediaPreviousTrack` / `MediaStop` / `MediaPlay` / `MediaPause`
- 双通道接管：Chromium Media Session（SMTC）+ Electron `globalShortcut`
- 幂等注册 + 6 s 自动重试，避免把已注册的键误判为「被占用」
- 300 ms 防抖，避免耳机连发事件导致播放/暂停互相抵消
- 设置面板内置媒体键自检（✓ 已注册 / ⚠ 被占用 / ✕ 全部被占用）
- 全局备用组合键 `Ctrl+Alt+P/N/B/Space`
- 迷你窗全局控制键 `Ctrl+Alt+方向键/0/9/L`

**界面**
- 左右分栏布局：左侧大封面，右侧歌曲信息 + 歌词 + 频谱可视化
- 封面区域向整屏渗出模糊背景，形成类网易云全屏封面的渐变过渡
- 三套主题：深色（蓝紫）、浅色、网易云红（`#EC4141`）
- 所有弹层、滑槽、滑块、进度条把手跟随主题
- 统一极简线性图标（`stroke-width: 1.7`，圆角端点），圆角播放按钮与胶囊形暂停图标
- 收藏、播放次数统计、多字段排序

**工程**
- `scripts/build-portable.ps1` — 一键构建便携版，运行时本地复用或自动下载
- `scripts/install.ps1` — 按用户安装 + 桌面/开始菜单快捷方式 + 卸载脚本
- `scripts/use-version.ps1` — 回滚 `app/index.html` 到 `versions/` 里的历史快照
- `scripts/push-to-github.ps1` — 设置 origin 并推送，含退出码检查与失败归因
- `versions/` — 12 个历史版本快照（自包含单文件 HTML，可直接当 `app/index.html` 运行）
- `构建.bat` / `安装.bat` 双击即用
- 完整中文文档：功能介绍、快捷键、构建与安装、架构说明、版本回滚

### 修复

开发过程中定位并修复的问题，一并记录以便追溯：

- **鼓点响应失效** — 低频参考值 `kickRef` 只在首次赋值（`if (kickRef <= 0)`）之后不再更新，
  导致 `kick` 迅速饱和到 1.0，乘性泵浦完全失效。改为持续跟踪 `kickRef += (lowMag - kickRef) * 0.05`，
  Worker 与同步回退两条路径都修复
- **滑动感做不出来** — 值位移混合在平滑频谱上不可见；随机抖动波方向随机、平均位移为零。
  改为每 6 条柱体一个周期的相干行波，相位每帧推进 0.26
- **打开小窗后主窗帧率减半** — `resources\app\main.js` 曾设置
  `webContents.setFrameRate(60)` 且小窗持续渲染；移除 `setFrameRate`，
  小窗改为按需渲染，并关闭 `disable-direct-composition`（保留 flip-model）
- **媒体键状态误报「被占用」** — 6 s 重试逻辑把已被本程序注册的键重新注册，
  Electron 返回 `false`（`IsRegistered` 检查），把健康状态改写成失败。改为幂等注册
- **进度条圆形滑块不跟随** — 代码只设置了 `#barFill` 的宽度，`#barThumb` 从未被定位。
  新增 `setBarUI(pct)` 同时设置填充宽度与滑块位置，接入 `timeupdate`、重置与两条拖动路径
- **暂停按钮看起来是方的** — 两个独立原因：图标原来是两个尖角矩形
  （`M6 5h4v14H6zM14 5h4v14h-4z`），改为圆角 `<rect rx="1.8">`；
  且 `#playBtn` 缺少 `icon-btn` class，因而没有 `border-radius: 50%`
- **迷你窗图标未同步改版** — 主界面换新图标集后小窗仍用旧图标，新增独立 `MIC` 图标库
- **迷你窗缩放异常** — 渲染层 `e.screenX` 已是 DIP，又除了一次 `scaleFactor`，
  125% 缩放下窗口增长慢 20%。改用主进程 `screen.getCursorScreenPoint()`
- **迷你窗拖不动** — 点击穿透靠页面 mousemove 事件驱动，快速移动后立刻按下时状态未切换。
  改为主进程 50 ms 光标轮询，即使丢事件也会自愈
- **迷你窗被游戏遮挡** — 无边框全屏游戏会重新抢 Z 序，增加 800 ms 周期重申置顶

### 已知限制

- Windows 独占全屏（Exclusive Fullscreen）下，任何普通窗口都无法覆盖，迷你窗不会显示；
  请将游戏改为「无边框窗口」或「窗口化全屏」
- Windows 媒体键是独占资源，被其它程序注册时本程序无法接管，设置面板会显示占用状态
- 60 Hz 显示器下可见帧率上限为 60，渲染路径的目标是「稳定无卡顿」而非追求更高数字
