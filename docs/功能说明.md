# 功能说明

本文档详细说明音乐播放器的全部功能与使用方式。

---

## 1. 曲库导入

### 1.1 导入文件

点击左栏「+ 添加」→ 选择文件，支持多选。

支持的音频格式：

| 格式 | 说明 |
| --- | --- |
| `.mp3` | 最常见，ID3v1 / ID3v2 标签与内嵌封面均支持 |
| `.flac` | 无损，支持 Vorbis Comment 与内嵌封面 |
| `.m4a` / `.aac` | AAC 系，支持 MP4 元数据 |
| `.wav` | 支持 LIST/INFO 标签 |
| `.ogg` | Vorbis |
| `.wma` | Windows Media Audio |
| `.ape` | Monkey's Audio |
| `.ncm` | 网易云加密格式，**导入时自动解密**（见 1.4） |

### 1.2 导入文件夹

点击「添加文件夹」→ 选择目录。程序会**递归**扫描该目录下所有支持的音频文件。

### 1.3 拖拽导入

直接把文件或文件夹拖到窗口任意位置即可，无需点击按钮。

### 1.4 NCM 自动解密

网易云音乐的 `.ncm` 是加密容器。本项目内置了两条解密路径：

1. **首选：随包的 `ncmdump.exe`**（官方实现，兼容全部 NCM 变体）
   - 把解密后的 mp3 / flac **连同完整 ID3 标签（标题 / 歌手 / 专辑 / 封面）** 一起写出
   - 程序在系统临时目录中解密，完成后读回内存，再清理临时文件
2. **回退：内置 AES-ECB 解密**
   - 当 `ncmdump.exe` 不可用或被安全软件拦截时启用
   - 直接解析 NCM 头部密钥块、RC4 密钥、元数据 JSON，再 AES-128-ECB 解密音频体
   - 通过文件头魔数嗅探真实格式（`ID3` / `fLaC` / `OggS` 等）

解密结果**只在内存中传递**，不会在你的音乐目录里产生任何新文件。
`ncmdump.exe` 写出的中间文件位于本次会话专属临时目录，字节读回内存后**立即覆盖擦写并删除**。

另外，`convert-ncm` 会先校验 `CTENFDAM` 容器魔数 —— 不是真正的 NCM 文件直接拒绝，
因此它不是一个"拿任意文件来试解"的通用解密器。

> 管控细节见 [数据管控与合规](数据管控与合规.md)。

## 2. 元数据识别

### 2.1 识别优先级

```
内嵌标签（ID3v2 / Vorbis / MP4）
      ↓ 缺失时
同目录 cover.jpg / cover.png / folder.jpg / 与音频同名的图片
      ↓ 缺失时
文件名解析（"歌手 - 歌名" 等常见格式）
```

### 2.2 多歌手识别

以下写法都会被拆分成**多个独立歌手**，并对每位歌手分别建立索引：

| 写法 | 拆分结果 |
| --- | --- |
| `周杰伦/费玉清` | 周杰伦、费玉清 |
| `周杰伦、费玉清` | 周杰伦、费玉清 |
| `周杰伦 & 费玉清` | 周杰伦、费玉清 |
| `周杰伦 feat. 费玉清` | 周杰伦、费玉清 |
| `周杰伦 ft. 费玉清` | 周杰伦、费玉清 |
| `周杰伦; 费玉清` | 周杰伦、费玉清 |

分隔符识别包含 `/`、`、`、`,`、`&`、`;`、`feat.`、`ft.`、`with`、`×` 等，
并带有「不误伤」保护：`AC/DC`、`/` 出现在 URL 中、`R&B` 等已知组合不会被拆开。

### 2.3 重新识别

对**已导入**的歌曲可以一键重跑识别流程（设置面板 → 重新识别）。
用于以下场景：

- 之前导入时文件名不规范，后来补了 ID3 标签
- 歌手拆分规则更新后需要重新索引
- 封面当时读取失败

重新识别只更新元数据，**不会**丢失收藏、播放次数与播放进度。

## 3. 播放

### 3.1 播放模式

| 模式 | 行为 |
| --- | --- |
| 列表循环 | 播完最后一首回到第一首 |
| 顺序播放 | 播完最后一首停止 |
| 单曲循环 | 当前曲目结束后重头再播 |
| 随机播放 | 随机选曲，尽量避免连续重复 |

点击播放控制区的模式按钮循环切换。

### 3.2 下一首播放

在任意曲目上右键 / 悬停菜单选择「下一首播放」，该曲目会被**插入**到当前播放位置之后，
而不是替换整个播放列表。

### 3.3 倍速播放

0.5× ~ 2.0×，调节后立即生效并随歌曲切换保持。

### 3.4 进度记忆

程序退出时保存：

- 当前播放列表
- 当前曲目
- 当前播放位置（秒）
- 收藏状态、播放次数、音量、播放模式、主题、可视化参数

下次启动自动恢复。若上次退出时正在播放，会恢复到暂停状态（不会突然出声）。

## 4. 歌词

### 4.1 来源优先级

1. 与音频文件**同名**的 `.lrc`
2. 音频文件**内嵌**歌词（ID3 USLT / SYLT 帧）
3. 同目录下文件名相似度最高的 `.lrc`
4. 上级目录中的 `.lrc`

### 4.2 编码

自动尝试 UTF-8 → UTF-8 BOM → GBK，避免中文歌词乱码。

### 4.3 显示

- 逐行滚动，当前行高亮放大
- 支持翻译行（同时间戳的第二行会作为译文并列显示）
- 无歌词时显示占位提示，不影响播放

## 5. 频谱可视化

### 5.1 为什么不用 `AnalyserNode`

`AnalyserNode.getByteFrequencyData()` 输出的是**等宽线性**频段。
音乐的绝大部分能量集中在低频，结果是左侧几条柱体剧烈跳动、右侧一片死寂，观感很差。

本项目自己实现了完整的频谱管线。

### 5.2 处理链路

```
AudioBuffer / MediaStream
   ↓ 取 1024 点时域样本
   ↓ Hann 窗（减少频谱泄漏）
   ↓ Goertzel 逐 bin 精确计算指定频点能量
   ↓ 对数频率分带 → 120 条柱体（每条约 1/12 倍频程）
   ↓ 峰值归一化（自适应 gain，随信号强度跟随）
   ↓ 对数压缩（dB 域取包络）
   ↓ 时间平滑（快攻慢放：上升快、回落慢）
   ↓ 鼓点泵浦（低频能量乘性调制）
   ↓ 相干行波叠加（滑动感）
   ↓ 逐柱峰值保持 + 衰减
输出到 canvas
```

### 5.3 关键参数

| 参数 | 默认值 | 含义 |
| --- | --- | --- |
| `SPECTRUM_N` | 1024 | 时域采样点数 |
| `SPECTRUM_BANDS` / `BAR_N` | 120 | 柱体数量 |
| `VIZ_LEVELS` | 14 | 柱体灰度层级 |
| `kickPump` | 0.40 | 鼓点泵浦强度 |
| `bassSigma` | 0.048 | 低频高斯权重宽度 |
| `bassGainTarget` | 1.05 | 低频增益目标 |
| `BASS_WIDE_CENTER` | 0.12 | 低频能量中心位置 |
| 行波频率 | `i / 6` | 每 6 条柱体一个完整周期 |
| 行波速度 | `0.26` / 帧 | 约 12 条/秒，方向右 → 左 |

### 5.4 高耸条

低频峰值的位置由 `bassPeakBar()` 实时计算，`NEEDLE_CENTER` 随之自动左移到柱体序列的
最左边缘，配合倾斜因子 `Tp = pow(5, tilt * (1 - BASS_PEAK_BAR / BAR_N))`
让高峰呈现**窄而尖**的形态，而不是胖墩墩的一坨。

### 5.5 鼓点响应

历史上这里有一个真实 bug：低频参考值 `kickRef` 只在第一次被赋值
（`if (kickRef <= 0) kickRef = lowMag;`）之后再也不更新，导致 `kick` 迅速饱和到 1.0，
乘性泵浦彻底失效。

修复方式是让参考值持续跟踪：

```js
kickRef += (lowMag - kickRef) * 0.05;
```

并用上升沿检测触发泵浦：

```js
const kRise = lowMag / (kickRef + 1e-6);
const kick  = Math.max(0, (kRise - 0.08) * 2.2);
```

Worker 路径与同步回退路径**两处都**做了同样的修复。

### 5.6 滑动感

早期的「值位移混合」在平滑频谱上完全不可见，随机抖动波的方向也是随机的
（平均位移为零，看起来只是抖，不像滑动）。现在改为**相干行波**：

```js
const wave = Math.sin((i / 6 + wavePhase) * Math.PI * 2) * 0.18;
// ...
wavePhase += 0.26;   // 每帧推进，波峰从右向左移动
```

每 6 条柱体一个完整正弦周期，相位每帧推进 0.26 → 约 12 条柱体/秒的**定向滑动**。

### 5.7 性能

- 频谱分析跑在 **Web Worker** 里，主线程零阻塞
- Worker 创建失败时自动降级为同步计算（功能不变，帧率略降）
- 可视化渲染由**定时器**驱动，而不是 `requestAnimationFrame`，
  避免窗口被遮挡 / 后台时被 Chromium 节流到 1 fps
- 迷你窗复用主窗已经算好的柱体数据，不重复计算

## 6. 迷你悬浮窗

### 6.1 打开方式

- 主界面右上角按钮
- 快捷键 `Ctrl+Alt+M`
- 托盘 / 菜单

### 6.2 特性

| 特性 | 实现 |
| --- | --- |
| 置顶 | `setAlwaysOnTop(true, 'screen-saver')` + 周期性 `moveTop()` 保活 |
| 不抢焦点 | `setFocusable(false)`，点击不会让游戏失焦 |
| 拖动 | 渲染进程指针事件 + 主进程 `screen.getCursorScreenPoint()` 轮询，拖动期间锁定窗口尺寸 |
| 缩放 | `Ctrl+Alt+ + / -`，或拖动边缘 |
| 透明度 | 滑块调节，`setOpacity` |
| 锁定 | `Ctrl+Alt+L`，锁定后忽略指针事件，防误触 |
| 吸附 | 拖动到屏幕边缘自动吸附 |
| 可视化 | 复用主窗数据，仅有独立的绘制尺寸 |

### 6.3 与独占全屏游戏

Windows 的**独占全屏**（Exclusive Fullscreen）会让 DWM 完全交出显示输出，
此时任何普通窗口都无法覆盖，这是操作系统层面的限制。

解决方案：把游戏改为「**无边框窗口**」或「窗口化全屏」。这样迷你窗可以正常置顶显示，
且点击迷你窗不会切出游戏。

## 7. 媒体键与耳机线控

### 7.1 双通道

Windows 上媒体键有两条独立路径：

1. **Chromium Media Session（SMTC）** — 系统媒体控制面板 / 部分蓝牙耳机走这条
2. **Electron `globalShortcut`（Win32 RegisterHotKey）** — 键盘与多数有线耳机线控走这条

两条都注册，命中任意一条都能工作。

### 7.2 幂等注册

`globalShortcut.register()` 对一个**已经被本进程注册**的键会返回 `false`。
历史上定时重试逻辑因此在重试时把健康状态误判成「被占用」，并把快捷键显示成不可用。

现在注册是**幂等**的：先查 `getHotkeyStatus()`，`detail[key] === true` 的键直接跳过重注册。

### 7.3 自检

设置面板中的「媒体键」一行显示：

| 显示 | 含义 | 处理 |
| --- | --- | --- |
| `✓ 已注册` | 全部成功 | 无需处理 |
| `⚠ 被占用` | 部分成功 | 关闭冲突程序，或用应用内快捷键 |
| `✕ 全部被占用` | 全部失败 | 同上 |

媒体键在 Windows 上是**独占**资源，同一时刻只能被一个程序注册。

### 7.4 防抖

按键事件做了 300 ms 防抖，避免部分耳机在单击时连发多次事件导致「播放→暂停」互相抵消
（表现为按了没反应）。

### 8.1 主题

#### 莱茵生命（仪器面板变体）

配色取自 [RhineLabUI](https://github.com/LBEILC/RhineLabUI)（明日方舟 · 莱茵生命，MIT）的
暗色面规范 —— 它自己的 `DESIGN.md`「明暗配色」一节写得很明确：

```
背景 #11181b   正文 #e0e3dc   辅助文字 #a6b0b1   分隔线 #536166   琥珀强调 #c5a16b
（另用 panel #202a2f / field #2a363b / 暖棕悬停 #9b7247）
```

与另外三套主题的区别**不只在换色，还在材质** —— 下面三条都是照搬原规范的做法：

| 做法 | 说明 |
| --- | --- |
| **1px 实心细线** | `--card-border` 直接用分隔线色 `#536166`，不再是半透明描边 |
| **构件直角** | 按钮、pill、列表项、封面、可视化区一律 `border-radius: 0`（原规范的按钮就是 1px 描边 + 无圆角）；只有大面板留 2px 免得割裂 |
| **选择用「竖线刻度」而非色块** | 原规范用长短竖线表达选中。所以列表选中项在这里是**左侧黄铜竖条 + 极淡底**，不是整块高亮 |

另外两处细节：数字用等宽字形（`tabular-nums`，时间读数不随数字宽度左右抖）；
封面四角加黄铜直角标记（取景框 / 刻度的意象）。

> **刻意保留圆形的**：播放键、收藏键、圆形滑钮。圆形是"可点"的强提示，
> 而且早先明确要求过暂停键不要方 —— 这里是有意混搭，不是漏改。

实现上换色走 `applyTheme()` 的 `rhine` 分支（改 CSS 变量），
材质差异走 `:root[data-theme="rhine"]` 限域规则 —— 主题名由
`document.documentElement.dataset.theme` 写入，否则只能"干换颜色"。

## 9. B 站缓存提取

用于播放**你本机已缓存**的 B 站音频。

### 9.1 流程

1. 扫描本机 B 站客户端缓存目录（默认路径自动探测，也可手动指定）
2. 解析缓存条目的元数据（标题 / UP 主 / 封面）
3. 把缓存的 `.m4s` 转成可播放副本（去掉自定义头 / 建立硬链接，不重复占用磁盘）
4. 补齐标题、歌手（UP 主）、封面后加入曲库

### 9.2 说明

- 只处理**本机已有**的缓存文件，不发起任何网络请求下载音频
  （只有封面图会按缓存里记录的 URL 取一次并缓存在 `userData\bili_cover`，那只是图片）
- 原始缓存文件不被修改或删除
- 若播放失败，会回退到「读入内存 + blob URL」方式播放

### 9.3 数据管控

剥掉私有头得到的可播放 `.m4a` 属于**派生数据**，因此：

- 副本只写在 `%TEMP%\mp-session-<会话ID>\audio\`，**不再长期驻留在 `userData`**
- 程序退出时整个会话目录被覆盖擦写并删除
- 下次启动由 `ensureAllPlayable()` 从原始缓存路径重新生成，功能不受影响
- 每次提取都记一条本机审计记录（来源文件 + 产物体积）

> 管控细节见 [数据管控与合规](数据管控与合规.md)。

## 10. 封面 3D 档案

在封面区叠一层可旋转的 3D「档案」，并把**拆解 / 重组**做成可玩交互。

### 10.0 先说清楚：`.blend` 不能直接用，用的是它的导出件

压缩包里有两个 Blender 工程（`art/rhine-archive.blend`、`art/archive-assembly.blend`），
但 **`.blend` 是 Blender 的工程文件，运行中的程序读不了它** —— 没有运行时会去解析
`.blend`。正确通路是：Blender 里导出成 `glTF 二进制`（`.glb`），程序加载 `.glb`。

压缩包里已经带了导出好的两个 `.glb`，它们与那两个 `.blend` 场景一一对应
（原项目自己的 `AGENTS.md` 写明：*"通过 Blender MCP 重新生成单体与拆解资产，
保留 `art/internal_architecture.py` 和两个 `.blend` 源场景"*）：

| `.blend` 源 | 导出件 | 用途 |
| --- | --- | --- |
| `rhine-archive.blend` | `archive-cassette.glb` | **单体**：装好的档案（默认视图） |
| `archive-assembly.blend` | `archive-assembly.glb` | **拆解件**：内部结构，22 个节点带部件标签 |

本机没装 Blender，所以无法从 `.blend` 重新导出或做减面 —— 直接用现成的 `.glb` 是
唯一可行的做法（也是原项目的做法）。

### 10.1 拆解 / 重组

点击封面左下角的「**拆解**」，档案会沿 Z 轴分层散开，露出内部六个部件；
再点「**重组**」装回去。「复位」按钮同时把旋转角归零。

拆解动画**完全照抄原实现的规范**，不是自己发明的：

```
原实现（RhineLabUI model-viewer.ts）：
  PARTS = [ {id,depth} … ]                  六个部件，各带一个 depth
  按 userData.assemblyPart 把网格分组         ← 22 个节点每个都带这个 extras
  每帧：group[part].position.z = depth * spread
  spread 用阻尼跟随目标值，速率 5.5

本播放器：同上。spread 0=装好、1=拆开，阻尼速率同样 5.5。
```

| 部件 | 英文 | depth |
| --- | --- | --- |
| 紧固件 | FASTENERS | 2.75 |
| 透明盖板 | OPTICAL COVER | 1.85 |
| 折射环组 | REFRACTIVE RINGS | 0.75 |

两个模型**共用同一个中心偏移**（都按单体的包围盒居中）。各自按自己的包围盒居中会让
拆解时零件整体错位 —— 它们出自同一套 Blender 坐标，必须一起平移。

装好时显示单体、`spread > 0.02` 时换成拆解件。两者在 `spread = 0` 时外形一致，
所以这个硬切换看不出来。

### 10.2 与播放状态联动

转速跟着播放状态走：**播放时正常转（0.30 rad/s），暂停时几乎停住（0.05）**，
用阻尼过渡避免一按暂停就跳。这样 3D 和"正在放歌"这件事产生联系，
而不是自顾自地转。

### 10.3 默认开启策略

**莱茵生命主题下默认开启**（这套主题的封面本来就该是那卷档案）；
其它主题默认关闭。只要用户手动关过一次，就**永远尊重用户的选择**、不再自动打开
（`localStorage.mp_cover3d` 为 `'0'`）。

### 10.4 为什么必须考虑性能

它要在封面区再开一个 WebGL 上下文，而频谱可视化已经占着 GPU。本机是 Intel UHD，
这个项目之前为了帧率折腾过很久（见 [架构说明](架构说明.md)），所以：

| 措施 | 说明 |
| --- | --- |
| 按需加载 | three.js + GLTFLoader + 两个模型共约 7.4 MB，**只有开启时才注入**，不开启一行都不加载 |
| 启动延迟 | 若上次是开启状态，等首屏渲染完 1.5 秒再加载，避免抢启动带宽 |
| 限帧 30fps | 内部按 `1/30` 秒累积后才渲染；转得慢，看不出差别 |
| 窗口隐藏即停 | 接住主进程的 `win-state`，最小化/隐藏时直接跳过绘制 |
| 像素比封顶 1.5 | 与可视化那边一致，不在核显上按 2x 渲染 |
| 取景只做一次 | 按**单体**包围盒定相机（1.72 倍留白吃掉拆解的增量），拆解途中不重新取景 —— 否则镜头自己缩放会晕 |
| 失败自关 | WebGL 不可用 / 模型读不到 / 脚本加载失败 → 提示一次并自动关闭，封面回 2D |

### 10.5 渲染与素材要点

- **透明底叠加**：`alpha: true` + `setClearAlpha(0)`，画布不遮住底下的专辑封面，
  档案像浮在封面之上
- **材质配色照抄原项目**：两个模型都没有贴图（合计 39 个材质、约 16.9 万三角形），
  材质名与 RhineLabUI `theme-material.ts` 里的 `surfaces` 表一一对应
  （`Frosted_Polymer` `#626b70`、`Optical_Diffuser` `#192226`、
  `Amber_Optical_Inlay` `#c6a36b` …），所以直接沿用那套配色，
  未知材质再按名字兜底，保证不会渲染成纯白
- **为什么锁 three r147**：页面跑在 `file://` 下，**ES module 会被 CORS 拦**，
  所以不能用现代 three.js（ESM-only），必须用 classic script（UMD）。
  r147 是最后一个同时提供 `build/three.min.js` 与 `examples/js/loaders/GLTFLoader.js` 的版本
- **为什么必须走 IPC 读模型**：同样是 `file://` 限制 —— Chromium 禁止
  `file://` 页面对本地文件发 XHR/fetch，`GLTFLoader.load()` 会直接撞 CORS。
  所以由主进程读字节、渲染进程 `loader.parse()`。该通道**只读且只放行白名单文件名**
  （不接受任意路径），遵守[数据管控](数据管控与合规.md)里那条结构性保证

### 10.6 与主题的关系

3D 档案在**四套主题下都可用**，但模型的材质配色固定用 RhineLabUI 那套
（因为材质名就是它的材质体系），不跟随主题换色。
