# 维护指南

回答一个具体问题：**改了代码之后，怎么保证文档和更新日志也跟上？** 三层的答案：一张对照表（改什么要动哪些文档）、一个检查器（忘了改会失败）、一个发布脚本（把检查变成发版流程里过不去的一步）。

## 1. 一条命令走完发布

```powershell
.\scripts\release.ps1 -Bump patch      # 修 bug
.\scripts\release.ps1 -Bump minor      # 加功能
.\scripts\release.ps1 -Bump major      # 破坏性变更
```

按顺序做：

```
1. 检查工作区是否干净（有改动会问你是否先提交）
2. 计算新版本号，并校验它确实比当前版本大、标签没被占用
3. ★ 检查 docs\更新日志.md 里有没有新版本的段落
     —— 没有就生成骨架并**停下**，等你写完再跑一次
4. 写入 app\package.json 的版本号 + README 顶部的「当前版本」
5. 跑三套验证：文档一致性 / 数据管控 / 设置持久化（任一失败就中止）
6. 构建便携版
7. git commit + 打附注标签 vX.Y.Z
8. 推送分支与标签（走 push-to-github.ps1，自带受限网络适配）
```

**关键在第 3 步和第 5 步**：更新日志没写、或文档跟代码不一致，发布就进行不下去。所以「忘了改文档」不会变成一个悄悄溜进远端的提交，而是变成一个当场报错。

第一次跑 `-Bump patch` 时它会生成骨架然后退出（脚本没法替你写变更说明）：

```
    docs\更新日志.md 里没有 [1.1.3] 段落
已经生成骨架，请把内容写实。写完更新日志再跑同样的命令就会继续往下走：
    .\scripts\release.ps1 -Version 1.1.3
```

此时 `-Version` 指定同一个号，脚本会跳过递增。

### 参数

| 参数 | 说明 |
| --- | --- |
| `-Bump` | `patch` / `minor` / `major` |
| `-Version` | 显式指定版本号，例如 `1.2.0` |
| `-Message` | 提交信息；不指定时从更新日志的「主题」那行自动生成 |
| `-NoPush` | 只到打标签为止 |
| `-NoBuild` | 跳过构建（只改文档时用） |
| `-Yes` | 不再交互确认 |

## 2. 只跑检查（不发布）

```powershell
node scripts\文档一致性验证.js
```

任何时候都可以跑，几毫秒出结果。它检查 16 项：

| 组 | 检查内容 |
| --- | --- |
| 1 | `app/package.json` 的版本号在更新日志里有 `## [x.y.z]` 段落，且段落有实质内容（不是占位） |
| 2 | README 顶部「当前版本 vX.Y.Z」与 `package.json` 一致 |
| 3 | 更新日志的版本号严格从新到旧排列、没有重复 |
| 4 | README「项目结构」提到了**每一个受版本管理的顶层条目** |
| 5 | README「项目结构」提到了 `scripts\` 与 `docs\` 下的**每一个文件**（反向也查：结构图里不许有仓库里不存在的文件） |
| 6 | README「文档」小节的链接都有效 |
| 7 | README 与 `docs\*.md` 里所有相对 Markdown 链接都能解析到真实文件 |
| 8 | 当前版本已有 git 标签、每个标签都有对应的更新日志段落（WARN 级） |

第 5 组最容易漏：新加了脚本或文档，忘了写进 README 的结构图。

> 检查器**故意不调用 git 子进程** —— 有些受限环境禁止 Node 以管道方式 spawn（表现为 `spawnSync git EPERM`），那样检查会静默退化。改成直接遍历文件系统、直接读 `.git\refs\tags` 与 `.git\packed-refs`，到哪都能跑出一样的结果。

### 2.1 版面遮挡怎么查（改过任何绝对定位的尺寸 / 位置之后）

面板都定位在固定的 **1920×1080 舞台**里（`#stage` 再整体 `transform: scale()`），所以"谁压住谁"是**算得出来**的，别靠眼睛看截图：

```powershell
node scripts\探针\版面探针.mjs                                  # 生成 app-rhine\dist\_layout.html
node scripts\探针\观测服务.js app-rhine\dist                    # 起服务（固定 41888，输出会打印回传的读数）
# 另开终端用无头浏览器打开下面任一个地址（--virtual-time-budget 给 20000）：
#   http://127.0.0.1:41888/_layout.html?scene=detail                        详情模式
#   http://127.0.0.1:41888/_layout.html?scene=archive&modal=settings        档案模式 + 设置弹窗
```

探针列出每块面板的矩形（已归一化回 1920×1080 基准），并算出**所有可见块两两之间的重叠面积**。读法：

- 只有"弹窗 × 背景元素"那一类是预期的（弹窗本来就该盖住背景），其余重叠都算缺陷
- `[不可见，不参与重叠统计]` 的块用 `checkVisibility` 判（会看整条祖先链的 opacity）—— 档案阵列与详情面板靠父容器 `opacity: 0` 收起，只看元素自己的 computed opacity 会误报
- 弹窗那行还会报 `可用高 / 内容高`，内容高于可用高时**必须**有 `overflow-y: auto`，否则会溢出到面框外去盖住播放条

无头浏览器用 Edge（`msedge.exe --headless=new`），3D 场景要加 `--use-angle=swiftshader --enable-unsafe-swiftshader`，否则页面初始化失败、量到的全是初始状态；完整参数照抄 `scripts\探针\渲染快照.ps1`。三个坑：不要把 stderr 重定向到文件（受限环境禁止管道 stdio，浏览器起不来且毫无输出）；别用 `--dump-dom`（页面的 rAF / WebGL 循环永远不会空闲，实测挂死两分多钟）；每次换全新 `--user-data-dir`（上一轮残留的无头进程会接管新实例并立刻退出）。

## 3. 改什么 → 要同步改哪些文档

| 改动 | 必须同步 |
| --- | --- |
| **任何版本发布** | `docs\更新日志.md` 新段落（写清主题 + 新增/变更/修复） |
| 改版本号 | `app\package.json`、`README.md` 顶部「当前版本」、更新日志段落 —— 这三处由 `release.ps1` 自动同步 |
| 加/删/改 `scripts\` 下的脚本 | `README.md` 的「项目结构」区块；用法变动还要改 `docs\构建与安装.md` |
| 加/删 `docs\` 下的文档 | `README.md` 的「项目结构」+「文档」小节 |
| 加/删仓库顶层文件 | `README.md` 的「项目结构」 |
| 新增用户可见功能 | `README.md` 的「特性」、`docs\功能说明.md`、更新日志 |
| 改快捷键 | `docs\快捷键.md`、`README.md` 的快捷键表、更新日志 |
| 改 UI 布局 / 交互 | `docs\功能说明.md`（§11.1 有各面板的定位数值、以及"版面遮挡的三条硬约束"）、必要时 `docs\架构说明.md`；**改完必须跑一遍 §2.1 的版面探针** —— 绝对定位的界面凭肉眼看截图发现不了几十像素的压边 |
| **改音频链路**（`ensureAnalyser` / `ensureCtx` / `<audio>` 属性 / B 站音源装载） | `docs\架构说明.md` §4.0 —— 那里写清了"为什么分析必须接 destination""为什么 `AudioContext` 要无参构造（传 `sampleRate: 0` 会抛错）""为什么 B 站音源必须走内存读取（`file://` 被拦）"；**别只改代码** |
| 改主题 / 强调色 | `docs\功能说明.md` §8.1（含「跟随封面」一节）、更新日志 |
| **改频谱观感**（`spectrum.ts` 的抖动 / 鼓点 / 瞬态 / 量化 / 顶边形态） | `docs\功能说明.md` §5.3（参数表）、§5.5（鼓点响应：低频泵动 + 宽带瞬态强调）、§5.6（顶端张力与形态）、更新日志；**并跑 `node scripts\频谱离线观测.mjs 12 --bpm=160`** —— 它会量出**纯张力落差/周期**（幅度与频率是两个独立读数）、顶端锯齿度、方块占比、密集鼓点命中率与**瞬态保真度**（三种敲击各抬哪半区），改观感必须看读数而不是凭感觉 |
| 改频谱的**分析实现**（`analyze` / Worker 源码字符串） | 注意 `spectrum.ts`（同步）与 `player.ts`（Worker）是**两份实现**：Worker 的源码由 `player.ts` 从 `SPECTRUM_*` 常量插值生成，改常量会同时生效，但**加新逻辑必须两边都写** —— 见 `docs\功能说明.md` §5.5.2 末尾 |
| 改主进程开关 / 性能相关 | `docs\架构说明.md`（那里记着每条 Chromium 开关的**原因**，别只改代码） |
| 改数据落盘 / 解密 / 缓存位置 | `docs\数据管控与合规.md`、更新日志；并跑 `node scripts\数据管控验证.js` |
| 改设置项的存取 | 跑 `node scripts\设置持久化验证.js`（会校验键名成对、恢复闸门与滑块范围一致） |
| 改构建方式 / 依赖 Electron 版本 | `docs\构建与安装.md`、`README.md` 的「构建」 |
| 改推送流程 | `docs\构建与安装.md` 第 6 节、更新日志 |
| 修一个 bug | 更新日志的「修复」；**如果是坑，把原因写进代码注释**（见下） |

## 4. 写更新日志的约定

每个版本一个 `## [x.y.z] — 年份` 段落，含「主题 / 新增 / 变更 / 修复」四段：

```markdown
## [1.2.0] — 2025
**主题：** 一句话说清这个版本干了什么。
### 新增
- 面向用户的新能力
### 变更
- 行为/接口/默认值的变化（**破坏性变更要标注**）
### 修复
- 修了什么、**根因是什么**
```

两条经验：**修复条目要写根因，不只是现象。** 例如不要只写"修复鼓点不响应"，要写"低频参考值 `kickRef` 只在首次赋值后不再更新，导致 kick 饱和到 1.0，乘性泵浦失效"——半年后回看，根因才是有用的信息。另外**段落不能只有标题**，检查器会把内容过短的段落判为占位并报错。

## 5. 代码注释与提交信息的约定

代码注释统一解释**为什么**，而不是**做了什么**。踩过的坑要在代码里留痕，否则将来有人"好心"改回去：

```js
/* 键名必须是 mp_kick：滑块写入的就是 mp_kick。这里曾写成 mp_kick2，而 mp_kick2 从来没被写入过
   → 每次重启都读不到，鼓点强度静默回到默认 0.40。 */
```

已有的例子散落在 `app\main.js`（Chromium 开关的原因）、`app\index.html`（可视化参数来历）、`scripts\*.ps1`（cmd/chcp、BOM、stderr 的坑）。

提交信息用带类型前缀的简短中文描述：`feat(vX.Y.Z):` 新功能 / 新版本、`fix(vX.Y.Z):` 修 bug、`chore(vX.Y.Z):` 工程脚本工具链、`docs:` 只改文档。`release.ps1` 不指定 `-Message` 时会自动拼成 `release(vX.Y.Z): <更新日志里的主题>`。

## 6. 写 PowerShell 脚本的五个坑（都是真踩过的）

### 6.1 含中文的 `.ps1` 必须存成 UTF-8 **with BOM**

5.1 读无 BOM 的 UTF-8 文件会按 ANSI/GBK 解码，中文里可能出现被误认成引号或反引号的字节，于是报出「字符串缺少终止符」这类语法错误，而文件内容看起来完全正常。补 BOM：

```powershell
$p = 'scripts\xxx.ps1'
$t = [System.IO.File]::ReadAllText($p, (New-Object System.Text.UTF8Encoding($false)))
[System.IO.File]::WriteAllText($p, $t, (New-Object System.Text.UTF8Encoding($true)))
```

反过来 `.md` / `.json` **不要**加 BOM（GitHub 和 git 都不喜欢）。

### 6.2 `Get-Content -Raw` 读不了无 BOM 的 UTF-8 文本

同一个编码问题，但更隐蔽：**不报编码错，只是内容悄悄变成乱码**。`package.json` 里的中文描述被破坏后 `ConvertFrom-Json` 直接失败；README 里的 `**当前版本 vX.Y.Z**` 匹配不到 → 表现为「版本号没被写进去」。脚本里统一用 `Read-Utf8()`：

```powershell
function Read-Utf8([string]$p) { [System.IO.File]::ReadAllText($p, [System.Text.Encoding]::UTF8) }
```

### 6.3 变量名不区分大小写 —— `$A` 和 `$a` 是同一个变量

错的写法里 `$A` 与参数 `$a` 同名，`$a` 声明为 `[string]` 后数组赋回去被静默转成字符串 `"1 1 3"`，`$A[2]` 取到的是字符 `'1'` 而不是数字 3 —— 于是版本比较恒等于 0，完全看不出和命名有关。参数名与局部名必须取得完全不一样：

```powershell
# 错
function Compare-Ver([string]$a, [string]$b) { $A = $a.Split('.') | ForEach-Object { [int]$_ } ... }
# 对
function Compare-Ver([string]$Left, [string]$Right) { $verL = @($Left.Split('.') | ForEach-Object { [int]$_ }) ... }
```

### 6.4 原生命令写到 stderr 会被 `EAP=Stop` 当成致命错误

`git` 把警告和进度都写在 stderr（`.gitattributes` 引起的 `LF will be replaced by CRLF`、推送时的 `To https://...`），`node` 失败时也写 stderr。脚本里 `$ErrorActionPreference = 'Stop'` 时这些会让 PowerShell 直接中断，看起来像"`git add` 把发布流程搞崩了"。所有外部命令都走封装，临时放宽 EAP 并自己判退出码：

```powershell
function Invoke-Git {
    param([Parameter(ValueFromRemainingArguments = $true)][string[]]$GitArgs)
    $old = $ErrorActionPreference
    $ErrorActionPreference = 'Continue'
    try { $out = @(& git @GitArgs 2>&1); $code = $LASTEXITCODE }
    finally { $ErrorActionPreference = $old }
    return [pscustomobject]@{ Code = $code; Text = ($out -join "`n") }
}
```

另外 5.1 的 `$ErrorActionPreference` **不覆盖原生命令的退出码**，必须显式检查 `$LASTEXITCODE`，否则推送失败也会打印"推送成功"。

### 6.5 `.bat` 里不要出现中文，也不要在 `chcp` 附近放多字节字符

`cmd.exe` 切换代码页后按**切换前的字节偏移**重读批处理文件，多字节字符会让它切到半个字上，把 `rem` 注释行解析成命令并报错。`.bat` 一律存成**纯 ASCII**，中文交给它调用的 PowerShell 脚本去输出。

## 7. 常规节奏

```powershell
.\scripts\release.ps1 -Bump patch     # 1. 改代码（app\ 下）→ 2. 想发版 → 3. 若提示补更新日志，补完再跑一次

node scripts\文档一致性验证.js        # 平时只想确认文档有没有漂

node scripts\数据管控验证.js          # 改了数据管控或设置存取相关的代码
node scripts\设置持久化验证.js
```
