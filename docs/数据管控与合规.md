# 数据管控与合规

本文档说明本程序对**派生数据**（从受限格式里解出来的音频）采取的管控措施，以及仍然存在的边界。

---

## 1. 什么是「派生数据」

本程序不含任何在线音源，不会下载任何内容。它能从两种受限容器里解出音频：

| 来源 | 操作 | 派生数据 |
| --- | --- | --- |
| 网易云 `.ncm` | 解密（AES-128-ECB / ncmdump） | mp3 或 flac 字节 |
| B 站客户端缓存 `.m4s` | 剥掉私有头，得到标准 MP4 容器 | 可播放的 m4a 副本 |

这两类派生数据受原平台版权与用户协议约束，一旦被随手复制出去就成为非法传播源。因此程序要让「顺手传播」变得困难，并让「发生过什么」可被追溯。

---

## 2. 三层管控措施

### 2.1 第一层：最小落盘

| 措施 | 说明 |
| --- | --- |
| 解密结果只在内存中传递 | 从不写入你的音乐目录 |
| 音频只存在于会话专属临时目录 | 每次启动重新生成，退出即整体销毁（含崩溃残留，下次启动清扫） |
| 读完立刻擦除 | 解密子目录在字节读回内存后立即覆盖擦写并删除，不等垃圾回收 |
| **本地保留副本**（2.2.0 起） | 导入 B 站缓存时另存一份到曲库音频目录，跨启动长期保留：迁走或删掉缓存文件夹后仍可播放。源缓存仍在时优先用会话副本。占用在设置面板「LOCAL AUDIO COPIES」可见 |
| 临时目录带隐藏属性 | 阻止「顺手翻到并拷走」 |
| 覆盖写零后删除 | 先用 0 覆盖整个文件并落盘，再删除 |
| 硬链接保护 | 遇到被多处引用的文件只摘目录项、绝不覆写——覆写会透过硬链接把别处那份一起毁掉 |
| 派生副本必须是独立文件 | 一律复制出独立副本，不做硬链接 |
| 升级清理 | 启动时擦除旧版本遗留的长期副本，只删本程序生成的副本，不碰你的缓存原文件 |

覆盖写零只是提高恢复门槛的威慑手段：SSD 的磨损均衡与 TRIM 使彻底擦除无法在软件层保证。真正的保底是根本不长期落盘，也就是会话目录这一层。唯一的长期落盘是曲库音频目录里那一份，这是用户在「迁走缓存后还能播」和「派生副本不驻留」之间选择了前者：它是标准 m4a（不含用户名、链接等元数据），只占音频本身的大小，删掉对应曲目后不再被引用，也可直接删掉整个目录，曲库条目会退回「从源缓存现做副本」。

### 2.2 第二层：不可导出

程序不提供任何「导出 / 另存为 / 分享」能力，并且从接口层面就做不到：

- 所有内部接口中，没有任何一个接受「输出路径」参数——都是「读进来」，不是「写出去」
- 界面层不暴露任何写文件方法，也拿不到文件系统权限
- 派生数据在界面层只作为内存对象存在，随页面生命周期结束而释放

这条保证是结构性的：不是「没做这个按钮」，而是没有可用的路径能把字节写到磁盘。

### 2.3 第三层：可追溯

每次解密与提取都会向本机审计日志追加一条 JSON 记录：

```json
{"t":"2026-09-22T13:41:07.812Z","v":"1.1.0","sid":"a1b2c3d4e5f6",
 "event":"ncm-decrypt","result":"ok:exe","bytes":9241837,"ext":"mp3"}
{"t":"2026-09-22T13:42:19.004Z","v":"1.1.0","sid":"a1b2c3d4e5f6",
 "event":"bili-extract","src":"D:\\...\\32707317016-1-30280.m4s","bytes":1617712,"ext":"m4a","result":"ok"}
```

| 字段 | 含义 |
| --- | --- |
| `t` | UTC 时间戳（ISO 8601） |
| `v` | 产生该记录的版本号 |
| `sid` | 会话 ID —— 同一次运行的所有记录可归组 |
| `event` | `ncm-decrypt` / `bili-extract` / `bili-scan` |
| `result` | `ok:exe` / `ok:builtin` / `failed` / `rejected:not-ncm` |
| `src` | 来源文件路径（**仅本机**，用于回答「这条数据是从哪来的」） |
| `bytes` / `ext` | 产物体积与格式 |

- 上限 **500 条**，超出自动裁剪最旧的
- 设置面板 →「数据管控」一行显示当前条数，点「清日志」一键清空
- 审计文件只在本机用户数据目录下，程序从不外发、不上传

### 2.4 输入侧限制

- 解密前先校验容器魔数，不是真正的 NCM 直接拒绝，使它不是一个「拿任意文件来试解的通用解密器」
- B 站缓存提取只处理本机已存在的缓存文件，全程不发起任何音频下载请求（仅封面图会按缓存里的 URL 取一次并本地缓存）
- 原始缓存文件与 `.ncm` 源文件从不被修改或删除

## 3. 程序内可见性

管控措施在 ⚙ 面板中可见：

- **「数据管控」行**：显示 `内存解密 · 会话级临时目录 · 无导出 · 审计 N 条`；悬停可看到完整说明与审计文件路径；旁边的「清日志」按钮一键清空审计
- **「版本」行**：显示当前程序版本号
- **首次启动告知弹层**：完整列出管控措施与使用边界，需点「我已了解」才消失，只在首次启动出现一次

## 4. 自动化验证

管控措施是可回归验证的，不是口头承诺：

```powershell
node scripts\数据管控验证.js app
```

覆盖 16 项断言：

| 组 | 验证内容 |
| --- | --- |
| 落盘位置 | 副本确实落在会话目录、不在用户数据目录、文件真实可读 |
| 擦除逻辑 | 擦除前能读到明文标记 → 擦除后文件与目录都消失；递归擦除生效；被多处引用的文件擦除后源文件内容一字不变 |
| 陈旧清扫 | 上次残留的会话目录被清掉 |
| 静态断言 | 魔数校验存在；无 write/save/export 类接口；提取音频走会话目录；退出销毁会话目录；存在升级清理；界面层不暴露写文件方法 |

其中擦除逻辑不是另写一份复制品来测，而是从主程序源码里摘出擦除实现再执行，所以测的是即将发布的真实代码。

## 5. 使用边界（用户责任）

> 请仅将本程序用于**个人本地播放**你已合法获得的内容。
> 解出的音频受原平台版权约束，**请勿传播、分发或用于任何商业用途**；
> 由此产生的法律责任由使用者自行承担。

管控措施降低了「误传播」的可能，但不能替代用户自身的合法使用义务——任何具备本地文件读取权限的程序都无法阻止你手动复制文件到别处。本程序能做的是确保自己不成为传播链条的一环（不落盘、不导出、不分享），并让每一次派生产生都可追溯。

## 7. 已知边界

| 边界 | 说明 |
| --- | --- |
| 覆盖擦除不保证取证级不可恢复 | SSD 磨损均衡 + TRIM 下无法在软件层保证；保底手段是「不长期落盘」 |
| 封面图仍缓存在用户数据目录 | 封面是图片，不是音频；缓存可避免每次重新下载。如需清理可直接删除该目录 |
| 审计日志含本机文件路径 | 目的是回答「这条数据从哪来」；只在本机，且可一键清空 |
| 无法阻止手动复制 | 会话目录在程序运行期间必须存在（播放器要读它），运行期手动拷贝无法阻止 |
| 内存中的字节无法控制 | 播放期间派生数据必然存在于进程内存，这是任何播放器的固有前提 |
| **历史版本曾损坏两个用户缓存文件** | v1.1.0–v1.1.3 存在「硬链接 + 覆盖擦除」缺陷，会就地毁掉部分源文件。v1.1.4 已修复；**已损坏的文件无法由本程序恢复** |
