# 版本说明

当前版本 **v2.7.8**（2026-10-14）｜[完整更新日志](更新日志.md)｜[功能说明](功能说明.md)

本软件是一款运行在 Windows 平台上的桌面音乐播放器。程序只专注于本地音频文件的读取与解码播放，不包含任何形式的在线流媒体音乐源，因此不会产生网络串流请求。

**播放与视觉交互**
  - 内置本地曲库管理功能，并配备团队自行开发的音频频谱可视化动效。
  - 提供跟随歌曲进度逐行高亮滚动的歌词页面。

**窗口与外设控制**
  - 配备可悬浮显示在全屏游戏画面上方的独立迷你窗口。
  - 支持响应耳机线控按键与键盘系统多媒体键的外部控制。

## 这一版改了什么

### 参数复刻修复：存档升 v2，旧档一次性迁移

用户提出需求："参数也要复刻"。

经过排查确认，打包出的 exe 内部生效参数未与 SelfMusic 调试数值对齐，根源在于本地存档机制而非出厂默认配置。当前环境下的 `localStorage['rhine-sm-display']` 仍残留 v2.7.5 写入的历史旧数据，其中有 12 项配置与 SelfMusic 面板不一致；由于原有逻辑中老存档优先级高于代码中的"出厂默认档"，导致设定的默认值被旧数据全量覆盖，渲染画面始终沿用旧参数。

针对该问题，本版通过存档结构升级与执行时机调整彻底解决了覆盖异常，并完成了全链路验证：

**架构改造与迁移逻辑**
  - 存档数据结构升级至 v2 版本，格式规范为 `{ v: 2, values: {…} }`。
  - 读取到 v1 旧档时触发一次性迁移，不再沿用历史旧值，直接使用实测档参数全面覆盖并立即写回本地存储。
  - 迁移时机提前至程序启动时立即执行，不再等待频谱渲染引擎初始化时才读取存档。

**验证结果**
  - 使用真实用户目录直接启动编译产物 exe，确认本地存档成功升级至 v2 结构，16 项参数完全与实测档对齐。
  - 重新运行自动化测试脚本 `_滑块验证.cjs` 跑通全链路，指标表现正常（head +48.9% / smooth −82.9% / RESET 干净）。
### 视觉重心：四方案对比出图（待定档）

用户此前提出的两点视觉反馈（"左侧的峰可以稍微右移一点" 以及 "视觉重心太靠左，左比右大约 6:4"），在数据层面上已经得到了确凿的验证。

**现状数据与归因**
我们统计了真实音乐在 79 帧内的具体表现，测得 **左:右 ≈ 6.5 : 3.5**，代表整个画面能量分布中心的质心位置处于 40.8%（该数值为中位数，按定义 50% 处于正中央）。画面呈现「左重」的核心原因，在于左半部分（低频区）分布着整片如『地毯』般持续偏高的柱体；单纯横向平移带来的改善相当有限，即使整体向右平移 8 格，能量比例也仅微调至 5.7:4.3。

**对比验证方案**
我们在 `dist\视觉重心对比.html` 中提供了横向效果对比（测试集包含三组场景 × 四方案，且每帧均标注了实时的 左:右比 与 质心位置）：
  - 基础对照组：保留现状，或仅做基础的平移 4 格。
  - 循环移位 8 格：左端保持充实不留白且不丢失内容，代价是被卷回最左侧的超高音区在视觉上闪烁变换更快。
  - 平移 4 格 + 右半渐强 ×1.6（软钳）：典型帧下表现最均衡（能量比 5.5:4.5，质心位于 46.4%），代价是右半侧柱体高度被人为放大显示。

待方案最终选定之后，我们会把对应的计算逻辑正式落实到显示层的前处理流程当中。

### 上一版（2.7.7）：频谱与算法，全部换成 SelfMusic 的

用户："将频谱，算法全部换为 SelfMusic 的"。

在先前的两个版本里，系统虽然已经把 SelfMusic 的引擎内核、16 项可调显示层以及取数活路径做到了逐位对齐，但渲染管线中依旧残留着两段来自本项目的旧代码。一段是界面绘制层仍然沿用着本仓库 1.3.0 版本的 Canvas 渲染逻辑，包含 14 级量化分桶、顶端补抖、绘制插值、五种样式和节拍先验驱动；另一段则是旧算法的整条执行链路，保留了算法档开关、运行在 Web Worker 中的 120 段 Goertzel 算法以及整套旧版调音参数体系。本次更新将这两段冗余代码彻底移除，使得频谱渲染与计算完全收敛到 SelfMusic 原版这一条逻辑线上。

#### 画面重构：照 `visualizer.py` 直译

画面布局与着色规则完全按原版脚本重构，并动态适配面板缩放：

  - 柱体计算改为严格贴合底部，高度公式直接采用 v×(画布高−8)；柱宽固定设为每个槽位宽度的 0.70 倍，画布左右两侧各自预留 6px 边距。
  - 柱体数量从先前的 150 根回退到音频引擎原生的 96 根直画模式，移除了中间的重采样环节，视觉宽度因此放宽约一半；画面涉及的 6、8、2、3 像素等绝对尺寸，均会随画布实际缩放比例动态换算。
  - 不透明度不再使用 14 级分桶，改为每根柱子单独计算（公式固定为 α = 0.45 + 0.55×柱高）；竖向线性渐变严格落在 0、45% 与 100% 三处，呈现亮色、主色与底色。
  - 位于柱顶上方的 2px 峰值顶盖，仅在峰值大于 0.004 时触发绘制，并联动客户端主题（浅色匹配墨色顶盖，深色匹配白色顶盖）。
  - 画面左上角补充了鼓、低音、人声与镲共四路音色指示条，用于直观显示当前瞬间大幅推高的频段。

#### 算法收敛与预分析降级

移除了所有旧版定制分支与补偿手段，计算链路保持单一纯净：

  - **算法侧只留一条路**：清理算法档开关与负责 120 段 Goertzel 运算的 Web Worker 线程；移除 mix、timbre、bars、ring、wave 五种样式，以及绘制插值、顶端补抖、节拍先验驱动与旧版调音参数结构；音频分析节奏周期固定为 16ms，窗口长度固定为 4096 点。
  - **节拍预分析（BEAT PRE-ANALYSIS）默认关闭**：早期用于鼓点提前 28ms 响应、每 4 拍切形态及副歌预热的补偿逻辑全部停用，以确保 SelfMusic 频谱波形的确定性逐位还原；设置项仍保留，手动开启时仍会后台分析并写入缓存，但默认不再自动调用。

#### 怎么证明"就是原版那套"

测试流程新增了两道明确拦截异常的断言检查，以验证与原版的绝对一致性：

  - **绘制层对拍**：通过正则解析 `visualizer.py` 提取关键常量与几何公式，与运行时绘图指令逐一核对，覆盖柱体坐标、宽高、贴底状态、独立透明度、顶盖尺寸、渐变点及四路指示条轨道与填充宽度等共 72 个比对项，全部达成 `max|Δ| = 0`。
  - **产物 exe 像素对拍**：启动打包后的 exe 程序并输入固定柱高帧回读像素，96 根柱子的顶部位置、贴底效果、顶盖间距及指示条坐标等 10 项测量指标均精确命中；同时修复了柱体循环绘制后未执行 `p.setOpacity(1.0)` 导致指示条变暗的隐蔽缺陷。

### 上一版（2.7.3）：保峰——融合之后把原来的峰还回来

（保留铺散版的 81%）、最高柱 0.796 → **0.845**（回到铺散版水平）。验收图与定档对比图逐字节相同。

  - 孤立高柱在全部数据中的占比从 14% 压低至 3%。
### 上一版（2.7.1）：顺带修好的三处"新算法与旧装饰打架"

当音频分析算法切换到 SelfMusic 档位后，负责画面输出的渲染层依然残留着旧版流水线沿用下来的视觉装饰逻辑，导致界面出现渲染冲突。本次更新将这些遗留代码逐一拆除：

**柱体形态修正**
以下调整解决了频谱柱本身的高度计算与顶部结构冲突：
  - 修复断柱现象：频谱柱的实际高度改为直接按照计算出的真实数值绘制，解决了旧逻辑强行拆分高度导致多达 42% 的柱体断裂成两截的渲染异常。
  - 移除假尖装饰：彻底移除额外叠加在顶部的尖峰图层；由于新算法已包含高频能量离散化处理，去除旧装饰避免了柱顶反复出现不自然的重复突起。

**附着装饰优化**
针对柱体外部悬浮元素的渲染逻辑进行了清理：
  - 优化浮空碎屑：调整峰值指示线（标记音频瞬间最高能量位置的浮动横线）的触发逻辑，仅在明显高于并脱离柱顶时绘制，避免此前未脱离时全部 150 根柱子中多达 104 根同时绘制该线条、堆积成杂乱碎屑的问题。
### 上一版（2.7.0）：延迟更低、帧率更高、动态对比更极端

这里针对三个参数做联合调整，整体目标是让频谱图的视觉反馈更贴合音频节奏，在听感与画面之间形成更强烈的打击感。主要改进集中在时延与渲染表现，以及瞬态动态响应两个维度：

**时延缩减与渲染帧率提升**
  - **窗口尺寸与系统延迟**：傅里叶变换的分析窗口长度（即单次处理采样的音频点数）由 1024 点压缩至 512 点，系统从采集信号到完成屏幕绘制的固有开销缩减约一半（实测耗时由约 10.7 毫秒降至约 5.3 毫秒）；技术代价是频率分辨率有所下降，低频区域最细的柱子易受临近频率干扰而出现轻微抖动。
  - **渲染机制与刷新帧率**：音频播放过程移除了固定的时间间隔节流限制，渲染循环改为与显示设备垂直刷新率同步以匹配高刷屏幕特性。实测绘制帧率由 41.6 fps 提升至 85.3 fps，画面刷新间隔时间中位数由 24 毫秒缩短至 12 毫秒，画面顿挫感明显减轻。

**动态对比与瞬态反馈算法**
  - **瞬态响应曲线重调**：打击乐等突发瞬态信号进入时，对应频段能量柱上升更快、冲得更高并在冲击后快速回落，平稳声音段落柱体则基本维持原状；处理放大了动静对比以增强鼓点等强节奏的弹性，且修改仅作用于动态过渡阶段，稳态频谱包络形状完全不受影响。
### 上一版（2.6.0）：鼓点跟上了画面

旧版本的频谱完全依赖即时音频输入，属于“听到声音才开始响应”的被动机制。短时傅里叶变换这类频域分析窗口自身带有二十几毫秒的固有延迟，音频数据在传输、解析与界面渲染链路中流转后，画面输出总是比耳朵听到的声音慢半拍，无论用户怎么调整缓冲或平滑参数，都无法消除这种音画不同步的迟滞感。

2.6.0 调整了技术方案，改为在音频正式播放前先在后台完成整首歌曲的离线预分析。算法会测算出整首歌的 BPM（每分钟节拍数，即音乐速度），精确定位出每一个节拍点的时间戳，并计算出每一拍对应的能量强度。

**视觉呈现优化**
本版本基于预分析生成的时间轴，对渲染节奏与动效触发机制进行了重构：
  - 系统在实际鼓点发声前 28 毫秒提前触发画面高亮动效，并在检测到副歌片段即将切入时提前完全打开渲染动态范围，避免高潮乐段爆发时的生硬削顶跳变。
  - 频谱柱体的视觉形态固定为每 4 拍切换一次，使动画节奏严格对齐音乐小节，不再只是被动跟随时域信号晃动。

**后台性能与配置控制**
预分析任务在保障执行效率的同时提供了灵活的控制选项：
  - 任务采用单曲单任务队列在后台静默运行，处理 4 分钟常规歌曲仅需约半秒，计算生成的节拍特征数据会被持久化保存，二次播放直接复用缓存。
  - 设置面板中新增了「节拍预分析」一行，实时显示当前歌曲的 BPM 与拍点数，用户也可以手动将其关掉。
### 再往前（2.5.0）

- 歌词高亮放大（普通行 16 px、高亮行 22 px）
- 频谱回落更干脆（峰值指示线拖尾从 1.5 秒收紧到 420 毫秒）
- 详情区与弹层的磨砂玻璃质感

## 播放器能做什么

### 播放与曲库

| 能力 | 说明 |
| --- | --- |
| 导入 | 选文件、选文件夹（递归）、直接拖到窗口 |
| 格式 | mp3 / flac / m4a / aac / wav / ogg，以及网易云 `.ncm` |
| NCM | 自动解密为 mp3 / flac，保留完整标签与封面 |
| B 站缓存 | 播放条上的电视图标，选本机缓存目录后按音频内容识别并补齐标题、UP 主、封面 |
| 播放模式 | 列表循环 / 顺序 / 单曲循环 / 随机 |
| 倍速 | 0.5× ~ 2.0×，保音调，变速不变声 |
| 续播 | 关掉再打开，回到上次那首歌和那个位置 |
| 队列 | 「下一首播放」插队，可拖动排序 |

### 歌词

播放器支持读取音频同名外部 `.lrc` 文件与内置内嵌歌词，自动识别 UTF-8 与 GBK 编码防止乱码。若当前曲目未精确匹配到歌词，程序会自动扫描同级目录检索歌名相似的文件。

界面随播放进度逐行向上平滑滚动并高亮当前句，原词下方同步显示翻译行。右侧内容面板支持在滚动「歌词」与「可视化」图表间切换，软件会自动记住当前选择。

### 可视化

自研音频频谱分析器将 FFT 频域变换计算完全交由后台 Web Worker 独立执行，不占用界面渲染主线程资源。

**频段映射与动效反馈**
  - 采用贴近人耳听觉的对数频率分带算法，将信号拆解至 120 条柱体，解决低频到高频细节堆叠在最左侧的问题。
  - 遇到强烈鼓点下潜时整排柱体产生受力弹跳，并激发由右向左平滑传递的行波物理动效，避免画面杂乱抖动。

**预判分析与面板协同**
  - 音频播放前预先扫描全曲节奏鼓点，使视觉效果能在鼓点发声前提前亮起预警，并随乐曲小节规律轮换柱体形态（可在设置中手动关闭）。
  - 右侧面板支持在「可视化」与「歌词」间随意切换，状态自动保存并在下次启动时保持。

### 迷你悬浮窗

点击按钮即可从主窗口分离出轻量级独立悬浮窗。主程序最小化或被遮挡时，悬浮窗内部动效依然保持全速渲染，不掉帧卡顿。

**层级与焦点控制**
  - 悬浮窗层级经过专门优化，可稳定置顶于无边框窗口化游戏上方。
  - 点击操作播放或暂停时系统焦点仍保留在游戏内，避免游戏画面意外最小化或失去响应。

**窗口操作与形态**
  - 支持自由拖拽移动、按比例拉伸缩放及调节整体透明度。
  - 提供窗口位置锁定功能，防止误触移动。

### 主题与外观

**配色方案**
  - 内置深色、浅色、网易云红以及**莱茵生命**四套视觉主题。
  - 界面主强调色支持通过算法自动提取正在播放的专辑封面主色调，也可在设置中关闭该功能并固定单色。

**专属主题特性**
  - 切换至**莱茵生命**主题时默认启用 3D 封面档案展示效果。
  - 3D 模型支持鼠标拖拽旋转视角与分层拆解重组动效，自转速度实时响应音频的播放与暂停状态。

### 系统集成

**硬件控制与监听**
  - 建立双通道统一监听并接管键盘多媒体物理按键及外接耳机硬件线控（涵盖播放、暂停、上一曲、下一曲与停止）。

**冲突排查与备用方案**
  - 设置面板内置媒体键占用状态自检工具，可排查全局媒体键是否被系统其他后台软件抢占。
  - 物理按键被占用失效时，支持无缝切换至软件内部定义的纯键盘热键操作，具体配置请参考 [快捷键](快捷键.md)。

## 已知问题

**界面与控制交互**

  - **媒体键没反应：** 打开设置面板查看「媒体键」状态提示。Windows 系统全局媒体键为独占资源，若显示被占用，说明已被游戏或其他后台播放器抢先绑定，需退出冲突程序或在设置中改用应用内快捷键。
  - **迷你窗在游戏里看不见：** 游戏启用独占全屏时系统会阻止普通窗口覆盖画面；需在游戏画质设置中切换为「无边框窗口 / 窗口化全屏」模式，即可正常悬浮。
  - **装了新版本还是旧界面：** 桌面快捷方式可能指向了系统中的旧版本副本。可直接从开始菜单启动新版程序，或重新运行安装脚本覆盖修复启动路径。

**媒体内容与动效**

  - **频谱柱体不动或者很平：** 先确认当前曲目是否包含足够的低频信号；若音频正常，可在设置面板中手动调高灵敏度、鼓点响应强度或调整柱体数量以增强可视化效果。
  - **切换歌曲后封面不刷新：** 可在设置面板中点击「重新识别」强制更新缓存，或在列表中删除该曲目后重新导入。
  - **曲目显示「音源缺失」：** 表明最初引用的 B 站源缓存已被清理且本机无可用副本。程序导入时存放在自身数据目录下的副本不受清理影响，此提示仅在关联的源文件丢失时出现。
