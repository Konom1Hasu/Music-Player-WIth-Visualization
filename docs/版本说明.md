# 版本说明

当前版本 **v2.7.8**（2026-10-14）｜[完整更新日志](更新日志.md)｜[功能说明](功能说明.md)

一个 Windows 桌面音乐播放器：本地曲库、自研频谱可视化、逐行高亮的歌词页、
可悬浮在游戏之上的迷你窗，以及耳机线控与媒体键支持。只做本地播放，不含任何在线音乐源。

## 这一版改了什么

### 参数复刻修复：存档升 v2，旧档一次性迁移

用户："参数也要复刻"。

排查确认**实锤**：exe 里实际生效的参数确实不是你在 SelfMusic 里调的那一套 —— 问题不在默认值，
而在**存档**。`localStorage['rhine-sm-display']` 里躺着 v2.7.5 时代写下的旧值（12 项与 SelfMusic
面板不符）。上一版把"出厂默认档"改成了你的实测档，但**老档里已存过的旧值会把新默认全量盖住**，
所以画面上一直是旧的那套参数在跑。这一版把存档格式升到 v2（`{ v: 2, values: {…} }`），
读到 v1 旧档时**一次性迁移**：不沿用旧值，直接以实测档收尾并写回；迁移在**程序启动时立即执行**
（此前只在频谱引擎初始化时才读档）。验证：`scripts\探针\_迁移验证.cjs` 用**真实用户目录**启动产物 exe，
存档已升 v2、16 项 = 实测档；`_滑块验证.cjs` 复跑全链（head +48.9% / smooth −82.9% / RESET 干净）。

### 视觉重心：四方案对比出图（待定档）

你的两条感受（"左侧的峰可以稍微右移一点" → "视觉重心太靠左，左比右大约 6:4"）已量化实锤：
真实音乐 79 帧 **左:右 ≈ 6.5 : 3.5**、质心 40.8%（中位，50% 为正中）；且「左重」主体是左半（低频区）
整片『地毯』的柱高，单靠平移改善有限（平移 8 格也只到 5.7:4.3）。`dist\视觉重心对比.html` 给出
四方案横向对比（三组场景 × 四方案，每帧标注 左:右比 与 质心位置）：现状 / 平移 4 格 / 循环移位 8 格
（左端不空、不丢内容；代价是卷回左端的内容实为超高音、闪得快一点）/ 平移 4 格 + 右半渐强 ×1.6（软钳）
（典型帧最平衡 5.5:4.5 / 46.4%；代价是右半柱高被放大显示）。选定后实施进显示层前处理。

### 调参时能看见频谱了：滚到可视化调节区，设置面板自动让位

设置面板滚到「SELF-MUSIC VISUALIZER」区块时自动进入**调参预览态**：遮罩去掉背景模糊与底色、
面板整体向左滑（左缘贴画布左边）—— 右侧频谱 100% 露出、恢复清晰；滚离或关掉面板即恢复。
自动触发、双向 0.3s 平滑过渡；拖动滑块时控件本身不会移动。
实测 11 项断言全绿（`scripts\探针\_调参遮挡.cjs`），截图 `dist\_调参遮挡-让位后.png`。

### 上一版（2.7.7）：频谱与算法，全部换成 SelfMusic 的

用户："将频谱，算法全部换为 SelfMusic 的"。

前两版把 SelfMusic 的**引擎**（算法内核 + 16 项可调显示层）与**取数活路径**逐位对齐了，
但画面上还有两截是本项目自己的东西：**绘制层**仍是本仓 1.3.0 的 Canvas 画法（14 级量化分桶、
顶端补抖、绘制插值、五种样式、节拍先验驱动），**旧算法整条路径**也还在（算法档开关、
120 段 Goertzel Web Worker、旧的调音参数体系）。这一版把这两截整体删掉 —— 频谱只剩
"SelfMusic 原版"一条路。

**画面：照 `visualizer.py` 直译。** 柱**贴底**（高度 = v×(画布高−8)）、宽 = 槽位 × 0.70、
左右各留 6px、**每根柱单独**的不透明度（α = 0.45 + 0.55×柱高，不再是 14 级分桶）、
竖向渐变在 0 / 45% / 100% 三处停下（亮色 → 主色 → 底色）、峰值顶盖（柱顶上方那条 2px
小横线）只在峰值 > 0.004 时画、左上角新增**四路音色指示条**（鼓 / 低音 / 人声 / 镲 ——
此刻哪几路被推高一目了然）。柱数从 150 根回到引擎的 **96 根直画**（删掉了中间的重采样），
所以每根柱比上一版宽了约一半。绝对尺寸（6 / 8 / 2 / 3 像素）按画布显示比例换算，
窄面板和宽面板下几何都成立。配色沿用本机主题（浅色主题用墨色顶盖、深色主题用白色顶盖），
规则与原版一致。

**算法侧：只留一条路。** 删除旧的五种样式（mix / timbre / bars / ring / wave）、绘制插值、
顶端补抖、节拍先验、旧的调音参数体系与一次性导入、120 段 Goertzel Web Worker 与算法档开关。
分析节拍固定 16ms、分析窗固定 4096 点，与 SelfMusic 相同。

**节拍预分析（BEAT PRE-ANALYSIS）默认关闭。** 它原来的三个收益（鼓点提前 28ms 点亮、
每 4 拍换形态、副歌预热）全是给旧算法用的，SelfMusic 的波形是逐位复刻、不接受任何先验改写。
设置里那一项仍在（打开会把每首歌后台分析一遍并缓存），只是默认不再跑。

**怎么证明"就是原版那套"**：新增两道会失败的检查 ——
① **绘制层对拍**：从 `visualizer.py` 的**源码**里正则抽出常量与公式，再和本仓绘制层实际发出的
每一条绘制指令（柱的左缘 / 柱宽 / 柱高 / 贴底 / 逐柱透明度 / 顶盖位置与厚度 / 渐变三个停点 /
指示条四条轨道与填充宽）逐条比，全部 `max|Δ| = 0`（72 项）；
② **产物 exe 像素对拍**：驱动真实产物喂一帧已知柱高，把画布像素读回来量几何，
96 根柱的柱顶、贴底、顶盖、指示条全中（10 项）。这一步还抓出一个隐蔽 bug：
柱循环结束后忘了把透明度归位（原版有 `p.setOpacity(1.0)`），会导致指示条跟着最后一根柱
一起变淡。引擎三档对拍、逐项 16 对拍与活路径对拍（400 帧 `max|Δ| = 1.8e-07`）保持全绿。
重启后的实拍图见 `dist\频谱画面-放大.png`，参数对比见 `dist\滑块效果对比.html`。

### 上一版（2.7.6）：参数与波形，双双与 SelfMusic 完全一致

SelfMusic 的启动参数分三层落定：类构造默认 → `analyzer.py` 的 `DEFAULT_PARAMS` →
面板把「已存值或面板默认」逐项覆盖（其中「细纹」上下限 `detail_hi/lo = 1.12/0.60` 来自第二层，
与类默认 1.45/0.70 不同）。本版按这个次序把默认档复算为**你机器上 SelfMusic 实际在跑的值**：
顺滑 0 / 软膝 95 / 细纹 0 / 左塔泵动 60 / 弹性 300 / 右细节 80 / 右丰 100 / 陡峭 114 /
倾斜 39 / 音色 93 / 毛刺 16 / 尖塔 100 / 低频高耸 110 / 回落 95 / 谷深 100 / 静音呼吸开。
取数侧把活路径重写为 SelfMusic 同式：整曲**原生采样率**单声道 PCM、**平滑位置时钟**、
16ms 节拍、按播放位置的前视窗 `[位置, 位置+4096)`、峰值直通 —— 写了一份"活路径对拍"
（同一 PCM、同一 (位置, 帧间隔) 序列各 400 帧，Node 侧真实驱动类 ↔ Python 侧逐行移植
`_refresh_viz`），heights 与 peaks 双通道 `max|Δ| = 1.8e-07`。

### 上一版（2.7.5）：自研内核全量回归 + 十六枚可视化滑块

用户："再次还原算法，并添加可视化参数的实时自定义调节滑块"。

SelfMusic 那边又一次大幅演进（可调显示层 6 项 → **16 项**）。这一版把频谱引擎**全量升级对齐**，
并把 16 项参数做成设置面板里的实时滑块。内核照 SelfMusic 最新版整体接管，并新增 **8 组显示层
模块**（短窗高频瞬态 / 四路音色强调 / 软膝 / 铺散 / 细纹 / 逐带 AGC / 右区细节 / 左塔泵动）；
v2.7.1~2.7.4 加在显示层的铺散 / 融合 / 保峰 / 减峰 / 补纹全部撤销、还原为直通。
面板侧「系统设置 → SELF-MUSIC VISUALIZER」十六枚滑块，拖动实时生效、自动记住、RESET 一键还原。
三档对拍（中性 / 出厂 / 扫档）各 1000 帧 × 96 条 `max|Δ| ≤ 2e-07`，另做逐项 16 + 累进 16
对拍定位到并修掉一处「谷深」判峰次序的误差。

### 上一版（2.7.4）：中段减峰、左塔保留、右区丰富

用户（看了保峰效果之后）："减少峰的个数。保留左边最高的峰，让右边丰富一点"。

三个要求分别落在三个区上：**中段**把闭运算填充半径加深（3 → 4）+ 保峰门槛 0.45 ——
相邻的丘并成整丘；**左区**（低频塔所在的 0~35 柱）半径与门槛保持原值，塔与上一版逐位相同；
**右区**（78 柱起斜坡进入）把铺散抹掉的细结构补回来 —— 先高通（去掉 15 柱尺度的结构）
再圆化（细针 → 小圆丘），丰富但不刺。仍然只动显示层，一键可回退。

同一段真实音乐的 79 帧统计：中段峰数 3.5 → **2.6**、中段宏观丘 2.4 → **1.7**、
右区纹理 0.011 → **0.015**；左塔高度 0.845 与最高柱 0.845 均不变。
验收图与定档对比图逐字节相同。

### 上一版（2.7.3）：保峰——融合之后把原来的峰还回来

用户（看了融合效果之后）："在这个算法基础上，和原来的频谱融合起来"。

融合在把窄谷填浅的同时，也会把峰磨圆、削低 —— 平缓是好了，但原来（铺散版）峰的高度与
形状也一起丢了。这一版在融合之后对照"闭运算之前的快照"，把**原来更高的柱位（峰区）**
还回来：**谷用融合的、峰用原版的**。定档值 `MERGE_KEEP = 1` 时即
`out = max(铺散版, 融合版)`；`0` 一键回退到纯融合，也可只还一部分（0~1 之间调节）。
仍然只动显示层。

同一段真实音乐的 79 帧统计（相对纯融合）：谷深 0.059 不变（连成片保持）、高尖 0.03 → **0.35**
（保留铺散版的 81%）、最高柱 0.796 → **0.845**（回到铺散版水平）。验收图与定档对比图逐字节相同。

### 上一版（2.7.2）：顶端曲线更平缓：相邻的峰融合

用户："顶端曲线平缓一点，可以将几个峰融合"。

铺散之后每个峰还是各自独立、峰尖偏锐。这一版再加一道**闭运算融合**：只把相邻峰之间的
窄谷填浅 —— 几座塔并成更缓的丘；孤立峰与宽隔断（如低频塔与中频墙之间的大空谷）
保持原形、不会被误填。之后补两遍铺散把平台边角圆化。仍然只动显示层。
不喜欢可以一键回退（`MERGE_R = 0`）。

同一段真实音乐的 79 帧统计（融合前 → 后）：峰数 8.6 → 3.4 每帧、近邻谷深 0.148 → 0.096、
顶端尖锐度 0.015 → 0.010、最高柱 0.845 → 0.796（高度几乎不掉）。

### 上一版（2.7.1）：高峰不再像树林（铺散开）

用户："高峰不要像树林一样，可以适当铺散开"。

频谱算法（SelfMusic 档）自带一条「高峰离散化」，会把扎堆的高条拉成一根根离散的细尖塔 ——
在真实音乐上就是一片"塔林"。这一版在**显示层**给引擎输出加了两遍 5 抽头空间平滑：
尖塔的高处摊开给相邻柱，圆丘相接。峰还在，只是不再孤立。

同一段真实音乐的 79 帧统计（铺散前 → 后）：锯齿度 0.045 → 0.029、
高尖数 2.9 → 1.5 每帧、孤立高柱占比 14% → 3%。只动显示层，算法与数据一行未改。

### 上一版（2.7.1）：顺带修好的三处"新算法与旧装饰打架"

算法换成 SelfMusic 档后，渲染层还留着旧流水线时代的装饰，逐一拆除：

- **断柱**：柱高改按真实值画（此前 42% 的柱会断成两截）；
- **假尖**：去掉重复的顶端尖峰层（新算法自带高峰离散化）；
- **浮空碎屑**：峰值指示线只在明显脱离柱顶时画（此前 150 根里最多 104 根都在画）。

### 上一版（2.7.0）：延迟更低、帧率更高、动态对比更极端

三处一起调，方向是"频谱看着更跟手、更有力"：

- **延迟更低**：分析窗口从 1024 点缩到 512 点，从"拿到声音"到"画出来"的固有延迟砍掉约一半
  （约 10.7 毫秒降到约 5.3 毫秒）。代价是低频那根最尖的柱子对邻近频率更敏感、会略微多抖一点。
- **帧率更高**：播放中不再按固定间隔节流，直接跑满显示器刷新率。高刷屏上尤其明显
  （本机实测 41.6 → 85.3 fps，帧间隔中位数 24 毫秒 → 12 毫秒）。
- **动态对比更极端**：敲击瞬间受影响的频段窜得更高、落得更快，稳态段几乎不动 ——
  "动 / 静"的反差更狠，鼓点更跳。（只改动态，不改稳态的频谱形状。）

### 上一版（2.6.0）：鼓点跟上了画面

之前的频谱是"听到才反应"：分析窗口本身有二十几毫秒的固有延迟，加上数据往返和绘制，
画面总比耳朵慢半拍，调参数救不了。

2.6.0 改成播放前先把整首歌分析一遍：测出 BPM、标出每一个拍点、每一拍的强度。
鼓点到来前 28 毫秒画面就已经亮起来；柱体形态每 4 拍换一次，画面跟着小节走，不再只是被动响应；
副歌进来前还会提前把动态范围打开，高潮不显得突然。

分析在后台悄悄跑，一次一首，4 分钟的歌约半秒，结果存下来第二次播放直接复用。
设置面板新增「节拍预分析」一行，显示当前 BPM 与拍点数，不想要可以关掉。

### 再往前（2.5.0）

- 歌词高亮放大（普通行 16 px、高亮行 22 px）
- 频谱回落更干脆（峰值指示线拖尾从 1.5 秒收紧到 420 毫秒）
- 详情区与弹层的磨砂玻璃质感

## 播放器能做什么

### 播放与曲库

| 能力 | 说明 |
| --- | --- |
| 导入 | 选文件、选文件夹（递归）、直接拖到窗口 |
| 格式 | mp3 / flac / m4a / aac / wav / ogg，以及网易云 `.ncm` |
| NCM | 自动解密为 mp3 / flac，保留完整标签与封面 |
| B 站缓存 | 播放条上的电视图标，选本机缓存目录后按音频内容识别并补齐标题、UP 主、封面 |
| 播放模式 | 列表循环 / 顺序 / 单曲循环 / 随机 |
| 倍速 | 0.5× ~ 2.0×，保音调，变速不变声 |
| 续播 | 关掉再打开，回到上次那首歌和那个位置 |
| 队列 | 「下一首播放」插队，可拖动排序 |

### 歌词

支持同名 `.lrc`、音频内嵌歌词，UTF-8 与 GBK 自动识别。逐行滚动高亮，带翻译行。
找不到时会在同目录和歌名相近的文件里再找一遍。

### 可视化

自研频谱分析器，不走常规的等宽频段方案：对数频率分带 120 条柱体，低频到高频不再挤在左边；
鼓点到来时整排柱体明显弹起；柱体间有从右向左的行波，而不是无方向的抖动。
计算放在 Web Worker 里，不占主线程。

播放前会先分析整首歌的节拍，鼓点提前亮起、柱体形态跟随小节轮换（可在设置里关掉）。

右侧面板可以在「可视化」和「歌词」之间切换，选择会被记住。

### 迷你悬浮窗

一键从主窗口弹出，置顶层级可以在无边框窗口模式的游戏之上显示，点击不会让游戏失焦。
支持拖动、缩放、调透明度、锁定位置。主窗口被遮挡时仍然全速渲染。

### 主题与外观

深色、浅色、网易云红、**莱茵生命**四套主题。强调色可以跟随封面取色，也可以关掉。
莱茵生命主题下默认开启封面 3D 档案，可旋转、可拆解重组，转速与播放状态联动。

### 系统集成

媒体键与耳机线控（播放 / 暂停 / 上下曲 / 停止）双通道接管。
设置面板里有媒体键自检，显示是否已被其它程序占用。被占用时可以改用应用内快捷键，
见 [快捷键](快捷键.md)。

## 已知问题

**媒体键没反应。** 打开设置面板看「媒体键」一行。Windows 的媒体键是独占资源，
同一时刻只能由一个程序注册。显示被占用就说明被游戏或其它播放器抢走了，关掉冲突程序，或者改用应用内快捷键。

**迷你窗在游戏里看不见。** 游戏用「无边框窗口 / 窗口化全屏」时可以正常显示；
用独占全屏时任何普通窗口都盖不住，这是 Windows 的限制，需要在游戏里改成无边框。

**频谱柱体不动或者很平。** 确认播的是有低频内容的曲目。
也可以在设置面板里调灵敏度、鼓点响应强度和柱体数量。

**切换歌曲后封面不刷新。** 在设置里点一次「重新识别」，或者删掉该曲目重新导入。

**曲目显示「音源缺失」。** 这首歌的 B 站源缓存已经被删掉，且本机没有留下副本。
导入时的副本存在程序自己的目录下，不会被 B 站客户端清掉；真正丢失的只是源。

**装了新版本还是旧界面。** 桌面快捷方式可能指向另一份独立安装的副本。
从开始菜单启动，或者重新跑一次安装脚本。

**安装包**：到 [Releases](https://github.com/Konom1Hasu/Music-Player-WIth-Visualization/releases)
