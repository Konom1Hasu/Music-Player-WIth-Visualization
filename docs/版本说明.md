# 版本说明

当前版本 **v2.7.8**（2026-10-14）｜[完整更新日志](更新日志.md)｜[功能说明](功能说明.md)

本软件是一款运行在 Windows 平台上的桌面音乐播放器。程序内置了本地曲库管理，配备团队自行开发的音频频谱可视化动效，提供跟随歌曲进度逐行高亮滚动的歌词页面，还带有能悬浮显示在全屏游戏画面上方的独立迷你窗口。在外部控制方面，软件兼顾了耳机线控按键与键盘系统多媒体键的交互响应。整个播放器只专注于本地音频文件的读取与解码播放，不包含任何形式的在线流媒体音乐源，因此不会产生网络串流请求。

## 这一版改了什么

### 参数复刻修复：存档升 v2，旧档一次性迁移

用户提出需求："参数也要复刻"。

经过排查可以完全确认：打包出的 exe 内部实际生效的参数，确实不是此前在 SelfMusic 里调试好的那套数值。导致这一现象的根源并不在出厂默认配置，而在本地的**存档**机制。在当前环境下，`localStorage['rhine-sm-display']` 这个负责保存界面的键名中，依然残留着 v2.7.5 版本写入的历史旧数据，其中有 12 项配置与 SelfMusic 面板当前的数值不一致。虽然上一版本已经把代码里的"出厂默认档"调整成了实测档，但是根据原有的读取逻辑，老存档中保存过的旧数据拥有更高的优先级，会全量覆盖掉新设定的默认值，最终导致渲染画面始终在按照旧参数运行。

为了彻底解决覆盖问题，这一版把存档的数据结构升级到了 v2 版本，规范为 `{ v: 2, values: {…} }` 格式。系统在读取到 v1 版本的旧存档时，会触发**一次性迁移**操作：逻辑中不再继续沿用任何历史旧值，而是直接采用实测档的参数全面覆盖，并立即写回本地存储。同时，这项迁移工作的执行时机被提前到了**程序启动时立即执行**，改变了此前只有等到频谱渲染引擎初始化时才会读取存档的做法。

修复后的验证流程如下：使用**真实用户目录**直接启动编译生成的产物 exe，检查确认本地存档已经成功升到 v2 结构，其中的 16 项参数也已完全与实测档对齐；随后重新运行自动化测试脚本 `_滑块验证.cjs` 跑通全链路，指标表现正常（head +48.9% / smooth −82.9% / RESET 干净）。
### 视觉重心：四方案对比出图（待定档）

用户此前提出的两点视觉反馈（"左侧的峰可以稍微右移一点" 以及 "视觉重心太靠左，左比右大约 6:4"），在数据层面上已经得到了确凿的验证。
我们统计了真实音乐在 79 帧内的具体表现，测得 **左:右 ≈ 6.5 : 3.5**，代表整个画面能量分布中心的质心位置处于 40.8%（该数值为中位数，按定义 50% 处于正中央）。画面呈现「左重」的核心原因，在于左半部分（也就是音频的低频区）分布着整片如『地毯』般持续偏高的柱体；如果单纯依靠横向平移，能够带来的视觉改善相当有限（即使整体向右平移 8 格，能量比例也仅仅微调到 5.7:4.3）。

为了便于评估，我们在 `dist\视觉重心对比.html` 中提供了四个方案的横向效果对比（测试集包含三组场景 × 四方案，且在每一帧画面上都明确标注了当时的 左:右比 与 质心位置）：
- 现状
- 平移 4 格
- 循环移位 8 格（这个做法可以让左端保持充实不留白、完全不丢失画面内容；但由此带来的代价，是那些被卷回到画面最左侧的内容本质上属于超高音区域，在视觉上闪烁变换的速度会更快一些）
- 平移 4 格 + 右半渐强 ×1.6（软钳）（在典型帧下能够达到最为均衡的视觉表现，能量比为 5.5:4.5，质心位于 46.4%；代价则是右半侧的柱体高度被人工放大显示）

待方案最终选定之后，我们会把对应的计算逻辑正式落实到显示层的前处理流程当中。
### 调参时能看见频谱了：滚到可视化调节区，设置面板自动让位

当用户在设置面板中向下滚动，页面显示到「SELF-MUSIC VISUALIZER」区块时，系统会自动切换进**调参预览态**。在这个状态下，遮罩层会移除原本的背景模糊与底色，同时面板整体向左侧滑动，让自身的左边缘紧贴画布的左边。这样一来，画布右侧的频谱就能 100% 完整露出，画面也恢复清晰，方便用户实时查看效果；一旦用户滚离这个区块或者直接关掉面板，界面就会立刻恢复原样。整个位移动作由系统自动触发，进出均带有 0.3s 的双向平滑过渡动画；在用户拖动滑块调节数值的过程中，控件本身会保持静止，不会跟随着发生移动。经过自动化测试验证，相关的 11 项断言已全部通过。
### 上一版（2.7.7）：频谱与算法，全部换成 SelfMusic 的

用户："将频谱，算法全部换为 SelfMusic 的"。

在先前的两个版本里，系统虽然已经把 SelfMusic 的引擎内核、16 项可调显示层以及取数活路径做到了逐位对齐，但渲染管线中依旧残留着两段来自本项目的旧代码。一段是界面绘制层仍然沿用着本仓库 1.3.0 版本的 Canvas 渲染逻辑，包含 14 级量化分桶、顶端补抖、绘制插值、五种样式和节拍先验驱动；另一段则是旧算法的整条执行链路，保留了算法档开关、运行在 Web Worker 中的 120 段 Goertzel 算法以及整套旧版调音参数体系。本次更新将这两段冗余代码彻底移除，使得频谱渲染与计算完全收敛到 SelfMusic 原版这一条逻辑线上。

**画面：照 `visualizer.py` 直译。** 柱体计算改为严格贴合底部，高度公式直接采用 v×(画布高−8)；柱宽固定设为每个槽位宽度的 0.70 倍，画布左右两侧各自预留 6px 边距。不透明度不再使用原本粗粒度的 14 级分桶，而是对每根柱子单独计算，公式固定为 α = 0.45 + 0.55×柱高。竖向线性渐变严格落在 0、45% 与 100% 这三个位置，色彩过渡呈现为亮色、主色与底色。位于柱顶上方的 2px 峰值顶盖，被限制在峰值大于 0.004 时才会触发绘制。画面左上角补充了四路音色指示条，对应鼓、低音、人声与镲，让用户能够直观分辨出当前瞬间哪几个频段被大幅推高。柱体数量从先前的 150 根回退到音频引擎原生的 96 根直画模式，移除了中间的重采样环节，每根柱子的视觉宽度因此比上一版放宽了大约一半。画面中涉及的 6、8、2、3 像素等绝对尺寸，均会根据画布当前的实际缩放比例进行动态换算，保证界面在宽面板与窄面板布局下都能维持正确的几何比例。配色方面则与本地客户端主题保持联动，浅色主题渲染墨色顶盖，深色主题匹配白色顶盖，规则与原版软件完全一致。

**算法侧：只留一条路。** 移除了旧有的 mix、timbre、bars、ring、wave 共五种样式，删除了绘制插值、顶端补抖、节拍先验驱动、旧版调音参数结构与一次性导入逻辑，并同步清理了算法档开关以及承担 120 段 Goertzel 运算的 Web Worker 线程。音频分析的节奏周期固定为 16ms，单次分析窗口长度固定为 4096 点，各项基准设定均与 SelfMusic 保持一致。

**节拍预分析（BEAT PRE-ANALYSIS）默认关闭。** 该功能在早期版本中主要提供三项优化：让鼓点提前 28ms 响应点亮、每隔 4 拍切换一次画面形态以及在进入副歌前进行预热。这些处理本质上都是为旧版算法定制的补偿手段；而 SelfMusic 的频谱波形依赖确定性的逐位还原，不需要也不能接受外部先验数据的二次改写。设置界面中的这一配置开关仍然予以保留，用户如果手动开启，程序依然会在后台逐首分析歌曲并写入缓存，但系统默认不再自动调用该流程。

**怎么证明"就是原版那套"**：测试流程中新增了两道可以明确拦截异常的断言检查 ——
① **绘制层对拍**：通过正则表达式直接解析 `visualizer.py` 的源码文本，提取其中的关键常量与几何公式，随后与本仓库绘制层在运行时输出的全部绘图指令逐一核对。比对项涵盖了每根柱子的左侧坐标、柱宽、柱高、贴底对齐状态、单柱独立透明度、顶盖位置与厚度、渐变的三个位置点，以及四条指示条轨道与其内部填充宽度，共计 72 个比对项全部达成 `max|Δ| = 0`。
② **产物 exe 像素对拍**：启动打包生成的实际 exe 程序，向渲染流水线输入一帧预设的固定柱高数据，直接抓取画布像素回读并测量其几何布局。结果显示，96 根柱子的顶部位置、贴底效果、顶盖间距以及指示条坐标等 10 项测量指标全部精确命中。这项测试还排查出一个隐蔽缺陷：原本在完成全部柱体的循环绘制后，上下文透明度未能及时复位；由于原版实现中包含 `p.setOpacity(1.0)` 的重置动作，这一缺失曾导致指示条跟随最后一根柱子的低透明度一同变淡变暗。与此同时，引擎三档对拍、逐项 16 对拍与活路径对拍均通过验证，其中活路径对拍在连续 400 帧的比对测试中保持 `max|Δ| = 1.8e-07`。程序重启后的实际界面表现可参考 `dist\频谱画面-放大.png`，具体的滑块调节与参数对比细节记录在 `dist\滑块效果对比.html` 中。

顺滑 0 / 软膝 95 / 细纹 0 / 左塔泵动 60 / 弹性 300 / 右细节 80 / 右丰 100 / 陡峭 114 /

### 上一版（2.7.4）：中段减峰、左塔保留、右区丰富

用户在查看保峰的处理效果之后提出：“减少峰的个数。保留左边最高的峰，让右边丰富一点”。

这三项要求刚好对应到频谱的三个区域，分别采取了针对性的处理：在**中段**区域，形态学闭运算（用来填平低谷并连通相邻起伏）的填充半径从 3 增大到 4，同时搭配 0.45 的保峰门槛，把挨在一起的几个小丘陵合并成一个完整的连续大丘；**左区**覆盖低频塔所在的 0~35 柱，这里的计算半径和门槛完全保持原值不变，让低频塔的形态能够和上一版实现逐位相同；**右区**从 78 柱开始通过斜坡过渡切入，目标是补回此前在铺散过程中被抹平的细微结构，做法是先执行高通滤波去掉 15 柱尺度的大结构，接着通过圆化操作把过于锐利的细针形态重塑为小圆丘，做到纹理细节丰富的同时视觉上不会刺眼。所有的修改依然局限在显示层内部，保留了一键直接回退的能力。

使用同一段真实音乐连续采集 79 帧进行数据统计：中段的波峰数量由 3.5 下降到 **2.6**，中段宏观丘的数量由 2.4 减少到 **1.7**，右区纹理指标则从 0.011 提升到 **0.015**；与此同时，左塔高度 0.845 以及最高柱数值 0.845 均未发生变化。最终生成的验收图与此前定档的对比图保持逐字节相同。
### 上一版（2.7.3）：保峰——融合之后把原来的峰还回来

用户（看了融合效果之后）：“在这个算法基础上，和原来的频谱融合起来”。

融合算法在填浅窄谷的过程中，会产生把波峰磨圆削低的副作用。频谱整体虽然变得平缓，但是原来铺散版中波峰的高度与形状特征也随之丢失了。为了解决这个问题，这一版在完成融合计算之后，会回过头对照"闭运算之前的快照"，把**原来更高的柱位（峰区）**重新还原回来，最终实现**谷用融合的、峰用原版的**这种分工处理方式。当定档值设置为 `MERGE_KEEP = 1` 时，计算逻辑表现为 `out = max(铺散版, 融合版)`；如果把该参数设成 `0`，系统能一键回退到纯融合效果；参数也支持在 0~1 之间调节，以便按比例只还原一部分峰值。这一改动依然只停在显示层，不影响底层的核心音频数据。

同一段真实音乐的 79 帧统计（相对纯融合）：谷深 0.059 不变（连成片保持）、高尖 0.03 → **0.35**
（保留铺散版的 81%）、最高柱 0.796 → **0.845**（回到铺散版水平）。验收图与定档对比图逐字节相同。
### 上一版（2.7.2）：顶端曲线更平缓：相邻的峰融合

用户提出反馈，希望顶端曲线能够更加平缓，可以将相邻的几个峰融合在一起。

在执行铺散处理之后，各个峰值之间仍然保持相互独立的状态，峰尖部分看起来也偏尖锐。针对这个问题，当前版本在管线中额外加入了一道闭运算融合处理，也就是先膨胀后腐蚀的形态学操作。该处理专门针对间距很近的相邻峰，只把它们之间的窄谷填浅，从而将多座独立的尖塔连成坡度更平缓的连续丘陵；对于完全孤立的单峰，或者原本间隔就很宽的区域（例如低频塔和中频墙之间存在的大空谷），算法会保持原始形状，不会发生错误填平的情况。融合完成之后，画面还会追加两遍铺散处理，用来把融合产生的平顶两端的多余边角修饰得更圆润。整套计算依然只作用于最终的渲染显示层，不影响底层的原始音频数据。如果用户不习惯这种视觉表现，可以将参数设为 `MERGE_R = 0`，就能一键回退到未融合的状态。

采集同一段真实音乐连续运行 79 帧后，各项指标在融合处理前后的具体统计数据如下：每帧平均峰数从 8.6 个减少到 3.4 个，近邻谷深从 0.148 降低到 0.096，顶端尖锐度从 0.015 改善至 0.010，最高柱的振幅仅仅从 0.845 微调到 0.796，整体能量高度几乎没有出现损失。
### 上一版（2.7.1）：高峰不再像树林（铺散开）

用户反馈希望“高峰不要像树林一样，可以适当铺散开”。

在 SelfMusic 档位的频谱算法中，原本包含一段名为「高峰离散化」的处理逻辑。该逻辑在遇到能量集中的连续高频条时，容易把它们强行拉成彼此割裂的离散细尖塔形状。当这一套逻辑应用到真实的音乐信号中时，画面上就会密集排布大量细高的竖条，视觉效果直接变成了一整片“塔林”。为了解决这一观感问题，我们在本版本中直接于**显示层**介入，对引擎最终输出的柱状数据连续执行了两遍 5 抽头空间平滑处理，也就是每次计算都结合当前柱及其左右各两根邻近柱的数值进行加权平均。这样做把原本过分尖锐的高点数值均匀分摊给了相邻的频柱，促使各频段的起伏形成连绵相接的圆丘形态；关键波峰的特征依然保留在画面中，只是不再显得单薄与孤立。

针对同一段真实音乐连续采集 79 帧数据，铺散处理前后的各项统计指标对比如下：画面锯齿度由 0.045 下降至 0.029；平均每帧出现的高尖数量从 2.9 个减少到 1.5 个；孤立高柱在全部数据中的占比也从 14% 压低至 3%。这项改动完全局限在负责渲染表现的显示层，底层的分析算法与核心数据资产一行未改。
### 上一版（2.7.1）：顺带修好的三处"新算法与旧装饰打架"

当音频分析算法切换到 SelfMusic 档位后，负责画面输出的渲染层依然残留着旧版流水线沿用下来的视觉装饰逻辑，导致界面出现渲染冲突。本次更新将这些遗留代码逐一拆除：

- **断柱**：频谱柱的实际高度改为直接按照计算出的真实数值绘制，修复了此前因旧逻辑强行拆分高度，导致有多达 42% 的柱体直接断裂成两截的渲染异常；
- **假尖**：彻底移除了额外叠加在顶部的尖峰图层，因为新算法本身就已经包含高频能量的离散化处理，继续叠加旧装饰会导致柱顶反复出现不自然的重复突起；
- **浮空碎屑**：调整了峰值指示线（用于标记音频瞬间最高能量位置的浮动横线）的触发逻辑，现在只有在它明显高于并脱离柱顶时才会绘制。在此之前，即便柱体高度没有脱离，画面上全部 150 根柱子中最多会有 104 根同时绘制该线条，在视觉上堆积成了杂乱的碎屑。
### 上一版（2.7.0）：延迟更低、帧率更高、动态对比更极端

这里针对三个参数做联合调整，整体目标是让频谱图的视觉反馈更贴合音频节奏，在听感与画面之间形成更强烈的打击感：

- **延迟更低**：傅里叶变换的分析窗口长度（即单次处理采样的音频点数）由 1024 点压缩至 512 点。调整后，系统从采集到音频信号开始计算，直到把画面完整绘制到屏幕上的这一段固有时间开销缩减了大约一半，实测耗时从约 10.7 毫秒降低到了约 5.3 毫秒。相应的技术代价是频率分辨率有所下降，低频区域中最细的那根柱子容易受到临近频率信号的干扰，在画面上会出现轻微的抖动幅度增加。
- **帧率更高**：音频播放过程移除了固定的时间间隔节流限制，渲染循环改为与显示设备的垂直刷新率保持同步，让渲染性能完全匹配高刷新率屏幕的显示特性。以测试本机的表现为例，绘制帧率由原来的 41.6 fps 提升到了 85.3 fps，两次画面刷新之间的间隔时间中位数也由 24 毫秒缩短到了 12 毫秒，画面顿挫感明显减轻。
- **动态对比更极端**：重调了响应曲线的瞬态反馈算法，当打击乐这类突发瞬态信号进入时，对应频段的能量柱上升速度更快、冲得更高，并在冲击过后快速回落；处于持续平稳的声音段落时，柱体则基本维持原状。这种处理放大了画面运动与静止之间的对比程度，使鼓点等强节奏看起来更有弹性，而且修改只作用于动态过渡阶段，稳态阶段原本的频谱包络形状完全不受影响。
### 上一版（2.6.0）：鼓点跟上了画面

旧版本的频谱完全依赖即时音频输入，属于“听到声音才开始响应”的被动机制。短时傅里叶变换这类频域分析窗口自身就带有二十几毫秒的固有延迟，音频数据在传输、解析与界面渲染链路中流转后，画面输出总是比耳朵听到的声音慢半拍，无论用户怎么调整缓冲或平滑参数，都无法消除这种音画不同步的迟滞感。

2.6.0 调整了技术方案，改为在音频正式播放前先在后台完成整首歌曲的离线预分析。算法会测算出整首歌的 BPM（每分钟节拍数，即音乐速度），精确定位出每一个节拍点的时间戳，并计算出每一拍对应的能量强度。基于这套时间轴，系统可以在实际鼓点发声前 28 毫秒提前触发画面的高亮动效；频谱柱体的视觉形态也固定为每 4 拍切换一次，使动画节奏严格对齐音乐小节，不再只是被动跟随时域信号晃动。同时，系统在检测到副歌片段即将切入时，会提前把渲染的动态范围完全打开，避免高潮乐段突然爆发时画面产生生硬的削顶跳变。

这套预分析任务完全在后台静默运行，采用单曲单任务的队列机制，处理一首 4 分钟长度的常规歌曲只需要约半秒时间。计算生成的节拍特征数据会被持久化保存，同一首歌曲在第二次播放时直接复用缓存，不会重复消耗计算资源。
设置面板中新增了「节拍预分析」一行，实时显示当前歌曲的 BPM 与拍点数，如果用户不需要这项特性，可以手动将其关掉。
### 再往前（2.5.0）

- 歌词高亮放大（普通行 16 px、高亮行 22 px）
- 频谱回落更干脆（峰值指示线拖尾从 1.5 秒收紧到 420 毫秒）
- 详情区与弹层的磨砂玻璃质感

## 播放器能做什么

### 播放与曲库

| 能力 | 说明 |
| --- | --- |
| 导入 | 选文件、选文件夹（递归）、直接拖到窗口 |
| 格式 | mp3 / flac / m4a / aac / wav / ogg，以及网易云 `.ncm` |
| NCM | 自动解密为 mp3 / flac，保留完整标签与封面 |
| B 站缓存 | 播放条上的电视图标，选本机缓存目录后按音频内容识别并补齐标题、UP 主、封面 |
| 播放模式 | 列表循环 / 顺序 / 单曲循环 / 随机 |
| 倍速 | 0.5× ~ 2.0×，保音调，变速不变声 |
| 续播 | 关掉再打开，回到上次那首歌和那个位置 |
| 队列 | 「下一首播放」插队，可拖动排序 |

### 歌词

播放器支持读取与音频同名的外部 `.lrc` 文件，也能直接解析音频内置的内嵌歌词。文本编码方面支持自动识别 UTF-8 与 GBK，避免出现乱码。界面会随歌曲进度逐行向上平滑滚动并高亮当前句，原词下方还会同步显示翻译行。
如果当前曲目没有精确匹配到歌词，程序会自动扫描同级目录，并在歌名相似的文件中重新检索匹配。

### 可视化

自研的音频频谱分析器放弃了常见的线性等宽分频方案，改为采用更贴近人耳听觉特性的对数频率分带算法，把声音信号拆解映射到 120 条柱体上，从而彻底解决了传统频谱图中低频到高频细节全部挤在最左侧的问题。当遇到强烈的鼓点下潜时，整排柱体会产生明显的受力弹跳反馈，柱体之间还会激发出由右向左平滑传递的行波物理动效，避免画面杂乱抖动。所有与频谱相关的 FFT 频域变换计算全部放在独立的后台线程 Web Worker 中执行，完全不会抢占界面渲染的主线程资源。

音频在开始播放前，后台会预先扫描分析完整首歌曲的节奏鼓点。这样一来，视觉效果能在鼓点实际发声前提前亮起预警，柱体的呈现形态也会跟随乐曲小节的更替规律轮换变化（如果用户不需要此动效，可以在系统设置中手动关闭）。

界面右侧的内容面板支持在「可视化」图表与滚动「歌词」之间随意切换，软件会自动保存用户的当前选择，下次启动时无须重新设置。

### 迷你悬浮窗

用户点击一下按钮就能从主窗口分离出轻量级的独立悬浮窗。它的窗口层级经过专门优化，能够稳定悬浮显示在开启了无边框窗口化模式的游戏画面上方；用户点击悬浮窗操作播放或暂停时，系统焦点依然会留在游戏内，不会导致游戏画面意外最小化或失去响应。
悬浮窗支持自由拖拽移动、按比例拉伸缩放、调节整体透明度，并且支持锁定位置防止误触。即使主程序窗口被完全最小化或被其他应用完全遮挡，悬浮窗内部的动画与界面依然会保持全速渲染，不出现掉帧卡顿。

### 主题与外观

软件内置了深色、浅色、网易云红以及**莱茵生命**四套视觉主题。界面的主强调色支持智能算法自动提取当前正在播放的专辑封面主色调，用户也可以根据喜好在设置中关闭该功能并固定单色。
当切换到莱茵生命主题时，播放界面会默认启用特制的 3D 封面档案展示效果。该组件支持鼠标自由拖拽旋转视角，并能执行分层拆解与重组动效，模型的自转速度还会实时响应当前的音频播放与暂停状态。

### 系统集成

键盘顶部的多媒体物理按键以及外接耳机的硬件线控（包括播放、暂停、上一曲、下一曲与停止功能）均由软件建立双通道统一监听并接管。
软件的设置面板中内置了媒体键占用状态自检工具，能够直接排查并显示当前全局媒体键是否已经被操作系统中的其他后台软件抢占注册。如果发现物理按键确实被占用而失效，用户可以直接切换为软件内部定义的纯键盘热键操作，具体配置请参考 [快捷键](快捷键.md)。

## 已知问题

**媒体键没反应。** 用户可以打开设置面板，查看「媒体键」这一行的状态提示。Windows 系统的全局媒体键属于独占资源，同一时刻只能由一个程序注册监听。如果界面显示被占用，说明键位已经被游戏或其它后台播放器抢先绑定，此时需要退出有冲突的程序，或者在设置里改用应用内快捷键来控制播放。

**迷你窗在游戏里看不见。** 游戏画面设置为「无边框窗口 / 窗口化全屏」模式时，迷你窗可以正常悬浮在游戏上方；如果游戏启用了独占全屏模式，Windows 系统会直接阻止任何普通窗口覆盖画面，导致迷你窗被完全遮挡。遇到这种情况，需要在游戏本身的画面设置里切换成无边框模式。

**频谱柱体不动或者很平。** 首先确认当前播放的曲目是否包含足够的低频信号。如果音频本身没有问题，用户也可以进入设置面板，手动调整灵敏度、鼓点响应强度以及柱体数量这几项参数，让可视化效果更明显。

**切换歌曲后封面不刷新。** 用户可以在设置面板中点击一次「重新识别」按钮来强制更新缓存，或者直接在列表里删掉该曲目，然后再重新导入一遍。

**曲目显示「音源缺失」。** 出现这个提示，说明这首歌最初引用的 B 站源缓存已经被清理，而且本机没有留下可用的音频副本。程序在导入时其实会把副本存放在自己的数据目录下，并不会被 B 站客户端的缓存清理动作删掉，此时真正丢失的是最初关联的源文件。

**装了新版本还是旧界面。** 桌面上现有的快捷方式可能指向了系统中另一份独立安装的旧版本副本。用户可以直接从开始菜单中启动新版程序，或者重新跑一次安装脚本来覆盖修复启动路径。

## 获取与更新

**安装包**：前往 [Releases](https://github.com/Konom1Hasu/Music-Player-WIth-Visualization/releases) 页面下载 `音乐播放器-Setup-x.y.z.exe`，直接双击运行文件即可开始安装。程序采用按当前用户安装的模式，运行过程中不会弹出 UAC（用户账户控制）提权提示，也不需要管理员权限。生成桌面快捷方式属于可勾选的项目，开始菜单中的快捷方式则默认一定会建立。如果后续需要卸载，请通过系统的「应用和功能」面板进行操作，卸载过程会自动保留现有的曲库数据与偏好设置，不会将其删除。

**便携版**：直接下载 `dist\音乐播放器-win32-x64\` 完整文件夹，进入目录后双击 `音乐播放器.exe` 就能启动。这种形式完全不需要向系统执行安装操作，用户可以直接存放在 U 盘等移动存储设备中随身携带使用；若不再需要该程序，手动删掉整个文件夹即可完成卸载。
