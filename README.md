# 音乐播放器 · Music Player

**当前版本 v2.7.8** ｜ [版本说明](docs/版本说明.md) ｜ [更新日志](docs/更新日志.md) ｜ [数据管控说明](docs/数据管控与合规.md) ｜ [维护指南](docs/维护指南.md) ｜ [发布与推送](docs/发布与推送.md)

这是一个基于 **Electron** 跨平台框架构建的便携式桌面音乐播放器。程序主要负责扫描与整理用户存放于本地硬盘的音频曲库，提供能够跟随音频节奏实时跳动的自定义频谱可视化动效，并包含一套适合大屏沉浸欣赏的全屏封面歌词展示页。当用户在全屏运行游戏或其他重度任务时，可以唤出置顶于所有窗口之上的迷你悬浮窗来控制播放进度，软件同时也接入了系统底层的多媒体控制协议，支持直接响应键盘上的全局媒体键以及耳机线控的播放、暂停与切歌指令。

软件界面全量采用中文呈现，整体视觉风格采用「干净圆角 + 极简线性图标」的统一规范。为了适配不同的桌面环境与个人偏好，系统内部默认预置了深色、浅色、网易云红以及莱茵生命这四套风格各异的主题配色，用户可以在设置中按需一键切换。

> 本项目专注于纯粹的本地音频文件回放，代码中没有接入任何第三方流媒体在线音乐平台的网络点播接口。软件内提供的 B 站缓存提取功能，使用目的只能用于解析并播放**你本机已缓存的音频**文件。
> 针对从本地缓存中提取解析出来的这部分音频数据，程序在底层执行了「不落盘 / 不可导出 / 可追溯」的三层数据安全管控策略，音频流只在内存中解密与播放，杜绝向外写盘泄露，具体机制详见
> [数据管控与合规](docs/数据管控与合规.md)。

## 特性

### 播放与曲库

| 能力 | 说明 |
| --- | --- |
| 多来源导入 | 支持直接选取具体文件、按文件夹递归扫描内部音频，或者将文件与目录直接拖拽到程序窗口内完成添加 |
| B 站缓存提取 | 点击播放条上的电视图标后，指定本机任意哔哩哔哩客户端缓存目录，程序会**按音频内容识别**提取其中的 `.m4s` 媒体流，自动补齐对应的视频标题、UP 主名称以及封面图（所生成的数据副本仅存放于当前运行会话的临时目录中） |
| NCM 解密 | 客户端内置了 `ncmdump` 处理模块，在导入网易云音乐 `.ncm` 加密格式时会自动在后台解密还原为标准 mp3 或 flac，同时完整保留原始 ID3 元数据标签（解密产生的数据只保存在系统内存中，不落盘写入新文件） |
| 播放模式 | 列表循环 / 顺序播放 / 单曲循环 / 随机播放 |
| 进度记忆 | 程序关闭后重新启动，会自动恢复关闭前正在播放的具体曲目与对应的播放进度时间点 |
| 队列控制 | 允许通过「下一首播放」动作将指定曲目优先插入当前播放队列，并在队列列表中支持鼠标拖动重新排序 |
| 倍速播放 | 支持在 0.5× 到 2.0× 范围间平滑变速，开启**保音调**算法处理音频（将播放速率设为 0.75× 时声音不会沉闷发浑，提升至 1.5× 时人声与乐器也不会尖锐变调） |
| 切歌预取 | 当当前歌曲播放至距离曲尾约 12 秒时，播放器会在后台静默完成下一首音源的数据准备工作，彻底消除切歌瞬间因跨进程通信（IPC）与读取磁盘文件产生的卡顿等待 |

### 音频链路

| 能力 | 说明 |
| --- | --- |
| **采样率跟随设备** | 用于音频可视化分析的 `AudioContext` 采用**无参构造**方式实例化。依据 Web Audio 规范，只有在构造时不传递 `sampleRate` 属性，运行时才会主动匹配并使用当前系统音频输出设备的首选硬件采样率（若显式传入 `0` 属于无效配置，接口会直接抛出 `NotSupportedError` 异常）。由于本地曲库文件多以 44100Hz 为主，让分析链路直接跟随音频设备采样率能够完全避免多次重采样带来的音质损耗与性能开销 |
| 音源内存读取 | 针对提取的 B 站缓存数据，播放器一律采用**主进程读取底层文件字节并构建 Blob URL**的链路提供给播放组件。如果直接使用本地文件路径 `file://` 协议加载，会被应用内嵌的静态资源服务拦截并触发 MediaError 4 播放错误，通过内存转接能够稳定避开系统协议权限限制 |
| 状态可见 | 系统的设置面板会实时反馈当前的保音调处理状态以及音频分析管线的实际工作去向；当频谱渲染管线未能正常启动时，面板会直接显示对应的**故障原因**诊断信息，不再处于静默失效状态 |

### 元数据

- 标题 / 歌手 / 专辑 / 封面：程序优先解析并读取音频文件内部嵌入的 ID3 等规范元数据标签；若文件未写入标签信息，则自动回退至根据文件名提取文本规则，并检索同级目录下的 `cover.*` 文件作为替代封面
- **多歌手识别**：针对字段中出现的 `A/B`、`A、B`、`A feat. B`、`A & B` 等多种常见复合连接形式，解析模块会全部自动切分并归类为彼此独立的歌手条目
- **重新识别**：对于曲库中已导入的本地曲目，支持通过界面提供的一键重新识别入口重新走一遍元信息提取流程，识别完成后歌手等关联条目会即时更新生效
- 封面支持从内嵌音频数据解析或读取同文件夹配套图片，针对 NCM 加密文件也能在解密链路中直接提取其内嵌的封面画作

### 歌词

- 完整支持外部 `.lrc` 同名独立歌词文件与音频内嵌歌词的读取，内置字符集检测模块可自动识别并转换 UTF-8 与 GBK 编码格式
- 采用网易云音乐交互风格的平滑逐行居中滚动与高亮渲染模式，并且支持双行展示对应的翻译歌词内容
- 当音频文件未提供歌词时，匹配引擎会自动在同级文件目录下检索同名或歌曲名称相似的其他歌词文件进行关联补全

### 可视化

频谱模块**逐位复刻并逐条直译了 SelfMusic 桌面端成熟的算法与图形绘制流程**：

- **计算引擎**：完整移植了 SelfMusic 最新版的核心处理逻辑（由底层数学计算内核 `web/spectrum.mjs` 配合上层引自 `selfmusic.py` 的 16 项参数化可调显示层组成）。全链路基于 96 段对数分布频带与 4096 点分析采样窗构建；经由引擎三档基准与 16 项微调参数比对校验，计算数据达到逐位一致的精度要求（各采样点绝对误差满足 `max|Δ| ≤ 2e-07`）
- **实时活动路径（数据采样）**：音频载入后整曲统一解码为保留**原生采样率**的单声道浮点 PCM 时域数组，通过平滑位置时钟与每 16ms 触发一次的时基节拍驱动，动态截取以当前播放时间戳为起始点的无跳跃前视采样窗 `[位置, 位置+4096)` 并直通峰值检波。该活动路径经过长达 400 帧的双通道对拍测试，误差值严格限制在 `max|Δ| = 1.8e-07`；遇到超长音频文件、单体数据体积过大或主解码器抛出异常的情况时，系统会自动平滑降级至流式音频管线运行
- **图形绘制层**：直接将原工程 `visualizer.py` 内的 Canvas 指令集直译实现。各频段能量柱底部完全贴紧底边，单柱宽度固定占据所在频段槽位宽度的 70%，柱体透明度遵循公式 `α = 0.45 + 0.55·柱高` 随能量动态映射；渐变填充由亮色、主体色与暗色三段过渡混合，并在柱体顶端上方固定悬空 3px 处绘制 2px 厚度的瞬态峰值顶盖。画布左上角实时渲染由鼓点、低音、人声与镲片组成的四路频段指示条；整套渲染管线以 96 个原始对数段直接打标上屏，不执行破坏相位特性的二次重采样
- **十六枚参数滑块**（设置 → SELF-MUSIC VISUALIZER）：调整界面提供的 16 项物理映射滑块，参数会实时生效至画面并持久化存盘；点击 RESET 按钮即可一键还原出厂值。该预设默认参数配置与原生 SelfMusic 生产环境保持一致
- 双重精确校验机制：通过提取 `visualizer.py` 源代码数学模型对齐本仓库 Canvas 指令（覆盖 72 处数学定义对照项），并结合打包后 exe 产物的屏幕帧回读进行像素几何尺寸标定（覆盖 10 处边界形态项），确保画面完全复原

> 历史：在 v2.7.7 版本以前，播放器使用的是 1.3.0 周期开发的自研可视化流水线（采用 Goertzel 算法计算频段、划分 120 柱输出、使用 14 级能量分桶、预置五种视觉样式，并辅以节拍先验检测算法在 Web Worker 中离线计算）。该套早期实现现已被彻底废弃并移除，技术演进细节参见 [更新日志](docs/更新日志.md)。

### 迷你悬浮窗

- 支持随时通过主界面操作按钮一键呼出悬浮窗口，其内部**直接复用主窗口已计算完毕的可视化频谱缓冲数据**，不额外开辟运算线程占用计算资源
- 悬浮窗默认配置操作系统顶级置顶标记 `screen-saver`，即使在运行**无边框窗口化全屏模式的 3D 游戏**时也能稳定保持浮动在最上层
- 窗口创建阶段显式声明 `setFocusable(false)` 属性，在游戏中用鼠标点击悬浮窗区域也**不会**导致主游戏窗口丢失当前输入焦点
- 支持在屏幕内任意拖动排布、缩放窗体大小、调节整体背景与元素不透明度，同时支持开启位置锁定以防止误触引发位移
- 当播放器主窗口被其他应用软件遮挡或最小化至后台时，该悬浮窗依然保持全帧率平滑渲染输出（应用底层已针对性关闭了渲染进程后台节能降频策略）

### 系统集成

- **系统媒体键与耳机线控适配**：针对键盘硬件的 `MediaPlayPause`、`MediaNextTrack`、`MediaPreviousTrack`、`MediaStop` 控制指令，程序组合使用 Electron 提供的 `globalShortcut` 系统热键（底层映射为 Win32 RegisterHotKey）以及 Chromium 内建的 Media Session 规范（接入 Windows 系统媒体传输控制 SMTC 模块）双通路同步监听
- 设置面板内嵌了**媒体键自检诊断工具**：可直观枚举并展示当前硬件动作的注册状态，以 ✓ 已注册、⚠ 被占用、✕ 全部被占用 三种状态指示系统冲突，便于定位全局热键冲突源
- 接口注册逻辑具备完全的**幂等**特征，在系统唤醒或设备插拔时触发的定时重试扫描中，程序不会将自身已占用并持有的全局键位误报为「被占用」

### 主题与外观

- 内置深色（蓝紫冷调）、浅色（高对比明亮）、网易云红（`#EC4141`）以及**莱茵生命**（琥珀金 `#c5a16b`）四套风格方案
- **强调色跟随封面**（终端用户界面默认保持开启）：程序会在歌曲载入后，提取当前曲目专辑封面的色彩分布，在 HSV 空间内经由饱和度加权计算提炼出最匹配的主题基色。界面的选中高亮竖条、滑块滑槽槽体以及播放进度指示把手均会联动变换色彩；当检测到封面灰度过高缺乏色彩或歌曲本身无封面时，界面元素会自动安全回退至当前主题的默认主色，用户随时可在设置中关闭这一动态色彩功能，详细计算方式与规则可查阅 [docs/功能说明.md §8.1](docs/功能说明.md)
- 莱茵生命主题属于一套特殊的「仪器面板」设计变体：整套视觉基调参考了开源项目 [RhineLabUI](https://github.com/LBEILC/RhineLabUI)（基于 MIT 协议，原作者为哔哩哔哩平台 **@路北路陈**）中确立的暗色界面规范，界面大量使用宽度为 1px 的硬质实心细线作为界限，所有功能容器皆收拢为锐利直角，**列表当前选中项摒弃了传统的半透明高亮底块，转而采用左侧单一黄铜细竖条指示状态**，同时搭配全界面等宽数字排版并在专辑封面四角绘制特征性的黄铜定位拐角标识，该主题在结构层面实施了重构，具体排版定义参见 [docs/功能说明.md](docs/功能说明.md#莱茵生命仪器面板变体)
- 软件内所有弹层模态框、控件滑槽、设置滑块与进度条拖拽把手均与选中的全局主题保持一致
- 全局交互图标采用统一设计规范的极简风格轮廓样式（共有 16 套纯手工绘制的轻量级 SVG 资源，线宽统一约束为 `stroke-width: 1.7` 并使用微圆角线条端点）
- 主界面设计有倒角圆润的主播放控制开关，与形态细长的胶囊样式暂停状态图标相呼应
- **封面 3D 档案模型**（该功能在莱茵生命主题环境下默认激活，用户可在设置面板 ⚙ 中随时手动启闭）：开启后将在封面展示区域叠加一层具有空间进深感且能够自由旋转交互的 [Rhine Lab 档案](https://github.com/LBEILC/RhineLabUI) 3D 模型资产（遵循 MIT 协议，模型源 Blender 工程文件由哔哩哔哩 **@路北路陈** 制作提供），组件还支持通过鼠标操作实现各个构造部位的**拆解展开与重组复位**。该部分完整复现了原项目 `model-viewer.ts` 定义的部件空间分层映射准则（各几何体统一按 `assemblyPart` 字段解析归类，沿 Z 轴依照公式 `depth × spread` 进行位移展开计算，过渡动画设定为阻尼速率 5.5 的弹簧效果）。3D 构件的旋转速率会跟随当前的音频播放状态动态同步；渲染管线强制限制在 30fps 以内以降低功耗，窗口隐藏或失去可见性时立即挂起渲染，若 WebGL 环境初始化失败则自动平稳降级关闭，具体开发文档可参阅 [docs/功能说明.md §10](docs/功能说明.md#10-封面-3d-档案)
- **MiSans 字体排版**：样式表通过 CSS `local()` 语句声明本地字体索引机制，只有在用户本机操作系统已预装该字体时才会调用渲染，未安装时直接由系统默认无衬线字体平替渲染，软件本身不内置任何体积庞大的字体静态文件

## 数据管控

程序能够从 `.ncm` 文件与 B 站缓存数据中提取并解出可播放的音频，但这部分解密后生成的**派生数据**依然受到原平台版权条款的约束。如果这类音频文件脱离控制被直接复制到外部，就会形成非法的传播源。为了防范这类外泄风险，程序在架构上设计了三层管控机制：

| 层 | 措施 |
| --- | --- |
| **最小落盘** | 解密结果只在**内存**中传递，绝不写入音乐目录；解出的音频只存在于 `%TEMP%\mp-session-<会话ID>\`，读完立即覆盖擦写，**退出程序即整体销毁**，崩溃残留下次启动清理 |
| **不可导出** | **不提供任何导出 / 另存为 / 分享**能力；28 个 IPC 通道没有任何一个接受"输出路径"；`preload` 不暴露写文件方法；渲染进程无 `nodeIntegration` |
| **可追溯** | 每次解密与提取写一条本机审计记录（时间 / 版本 / 会话 ID / 来源文件 / 产物体积），上限 500 条，可在设置面板查看条数并一键清空 |

在数据输入阶段，程序同样设置了前置校验。模块 `convert-ncm` 会首先读取并核验文件的 `CTENFDAM` 容器魔数，也就是用来标识 NCM 格式特征的文件头字节；凡是魔数不匹配的文件，处理逻辑会直接报错拒绝，因此该模块并非一个可以解开任意加密格式的“通用解密器”。对于 B 站提取模块，它只能处理用户电脑中已经存在的本地缓存，程序本身绝不会主动向服务端发起任何额外的音频下载网络请求。

前述的各项管控状态都支持在程序界面中直接**可见**。用户打开 ⚙ 面板后，在「数据管控」状态行能够看到当前运行策略的实时摘要：
`内存解密 · 会话级临时目录 · 无导出 · 审计 N 条`。此外，软件在全新安装后的首次启动过程中，会自动弹出一份使用边界告知窗口，向用户明确说明合规范围。

为了防止后续开发破坏这些安全限制，全部管控措施都编写了可用于回归测试的自动化脚本：

```powershell
node scripts\数据管控验证.js app     # 28 项断言，含"从源码摘出擦除逻辑实测"
```

> **唯一的例外，且是刻意为之 —— 导入音频的固化**：用户选择导入的 B 站缓存，会在本地存储目录
> `<userData>\library\audio` 内固化保留一份能够正常播放的音频副本，该副本在落盘前已经剥离了客户端私有文件头，并且完成了真实媒体内容头的校验。
> 之所以引入固化逻辑，是因为原始缓存保存在用户自己的 `Videos\bilibili` 路径下，极易在日常清理系统时被官方客户端或者用户手动清空。
> 一旦缺少本地固化机制，音乐库中“某首歌曲能否正常播放”就会完全受制于一个外部不可控的临时目录。
> 此前曾发生过真实事故：《scualee》这首曲目的源缓存目录被意外删除，导致播放列表里留下了一个永远无法载入、反复报错的僵尸条目。
> 生成的固化副本只保存在这台电脑本地，程序不会对其提供导出功能，也不会将其上传到外部服务器。在界面展示上，曲目列表会给这类音频打上「B 站缓存 · 已存本地」的显式标签；
> 如果原本的源缓存已经被清空，而且本地也没能留下固化副本，界面则会明确标记为「音源缺失」，不再伪装成普通曲目误导用户。

完整的技术说明文件，包含具体的底层技术实现、完整的验证断言明细以及系统已知的使用边界，请查阅 **[docs/数据管控与合规.md](docs/数据管控与合规.md)**。

## 快捷键

### 媒体键（系统级，任意界面生效）

本应用支持直接调用操作系统级别的媒体控制按键。即使当前窗口处于后台或者在运行其他全屏软件，按下这些按键也能直接触发对应的播放控制指令。

| 按键 | 功能 |
| --- | --- |
| `MediaPlayPause` / 耳机播放键 | 播放 / 暂停 |
| `MediaNextTrack` / 耳机下一曲 | 下一首 |
| `MediaPreviousTrack` / 耳机上一曲 | 上一首 |
| `MediaStop` | 暂停 |

### 全局备用组合键（媒体键被占用时使用）

这一组全局快捷键同样作用于整个系统环境。因为某些特定硬件的系统媒体键可能会被其他后台进程抢占，用户可以通过这些通用的组合键来控制播放状态，或者调整浮动在屏幕表面的迷你悬浮窗的位置与尺寸。

| 快捷键 | 功能 |
| --- | --- |
| `Ctrl` + `Alt` + `P` | 播放 / 暂停 |
| `Ctrl` + `Alt` + `N` | 下一首 |
| `Ctrl` + `Alt` + `B` | 上一首 |
| `Ctrl` + `Alt` + `Space` | 播放 / 暂停 |
| `Ctrl` + `Alt` + `← ↑ → ↓` | 移动迷你窗 14 px |
| `Ctrl` + `Alt` + `0` | 放大迷你窗 |
| `Ctrl` + `Alt` + `9` | 缩小迷你窗 |
| `Ctrl` + `Alt` + `L` | 锁定 / 解锁迷你窗 |

### 应用内快捷键（窗口聚焦时）

下列按键只在播放器的主界面窗口处于前台激活状态时起效。用户通过键盘可以直接控制播放进度、调整音量步进，也可以用来快速呼出辅助面板或保存正在修改的歌曲信息。

| 快捷键 | 功能 |
| --- | --- |
| `空格` | 播放 / 暂停 |
| `→` / `←` | 快进 / 后退 5 秒 |
| `↑` / `↓` | 音量 +/- 5% |
| `M` | 打开 / 关闭迷你悬浮窗 |
| `L` | 展开 / 收起播放列表 |
| `F` | 收藏 / 取消收藏当前歌曲 |
| `Esc` | 关闭歌曲编辑弹层 |
| `Enter` | 在歌曲编辑弹层中保存 |

> 完整说明见 [docs/快捷键.md](docs/快捷键.md)。

> 如果遇到系统媒体键没有响应的情况，用户可以进入设置面板，查看排查按键注册状态的「媒体键」自检行。自检项中如果出现了 ⚠ 或 ✕ 图标，说明操作系统的全局监听通道已经被正在运行的其它程序（例如游戏客户端或其他音视频播放器）独占注册了。遇到这种冲突时，用户切回应用窗口使用应用内快捷键即可完成控制。

4. 打印产物路径与体积

也可以直接双击根目录的 `构建.bat`。

### 自定义运行时版本

```powershell
.\scripts\build-portable.ps1 -ElectronVersion 31.7.7 -Mirror https://npmmirror.com/mirrors/electron
```

## 安装

通常情况下，用户只需要**双击根目录的 `安装.bat`** 即可完成全部配置（这条命令等价于在终端执行 `.\scripts\install.ps1 -Launch`）：

1. 自动调用构建脚本检查并生成运行所需的产物；如果本地开发环境中没有安装 Node 依赖，脚本会直接沿用现有的界面产物
2. 将程序文件统一安装到 `%LOCALAPPDATA%\Programs\音乐播放器`；如果目标路径已经存在，安装程序会先清空旧文件，遇到程序正在运行的情况则会自动结束对应进程
3. 在系统桌面上创建快捷方式，同时向开始菜单添加快捷方式
4. 在安装目录内部一并写入用于清理的 `卸载.ps1` 与 `卸载.bat` 文件
5. 启动程序的主进程，界面正常加载完成后终端窗口会自动退出关闭，用户无需再按键确认

```powershell
.\scripts\install.ps1              # 只安装，不启动
.\scripts\install.ps1 -Launch      # 安装并启动（= 双击 安装.bat）
.\安装.bat -NoLaunch               # 双击安装，但装完不启动
.\scripts\install.ps1 -InstallDir 'D:\Apps\音乐播放器' -Launch   # 自定义目录
```

卸载：直接运行安装目录下的 `卸载.bat`，也可以手动删除该文件夹；程序运行不会向 Windows 注册表写入配置，直接删除目录即可清理干净。

## 版本回滚

目录 `versions/` 中完整保留了 `musicplayer.html` 历史上 12 个关键节点的**逐字节快照**。这些文件全部从 DSH 会话日志中通过反向重放精确还原，重现了整整 204 处编辑且没有发生任何失败。如果用户在调整音频可视化参数或编写视觉特效时把界面调乱了，可以借助这些快照立刻退回到已知可用的稳定状态。

```powershell
# 列出全部版本（同时显示当前用的是哪一个）
.\scripts\use-version.ps1 -List

# 回滚到某个版本（自动备份当前版本 → 替换 → 重新构建）
.\scripts\use-version.ps1 -Version Q1
```

参数 `-Version` 的输入方式非常灵活，既支持输入完整文件名（如 `Q1_preWave.html`），也允许传入版本前缀（如 `Q1`）或是名称中的关键字（如 `preWave`）。只要传入的字符串能在历史列表中唯一匹配到一个快照，脚本就会开始处理。

- 执行替换操作之前，脚本会自动将当前正在使用的 `app/index.html` 备份到 `dist\版本备份\` 目录下，用户随时都能重新切回备份的内容
- 想要切回最新的开发版本时，可以直接运行 `git checkout -- app/index.html`，或者调用脚本传入 `-Version <备份文件名>` 来还原
- 加上 `-NoBuild` 参数之后，脚本在覆盖源码文件后不会触发前端重新构建流程，只完成文件替换

这些快照文件本身全都是自包含的单文件 HTML，内部只调用了当前 `preload.js` 中仍然保留的 IPC 通信接口。正因为这样，它们**可以直接当 `app/index.html` 跑**，运行时不需要把主进程代码 `main.js` 一并回退到旧版本。不过这样做也存在限制：旧快照的代码完全无法识别后来新增的 B 站缓存、迷你悬浮窗以及多歌手识别等新特性。

关于详细的版本对照表、各项功能的兼容性说明，以及一段已被推翻的历史约束记录，可以查阅 [versions/README.md](versions/README.md)。

## 常见问题

**Q：为什么 GitHub 仓库里没有 `音乐播放器.exe`？**

Electron 运行时解压后体积约为 222 MB，直接上传会超出 GitHub 单个文件的推荐体积限制，也会让仓库变得过于庞大。因此，仓库内仅保留源代码、自动化构建脚本和说明文档。环境部署改由本地的 `scripts\build-portable.ps1` 脚本处理；如果用户的本地开发环境中已经准备好了运行时包，脚本在执行过程中完全不需要联网下载，支持纯离线打包。

**Q：媒体键（耳机按键）没反应？**

用户可以进入设置面板，查看「媒体键」这一栏的当前状态：

- `✓ 已注册` → 说明播放器已经成功接管系统音频按键
- `⚠ 被占用` → 意味着部分多媒体按键已被后台其他程序（例如大型游戏或其他音乐播放器）抢先拦截
- `✕ 全部被占用` → 代表所有媒体控制键都已被占用，需要用户手动退出产生冲突的后台程序，或者直接改用播放器内置的界面快捷键

因为 Windows 操作系统的媒体控制键属于**独占**系统级资源，在同一时刻只能允许一个前台或后台程序完成全局热键注册。

**Q：迷你窗在游戏里看不见？**

- 只要将游戏的画面输出方式调整为「无边框窗口 / 窗口化全屏」，迷你窗就可以作为顶层窗口正常覆盖在游戏画面上方。
- 如果游戏运行在**独占全屏**（Exclusive Fullscreen，即游戏直接绕过桌面窗口管理器独占显示器控制权）模式下，受限于 Windows 系统的显示机制，任何常规的桌面浮窗都无法覆盖在画面上；
  遇到这种情况，建议用户进入游戏的图形设置菜单，将显示模式切换为无边框窗口。

**Q：切换歌曲后封面不刷新？**

这是因为元数据缓存未能同步更新，用户可以在设置界面中点击「重新识别」按钮触发手动解析，也可以把该曲目从播放列表里移除后重新导入。

**Q：频谱柱体不动 / 很平？**

请先确认当前播放的音频文件本身包含充足的低频信号；随后可以打开设置面板，根据听音喜好适当调高可视化灵敏度、鼓点响应强度，或者重新设置柱体数量来改善视觉跳动效果。
